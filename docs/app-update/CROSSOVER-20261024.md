# RisuBard 0.9.90 — NAS 앱 코드 자동 패치 / Windows 로그 복구

작성: 2026-10-24. Codex 구현, 실제 Claude Code 구독 CLI `claude-opus-5-5`·high 계획 검토 및 코드 3차 교차 검수. 별도 API 키로 호출하지 않았다.

## 계약
- GOAL: Windows 로그 교체 오류 해결, 앱 서버 시작 시 기존 NAS에서 호환 코드를 자동으로 받아 적용하는 모듈, 정식 APK/Windows 공개.
- MUST: 최소 수정, Claude 검수 후 배포, 기존 대화·설정 보존.
- KEEP: 전송·NAS 대화 동기화·API 연결·페르소나·Wiki·저장 슬롯·백업·현재 플레이. 새 계정·PIN·보안 제품·자동화는 추가하지 않는다.
- VERIFY: 오류 재현, 회귀 검사, 전체 모듈 재적용, 서명/16KiB/패키지 검사, 실제 NAS 왕복과 격리 서버 기동. 실기기와 실사용 데이터 검증은 구분한다.

## 원인과 수정
Windows 파일 공유 잠금의 일시적 EPERM/EACCES/EBUSY를 공통 파일 교체 함수에서 재시도하지 않았고, 로그 잠금은 작성자가 살아 있어도 30초가 지나면 가져올 수 있었다. 파일·백업·체크섬 교체를 같은 제한된 재시도 경로로 연결하고, 살아 있는 작성자의 잠금을 보존했다. 잠금을 만든 특정 외부 프로세스(백신 등)는 확인되지 않았다. 데이터 파일을 먼저 삭제하는 우회는 하지 않는다.

`app-update`는 10번째 기능/연결/이력 모듈이다. 고정 로더는 `server/node/app-update`, 공통 서버 연결점 세 곳은 `host-bridges`, Android 네트워크 정보 연결은 기존 `transfer-sync`에 속한다. Windows 파일 보존은 `storage-recovery`, 로그 잠금은 `model-compat`, 전체 업데이트 검증의 NAS 패치 제외는 `distribution`에 반영한다. 기존 파일 소유권을 중복 등록하지 않는다.

NAS 연결은 기존 설정·집/외부 경로를 사용하며 `.risubard-app-updates` 아래의 앱 코드만 게시한다. 대화 동기화 저장소와 코드 배포는 별도다. NAS 검색은 8초 예산, 다운로드는 처음 2초 이후 백그라운드로 이어서 다음 서버 시작에 적용한다. 실행 중인 플레이를 강제 재시작하거나 가리는 팝업은 없다. 서버가 살아 있을 때 앱 화면만 여는 동작은 새 서버 시작이 아니다.

코드 ZIP 준비→검증→이전 코드 보관→파일별 원자 교체→서버 정상 기동 확인으로 진행한다. 중단 시 이전 코드로 복구한다. 실패한 패치는 이전 판으로 실행하는 회차를 사이에 두고 한 번만 재시도하며, 실패한 캐시 때문에 다음 수정판을 못 받지 않도록 한다. 전체 패키지 교체가 감지되면 낡은 복구 기록으로 새 앱을 덮지 않는다. 저장 형식·네이티브·Node·의존성·고정 로더가 바뀌면 전체 APK/PC 패키지로 배포한다.

## Claude 검수
계획 검토에서 시작 시간 제한, 오래된 복구 기록과 전체 패키지 충돌, 데이터 위치·인증서 경로 보호, 실패 진단, 전체 업데이터와의 충돌, 부분 업로드 재시도 6건을 수정했다. 코드 1차에서 실패 캐시의 후속판 차단과 ssl 빌드 입력 누락을 수정했고, 2차/3차에서 선택적 Wi-Fi 정보 실패 처리와 만료된 시작 예산 처리까지 확인했다. 최종 코드 판정은 차단 항목 없음·P0/P1 0건이다. Claude가 실기기에서 직접 테스트한 것은 아니다.

## 검증 결과
- 변경 전 회귀 2실패를 재현하고 수정 뒤 통과. 최종 관련 7파일 99검사 통과, 코드 해시를 검사 전후로 기록하고 동일함을 확인했다.
- Windows 로그 작성 4프로세스 동시 검사 최종 3회 통과(초기 6회와 별도). 원래 ID·기록 보존 단정은 유지했다.
- Android release APK: 기존 앱 ID/서명, 디버그 아님, 16KiB ELF/ZIP 정렬, 런타임 CRC와 원본 비교 통과. 최종 컴파일된 Java/Kotlin 단위 17검사 통과. Gradle test worker의 한글 경로 ClassNotFound 실패는 보존하고, 동일 Gradle 클래스패스를 UTF-8/base64로 전달한 직접 JUnitCore 실행으로 확인했다.
- Windows 포터블: 포함 의존성과 격리 서버 기동 통과. 전송기/런처 소스40파일이 이전 공개판과 동일하여 검증된 바이너리 재사용. 서드파티 소스맵의 sources·sourcesContent에 있는 빌드 경로만 제거했다.
- APK·Windows·NAS 코드의 공통 runtime 지문 일치: `3486f5f792cc676009da2981a52f10f3d2029c4b990741553b9a0195b5d3220b`.
- 실제 NAS에 0.9.90 코드 게시 후 재다운로드 해시 일치. 격리 Windows 전체 서버가 NAS에서 자동 다운로드·적용·재시작 성공. 최초 적용 기동 17.114초, 다음 기동 1.424초. 이 수치는 현재 PC의 실측이며 Android 성능 보장이 아니다.
- 실제 NAS 시험은 0.9.90 로더를 넣고 버전을 0.9.89로 낮춘 시험 설치본이다. 기존 공개 0.9.89에 로더가 저절로 생기는 것은 아니다. 사용자는 0.9.90 전체 패키지를 먼저 설치해야 한다.
- 시험용 전체 DB의 대화·캐릭터·페르소나·API 설정이 동일하고, 보호된 NAS 설정과 백업 바이트가 동일함을 확인했다. 실제 사용 중인 앱 데이터는 설치/변경하지 않았다.

## 미실행·남은 경계
Android 실제 기기 설치·SSID 콜백 타이밍·90초 안의 코드 적용·플레이, 사용자 데이터의 실제 기기 간 동기화는 이번 릴리즈 작업에서 실행하지 않았다. 선택한 원작 두 커밋의 재적용 성공이 향후 모든 원작 업데이트 호환을 보장하지 않는다. 내부 복구 상태가 rolled-back일 때 후속 연결 오류 설명이 상세히 갱신되지 않는 P3 진단 한계는 남아 있으며 업데이트/자료 보존 동작에는 영향이 없다.

사용 방법과 배포 명령은 [모듈 안내](MODULE.md)를 따른다. 릴리즈의 SHA256SUMS와 검증 기록을 함께 확인한다.

최종 배포 증거 검수에서 Claude는 차단 불일치 없음으로 판정했고, 남겨 두었던 원작 전체 검사 게이트는 2026-10-24 11:23 KST PASS로 충족했다. NAS 최신 manifest·실제 적용 저널·GitHub code ZIP의 SHA-256 일치와 최종 APK/PC 로더 비교 대상 해시도 추가로 기록했다.
