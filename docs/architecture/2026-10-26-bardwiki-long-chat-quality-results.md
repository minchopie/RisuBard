# 바드위키 초장기 채팅 측정 결과 (2026-10-26)

- 대상: 0.9.84 작업 트리(단계 1~4 적용). [설계](2026-10-26-bardwiki-long-chat-fix-design.md)
- 도구: `server/node/risubard-wiki-quality.bench.test.ts`와 `risubard-wiki-quality.fixture.ts`. `RISUBARD_QUALITY_BENCH=1`로 켜고, `RISUBARD_QUALITY_TURNS`(기본 `100,300,1000`)와 `RISUBARD_QUALITY_MODES`(`clean`, `faulty`)로 범위를 고른다.
- 방식: 코드로 만든 합성 장편(인물 6명, 장소 6곳)에 정답 장부를 두고, 장부대로 답하는 가짜 분석 모델을 실제 분석 러너, Markdown 위키, inquiry, 과거 원문 회수에 연결했다. 모델 호출 비용은 없다. 클라이언트와 같은 순서 처리(가장 오래된 대기 턴부터, 실패 시 멈춤)를 `wikiBacklogMessages`로 재현했다.
- 합성 이야기에 심은 것: 초반 출신지 6개, 37턴마다 바뀌는 관계 3쌍, 53턴마다 바뀌는 열쇠 소유자, 61턴마다 생기는 비밀, 45턴의 소문과 140턴의 정정, 10턴마다 반복되는 "아침 식사" 사건, 매 턴 장면 주인공이 얻는 단서.
- 장애 모드(`faulty`): 기존 지식 절 갱신의 15%를 "가장 오래된 항목을 빠뜨린 전체 재작성"으로, 의미 분석의 5%를 공급자 오류로 바꾼다.

## 남은 한계

- **전체 재작성으로는 지우지 못함:** 모델이 항목 편집 대신 절 전체를 다시 쓰면 "이 줄을 지운다"를 표현할 수 없어, 안전망이 지워진 소문 줄을 되살렸다(장애 모드에서 정정 뒤에도 소문이 남음). 항목 편집을 따르는 모델에서는 생기지 않았다(clean). 실제 모델이 편집 형식을 얼마나 따르는지는 재지 않았다.
- **한 자리 숫자:** 3,000턴의 "단서 3" 질문 하나가 실패했다. 질의어 처리에서 한 글자 낱말을 버려 "3"이 검색어가 되지 않고, "단서"는 거의 모든 사건에 있어 구별이 안 된다. 실제 대화에서 한 자리 숫자만으로 장면을 찾는 경우는 드물어 고치지 않았다.
- **아크 장이 많음:** 아크 개요가 8개를 채울 때마다 장을 닫아, 3,000턴에 53개가 생겼다. 장은 다시 요약되지 않고 링크로 이어지지만, 장 수를 줄이려면 아크 수 상한을 늘리면 된다.
- **가짜 모델의 범위:** 이 측정은 "같은 모델 행동에서 프로그램이 기억을 지키는가"를 본다. 실제 모델의 요약 정확도, 바꿔 말한 질문의 회수, 응답 모델이 근거로 맞게 답하는지는 재지 않았다. 장애 모드 3,000턴은 시간 때문에 1,000턴에서 멈췄다.
