# Fable R5 대응과 범위 정리

GOAL: 태블릿/스마트폰 자체 Offline 채팅. MUST: PC/Termux/네트워크 없는 생성, 명시적 모델 준비, 자동 온라인 대체 금지, 실기기 설치 HOLD. KEEP: 일반판/채팅/설정. VERIFY: 내부 검증과 물리/전체 이식 구분.

## 새 변경
1. 시작 GC 실패: 수정 전 코드로 UUID.part 디렉터리를 만들어 실제 ERR_FS_EISDIR와 수동 PUT 실패를 재현했다(r5-gc-before.json). 이제 항목별 삭제 실패는 경고로 남기고 초기화를 계속한다. 기존 선택 모델과 사용자 설정 PUT을 보존하는 새 회귀 포함 서버11개 통과.
2. 초기화 자체 실패: 자동 전환은 여전히 없다. 사용자가 enabled=false PUT을 명시하면 이번 실행에만 온라인 선택을 적용한다. 저장하지 못했고 재시작 때 이전 모드로 돌아간다는 경고를 반환한다. enabled=true는 계속 초기화 오류를 반환한다. 모델 실행 파일 부재/저장소 실패 테스트에서 명시적 전환과 미저장을 확인했다.
3. 시작 시 GC에 앞서 POSIX 디렉터리 sync를 수행하고 실패하면 GGUF 정리를 건너뛴다. 별도 Linux 실제 테스트3통과, skip0. 삭제가 안 되거나 sync가 안 된 항목을 안전 때문에 억지로 지우지 않는다.
4. 저장 확정 실패 안내를 설정에도 맞도록 바꾸고, 재적용 뒤 앱을 재시작하라고 안내한다. 정상 교체는 즉시 이전 모델을 정리한다. sync 실패의 잔여 파일은 재시작에서만 정리하는 예외다.

## 의도적으로 보존하는 제한
손상 설정에서 연결을 잃은 GGUF는 사용자의 원본 보존을 위해 새 모델 가져오기가 성공하기 전까지 보존한다. 성공 후 시작 GC로 정리한다. 모델 관리/삭제 UI를 새로 추가하지 않았다. 정상 A→B→C 교체와 다르며 설정 손상 예외다. 초기화 불가시 수동 온라인 전환은 일시적이고 오류 메시지로 표시한다. 저장소가 런타임 중 고장 나 정상 PUT 저장 자체가 실패하는 경우까지 자동 복구/초기화하지 않는다.

## R5에서 요청한 증거 해명
- Turn4는 APK23에서 'Write a long numbered list...'를 보낸 뒤 사용자가 누르는 Cancel 버튼을 실행한 의도적 취소 시험이다. apk23-cancel-before/after와 이후 Turn5 재시도 증거가 있다. 시험 한도는96토큰이었다. 512 cap 초과/길이 제한 경로라고 추정하지 않는다.
- Turn9는 내용 없이 합성 SSE 오류를 준 시험이다. 기존 index.svelte.ts가 첫 청크 전에 빈 char 메시지를 먼저 추가하고 오류 표시 후 기록을 남기는 기존 동작이다. 이번 작업에서 그 빈 메시지 삭제/채팅 구조 변경은 하지 않았다. Turn11은 부분 텍스트 뒤 SSE500 실제 화면 주입 시험이며 부분 내용 보존+오류창을 확인했고, 주입 해제 후 Turn12 실제 네이티브 답변 '준비 완료'에 성공했다. 일반 성공으로 표시한 것이 아니다.
- BardWiki 의미 분석은 작은 시험 모델/문맥4096에서 시스템 프롬프트만 약4609(예상), 전체4785로 초과했다. 로컬 엔진으로 실제 라우팅됐으나 성공했다고 주장하지 않는다. 필수 프롬프트/사용자 자료를 임의로 줄이지 않고 서버에서422로 표시하는 현재 계약이다. 긴 기억/로어에는 더 큰 문맥과 이를 감당하는 기기/모델이 필요하다. 실제 BardWiki 분석/장문 플레이 품질은 미검증이며 이 APK를 모든 기능 완성판으로 배포하지 않는다.
- SSE 와이어: 번들 엔진의 고정 커밋 ea0c4c2c85fb183ec0fbd30a1af4e4275a18a064의 실제 server-context.cpp는 OAI 오류를 format_oai_sse(json{{error,res_json}})로 반환하고 server-common.cpp의 함수는 data: + JSON + 두 줄바꿈이다. 구버전 error: 필드가 아니다. 실제 모델 중간 실패 프레임을 얻었다고 주장하지 않고, 정확한 고정 소스 확인과 합성 wire 재현을 구분한다.
- normalizeHttpStatus: 200~299만 null, 모든400~599는 반드시 ModelPresetAdapterError다. 관련 실제 함수 전체를 첨부한다.
- 실제 부분 응답 소비와 fetchImpl, 부팅 호출 위치를 아래 소스 발췌로 제공한다. 로컬 생성은 모델 job journal을 사용하지 않으므로 렌더러/프로세스 강제 종료 시 진행 중 출력은 손실될 수 있다. 저장 완료 채팅/모델 보존과 다르다.

APK26의 실제 Android 시험/파일 검증은 R5 새 수정 이전 결과다. 새 서버 코드 APK27을 별도로 만들고 검증한다. 모든 실제 물리 기기 설치와 정식 배포 HOLD.
