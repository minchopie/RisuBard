# Fable R6 대응

이번 최종 후속은 R6의 경미2건과 확인된 상태 조회 경계만 수정한다. 다른 기능/프롬프트/기억 스키마/전송/실기기 설치는 바꾸지 않는다.

1. lastError ||= 정리 경고로 바꿔 손상 설정/저장 sync 경고를 보존한다. 경고 자체도 기존 모델 사용 가능이라고 단정하지 않는다. 수정 전 실제 코드에서 손상 설정+.part 디렉터리를 만들어 재선택 안내 유실을 재현했고 새 회귀가 통과했다.
2. 저장된 설정을 먼저 읽고 이후 실행 파일/디렉터리를 검사한다. 실행 파일 부재에도 정상 저장된 enabled=false와2048/32를 보존하고 설정 파일은 쓰지 않는다. 수정 전 true/default로 바뀌는 실제 결과와 수정 후 회귀가 있다. 이는 이전 명시적 선택의 유지이며 오류에 따른 자동 전환이 아니다.
3. 실제 NodeStorage 소스를 보니 일반 authFetch에는 시간 제한이 없었다. 추가한 비필수 모델 상태 GET만 AbortSignal.timeout(5000)을 사용한다. 부팅 전 기본 스토리지 인증/Init은 기존 동작이며 전체 부팅을5초로 보장하지 않는다. Offline UA인데 available=false 응답이면 오류로 보고 기존 상태를 유지한다. 일반판은 기존 available=false를 수용한다. timeout/503/unavailable 응답 테스트3개, 전체 집중 클라이언트139 통과.

실제 서버12/Linux저장3(skip0) 통과, 타입0오류·기존8경고. R5 주요 수정은 APK27에서 실제 Android 검증: .part 디렉터리 정리 경고 후 모델/채팅 유지, 저장소 chmod000 EACCES 상태에서 UI 수동 온라인 세션 전환과 미저장 안내,700/설정 원복 후 실제 오프라인 TURN13 확인 완료 생성. APK27은 이 R6 마지막 수정 이전이고 새 APK28을 별도로 검증한다. 물리 설치/정식 배포 HOLD.

R6에서 제한으로 수용한 orphan 보존/빈 버블/문맥초과422/진행생성 journal 없음은 그대로 문서화. 새로운 모델 삭제 UI나 시스템 프롬프트 축소는 추가하지 않았다. 설치 APK/실제 실행과 소스 확인을 구분한다.
