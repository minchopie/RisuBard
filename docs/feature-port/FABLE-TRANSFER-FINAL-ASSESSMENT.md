# RisuBard 남은 기능 이식 — 공동 검수 최종 평가

날짜: 2026-10-17. 기준 브랜치 `codex/risubard-feature-port`, 기반 `64ebfb23`, 내부 패키지31.

## 목표와 보존 조건

- **GOAL:** 구 RisuAI USB/Windows 전송 기능을 RisuBard의 기존 가져오기·저장·로그·백업 기능에 연결한다.
- **MUST:** 공통 v2 묶음, 선택 채팅의 BardWiki/슬롯/이미지, 같은 캐릭터에는 대화 추가, 영속 대기열과 중단 복구, 실제 Fable 5.1·xhigh 공동 검수.
- **KEEP:** 기존 카드·대화·페르소나·API 설정·현재 화면, 구 JSON/PNG/RPT1 호환, 이전 후보·사용자 데이터. 물리 태블릿·스마트폰 설치는 보류한다.
- **VERIFY:** 파일 왕복·중복/변경본·canonical 저장/재시작·슬롯 불러오기, 오류 주입, 실제 UI/Windows IPC/Android 내부 실행, 소스와 패키지 해시. 모의 서비스와 실계정·물리 기기를 구분한다.

## 검수 판정

| 영역 | 실제 검수 | 현재 판정 |
|---|---|---|
| 데이터·복구·잠금 | core4 → core5 → core6 | 확인된 결함 수정 후 추가 확정 회귀 없음 |
| NAS·GitHub·자격정보·전송 UI | remote4 → remote5 | 확인된 결함 수정 후 확정 차단 문제 없음 |
| Android·Windows 연결/수명 | native1 → native2 → native3 → native4 | 제품 수정 수용. native4의 테스트 호출 오류는 권고한 공개 API로 교정했고 빌드/실제 에뮬레이터 통과 |
| 마지막 테스트 수정 | native5 | 추가 확정 결함 없음. Android 실제 재생성 통과와 Windows 8개 연결 검사의 유효성 수용 |

원문은 `fable-transfer-<검수명>.md`, 실제 읽기 전용 소스 사본·입력 해시·도구 사용/최종 결과는 `tmp/fable-readonly-<검수명>/`에 있다. 모델 결과의 `modelUsage`는 `claude-fable-5-1`, 실행 옵션은 `--effort xhigh`다. Codex가 Claude 역할을 대신해 생성한 평가는 사용하지 않았다. 읽기 도구 호출 문형만 있는 응답과 출력한도 오류는 검수 완료로 계산하지 않았다.

유효한 읽기 전용 검수10건을 기록했으며, 합쳐서 검토한43개 파일 전부가 하나 이상의 최종 검수 입력 해시와 현재 바이트가 일치한다(미대조0). `tmp/transfer-build31/review-source-coverage.json`이 근거다. 판정은 제공된 변경 소스와 시험 근거 범위이며 모든 환경의 무결함 보증이 아니다.

native5의 비차단 중복 helper 의견은 이번 사본에 없던 `Program.cs`의 `Local\\<PipeName>` Mutex와 대조했다. 이 파일은 native2 검수 입력과 현재 해시가 일치하며, 같은 경로의 두 번째 프로세스는 서비스 생성 전에 종료한다. 추가로 실제 패키지31 exe를 두 번 실행해 두 번째 exit0·첫 번째 유지·첫 번째 종료 후 파이프 ENOENT를 확인했다(`tmp/transfer-helper-single-instance.json`). 따라서 이 의견을 제품의 중복 리스너 결함으로 확정하지 않는다. 테스트의 고정 시작 대기를 명시적 리스너 준비 검사로 바꾸는 것은 향후 검사 안정성 보강 항목이다.

## 남겨 둔 범위와 한계

- 물리 TB710FU/SM-S938N 설치, 최종 ARM64 실행, 실제 Wi-Fi/USB/Quick Share 양방향, 실제 NAS/GitHub 계정 전송, 최신 기기 키보드/회전은 미검증이다. 사용자 지시대로 설치하지 않았다.
