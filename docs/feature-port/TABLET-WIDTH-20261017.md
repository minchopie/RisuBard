# 태블릿 채팅 본문 폭

사용자 요청: 태블릿도 휴대폰처럼 좌우에 작은 여백만 남기고 화면 폭을 사용한다. 물리 기기 설치 보류는 유지한다.

## 변경

기본 채팅 테마는 화면이 커지면 48rem/72rem 너비 제한과 바깥 16px + 안쪽 32px 패딩을 적용했다. Android 태블릿도 이 PC 배치를 사용했다.

- `Chat.svelte`: 기존 `isMobile` 판별을 재사용해 휴대폰·Android 태블릿에서는 메시지 너비 제한을 없애고 본문 패딩을 좌우 1rem(검사 기본값 16 CSS px)으로 유지한다. 화면 크기를 다시 판별하는 코드나 설정을 추가하지 않았다.
- `DefaultChatScreen.svelte`: 같은 기기의 입력창도 채팅 영역 전체 폭을 사용한다.

PC의 `standard`/`wide`/`full` 설정값과 표시 동작은 유지한다. 기기별 표시만 달라지고 저장된 너비 설정은 수정하지 않는다. 다른 채팅 테마·사이드바·채팅 내용·입력창 높이/키보드 처리에는 변경이 없다. 온라인/오프라인 후보가 공유하는 클라이언트 코드에 적용한다.

## 실제 확인

Playwright의 독립 Chromium 세션에서 실제 `DefaultChatScreen`/`Chat` 컴포넌트를 합성 자료로 렌더링했다. 테스트 API는 스텁으로 처리했다. 물리 태블릿이나 Android WebView 실행 검사는 아니다.

| 화면 | 변경 전 기본 본문 폭 / 한쪽 여백 | 변경 후 기본 본문 폭 / 한쪽 여백 |
|---|---|---|
| 휴대폰 390px | 358px / 16px | 358px / 16px |
| 태블릿 세로 800px | 704px / 48px | 768px / 16px |
| 태블릿 가로 1280px | 704px / 288px | 1248px / 16px |
| 큰 태블릿 1600px | 704px / 448px | 1568px / 16px |
| 좁은 창 600px | 568px / 16px | 568px / 16px |

각 모바일 화면에서 세 너비 설정을 모두 검사했다. 좌우 여백은 같고 입력창은 가용 폭을 사용하며 수평 넘침은 없었다. PC 1280/1920px의 세 설정도 함께 확인해 총21조합 통과. PC6조합과 휴대폰/좁은 창6조합은 변경 전후 실측 결과가 같았다. 저장된 너비 설정이 바뀌지 않았음을 실제 DBState에서 확인했다. 같은 페이지의 연속 크기 변경으로 방향 변경도 재현했다.

- 기존 채팅 편집·뷰포트 회귀 검사: 2파일/15개 통과.
- Svelte 검사: 오류0, 기존 한 파일의 경고8.
- 웹 빌드: 통과.
- 실제 캡처: `output/playwright/tablet-width-800.png`, `tablet-width-1280.png`.
- 코드/전후 측정/로그: `tmp/tablet-width/`.

## 공동 검수와 산출물

실제 Fable 5.1·xhigh에 변경 diff·관련 소스·브라우저 검사 코드 및 결과·회귀/타입 검사를 전달했다. 종료0, is_error=false, modelUsage=`claude-fable-5-1`. **범위 내 승인, 확정 제품 코드 결함0, 차단 사유 없음**. 원문은 [fable-tablet-width-review-1.md](fable-tablet-width-review-1.md), 입력/원응답은 `tmp/tablet-width/fable-review-1.*`에 있다. 제출한9파일은 최종 해시가 일치한다.

후속 권고인 제작자 코멘트 박스는 별도의 `w-5/6` 및 최대 폭을 쓰는 기존 컴포넌트다. 이번 사용자 요청은 채팅 본문·입력창 폭으로 적용했으므로 코멘트/다른 테마의 배치는 변경하지 않았다. 이 범위 판단은 미검증 결함을 수정했다고 표현하지 않는다. 검수 원문의 “설정값 영속 보존” 표현은 실제로는 DBState 메모리 값 무변경 검사이며 디스크 저장/재시작 검사가 아니다. 코드에도 해당 설정을 저장/변경하는 로직은 없다.

최종 내부 APK21의 SHA-256: `2f344d3666038ac61780f165b8694da5c3e6134635855971f10a5154176b5969`. 빌드·567개 소스/웹 파일 대조·ZIP 무결성·양 ABI 16KiB LOAD·zipalign·서명 검사가 통과했다. `tmp/tablet-width/apk21-final/app-debug.apk`와 source→destination 매핑을 보존했다. 이전 APK20은 그대로 보존했다. APK21은 기기에 설치/실행하지 않았으며 렌더링 수치는 개발 서버의 실제 Svelte 컴포넌트 검사다. 설치·커밋·푸시·정식 릴리즈는 하지 않았다.

전체 기능 통합과 offline AI 범위의 미완료 상태는 기존 STATUS를 따른다. 이번 변경은 기본 채팅 화면의 폭에 한정한다.
