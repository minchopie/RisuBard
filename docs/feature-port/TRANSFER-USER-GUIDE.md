# 캐릭터·대화 옮기기

설정 → 시스템 → 백업의 **캐릭터·대화 옮기기**에서 사용한다.
현재 캐릭터를 열고 보낼 대화를 선택한 뒤 **보낼 자료 확인**을 누른다.
필수 자료가 빠졌으면 목록을 먼저 확인한다. 외부 이미지 주소는 임의로 내려받지 않는다.

## 보내기와 받기

| 방법 | 사용 흐름 |
|---|---|
| 파일 | `.risuplay`로 저장하고 상대 앱의 **전송 파일 열기**로 연다. |
| NAS · WebDAV | HTTPS 폴더 주소·계정·비밀번호를 해당 기기에 저장한다. 업로드 후 상대 기기에서 목록을 열어 내려받는다. |
| GitHub 개인 백업 | 개인 대화용 **비공개** 저장소와 토큰을 해당 기기에 저장한다. 같은 대화의 파일을 갱신하며 다른 백업·Git 이력은 지우지 않는다. 공개 코드 저장소에는 올리지 않는다. |
| 내 기기 · 같은 Wi-Fi | 두 앱을 화면에 열고 기기를 찾는다. 처음에만 상대 기기의 6자리 코드로 등록한다. 코드는 5분간 유효하며 5회 실패하면 다시 표시한다. |
| Quick Share · 시스템 공유 | 시스템 공유창에서 대상을 고른다. 수신한 파일을 RisuBard로 연다. 공유창을 연 것만으로 전달 완료를 뜻하지 않는다. |
| USB | Android에서 USB 디버깅을 허용하고 PC와 연결한다. Windows의 RisuBard 전송 화면에서 기기를 골라 보내거나 받는다. PIN은 필요 없다. |

Wi-Fi·USB·시스템 공유는 이를 지원하는 Android 앱 또는 전송기가 동봉된 Windows 패키지에서 표시된다.
일반 웹 브라우저만 사용할 때는 파일·NAS·GitHub 방법이 표시된다.
외부 통신망에서 Wi-Fi 등록을 시도하는 대신 NAS 또는 GitHub를 이용한다.

받은 자료는 수신 목록에 남는다. 등록된 Wi-Fi 기기의 자료는 생성·저장 작업이 끝난 안전한 시점에 자동으로 가져온다.
파일·NAS·GitHub·USB 자료는 목록의 **가져오기**를 누른다. 오류나 중단이 있으면 항목을 확인하고 다시 시도하거나 **취소**한다.
대기 항목은 앱을 다시 열어도 남는다.

시작할 때 저장된 대화와 가져오기 기록이 달라 복구를 끝낼 수 없으면, 현재 대화와 받은 원본을 보존한 채 복구를 보류할지 묻는다. 보류하면 앱을 계속 사용할 수 있지만 해당 수신 대화의 기억·슬롯은 완성되지 않았을 수 있다. 원본 파일과 복구 자료는 남는다.

NAS/GitHub 설정의 암호화 자료가 손상됐을 때는 **전송 연결 정보 모두 재설정**의 확인 안내를 따른다. 두 연결의 계정 정보를 다시 입력해야 하며, 대화와 원격 백업은 지우지 않는다. 기존 GitHub JSON 백업과 현재 대화가 달라지면 갱신 확인을 표시하고, 확인한 뒤에도 원격 파일이 다시 바뀌면 덮어쓰지 않는다.

## 기존 자료 보존

- 같은 캐릭터를 찾으면 대화만 추가한다. 후보가 여러 개면 대상을 선택한다. 없으면 새 캐릭터를 만든다.
- 기존 카드·대화·API 설정·현재 화면을 덮어쓰거나 바꾸지 않는다. 별도의 ‘이어서 플레이’ 팝업은 없다.
- 동일한 채팅·BardWiki·저장 슬롯은 중복 추가하지 않는다. 내용이 달라진 수신본은 별도 대화로 남긴다.
- RisuBard끼리는 선택 대화의 BardWiki, 저장 슬롯, 필요한 이미지도 함께 보낸다.
- **구 RisuAI USB 앱용 호환 파일**은 BardWiki와 저장 슬롯을 제외하며, 제외 항목을 미리 표시한다.
- 기존 GitHub JSON 호환은 `chat-uploads` 브랜치와 8 MiB 한도를 유지한다. 내려받은 JSON은 캐릭터의 대화 가져오기에서 연다.
- 새 GitHub `.risuplay` 파일은 100,000,000바이트 미만이어야 한다. 더 큰 자료는 파일 또는 NAS로 보낸다.

연결 설정의 비밀정보는 Android Keystore 또는 Windows DPAPI로 보호한다. 계정·토큰·실제 NAS 주소는 배포 파일에 포함하지 않는다.
구 앱에서 새 앱으로 이동할 때는 내보내기 → 새 앱에서 가져오기 → 내용 확인 순서로 진행하며, 구 앱은 자동 삭제하지 않는다.
