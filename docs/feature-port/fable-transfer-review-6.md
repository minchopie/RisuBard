**Structural external URLs — fixed by trace; test sensitive.**
`assetField = key ∈ {image, icon, uri} || /^\/(?:additionalAssets|emotionImages)\/\d+\/1$/ || module && /^\/assets\/\d+\/1$/`; `wholeAsset = /^assets\/[^/\\\s]+$/ || (assetField && /^(?:assets\/|https?:\/\/|data:)/i)`. A whole-field URL enters `asset()`, whose order is: empty/`data:` → `null`; `/^https?:\/\//i` → `external.push`, return before any `source.asset` call; otherwise the strict `^assets\/[^/\\]+$` check. The literal extractor is guarded by `!wholeAsset`, so `assets/avatar.png` is never extracted from the URL. Test and repro log confirm image, `additionalAssets[n][1]` and module `assets[n][1]`. Source DB is unchanged (`canonical(db) === before`). The R5 claim is correctly scoped to *structural* fields; see D-R5-1 for what remains.

## 2. Proved defects (deterministic in supplied code; not covered by tests)

**D-R5-1 — Free-text URLs containing `/assets/<name>` still trigger a guessed local lookup that can block export or attach an unrelated file (medium, data-dependent prevalence).** Any non-structural string (message `data`, description, lore, module code, wiki/slot text via `chatMaterials`) such as `<img src="https://cdn.example/assets/pic.png">` is not `wholeAsset`; the literal branch runs `field.matchAll(/assets\/[A-Za-z0-9_.-]+/g)` with no URL exclusion and calls `asset('assets/pic.png', …, literal)`, which requests the local path. If absent: a non-optional `Missing local asset: assets/pic.png` issue, and `writePlaySetArchive` refuses the export with a message naming a file the user never referenced; no `external` notice is produced. If the chat scope happens to alias `assets/pic.png` to a real local file, that file is attached as a dependency and alias although the text is never rewritten — dead weight, not a leak outside the scope. Fix: skip literal matches that lie inside an `https?://\S+` token (or are preceded by `/` or `:`), and push them to `external` instead. Test: a message containing such a URL must yield `missing: []`, one `external` entry, and no `source.asset` call for the guessed path.

**D-R5-2 — An id-less chat on the target card matches every generation that does not map the incoming chat (low; R4-introduced, now compounded).** `generations = registry.generations.filter(g => row(g.ids)[item.id] === candidate.id)`: when `candidate.id` is `undefined`, every generation lacking `item.id` satisfies `undefined === undefined`. Consequences by trace: (a) every such generation is fingerprinted (cost); (b) if the candidate is a stub/placeholder/cold row it throws `Hydrate the matching chat before importing: undefined` spuriously; (c) a malformed generation row without a manifest (the shape the `mixed legacy` test injects into a receiver registry) reaches `generation.manifest.items` → TypeError, failing the import (non-mutating, but blocking). Fix: require `typeof candidate.id === 'string'` (or `Object.hasOwn(row(g.ids), item.id)`) in the filter. The app's handling of id-less chats elsewhere (`resolvePlaySetMemoryPreset` test) makes the shape plausible.

**Carried, still open:** `applyCharacterChats` has no explicit v2 check (insurance only); D-R3-4 page-path wrapping has no asserting test.

## 5. Verdict (export/archive and planner scope only)

The two R5 fixes are correct as implemented. D-R4-1 is fixed by trace and by a test the repro log shows failing pre-fix with the predicted mechanism; the wider-receiver policy is preserved both by trace and by the unchanged passing policy test, and narrower re-sends to a receiver now also deduplicate. Structural external URLs are never passed to the asset loader and never become local paths, proved by trace and a sensitive test; originals are untouched on every traced path. The claim is correctly limited to structural fields: free-text URLs still produce a spurious local lookup (D-R5-1), and an R4-era filter mis-handles id-less target chats (D-R5-2). Evidence is self-consistent (test names, counts, times) but the types log cannot be independently bound to this text, the memory log names no tests, and "strict" is unevidenced. Physical installation remains on HOLD; the v2 host/import/journal/transport integration is neither present in the supplied code nor claimed, and the planner-level v2 throw remains necessary but not sufficient. No release approval.
