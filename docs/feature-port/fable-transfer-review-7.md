## 1. R6 fixes checked against code

**D-R5-1 (free-text URLs with `/assets/`) — fixed by trace for `http(s)` URLs; test sensitive; adjacent local references preserved.**
`scan()` now builds `localText = field.replace(/https?:\/\/[^\s<>"']+/gi, url => { if (/assets\/[A-Za-z0-9_.-]+/.test(url)) external.push({path: owner+p, reason: url}); return ' '; })` and only then runs `matchAll(/assets\/[A-Za-z0-9_.-]+/g)` over `localText`. The branch is still guarded by `!wholeAsset`, so structural handling is untouched. Trace of the test: `<img src="https://cdn.example.invalid/assets/remote.png"> local assets/actual.png` → the URL terminates at `"`, is pushed to `external` and replaced by a space; `assets/actual.png` survives and reaches `asset()` → `source.asset('assets/actual.png')`. `assets/remote.png` is never passed to the loader (the pre-fix log shows exactly that lookup producing the missing-asset issue). The description is scanned at least twice (per-chat `aliasesOnly` scan and the final `addRecord` scan), so the `external` count of 1 depends on `unique()` dedup by (path, reason) — fine, but worth knowing. Source DB unchanged (`canonical(db) === before`). "No download attempted" holds: neither the new branch nor `asset()` ever fetches an `http(s)` value.

Regression check on prior literal behaviour: `'assets/first.png explanation\nassets/second.png'` has no URL and still collects both; `<img src="assets/inline.png">` (H1/H2 test) is unchanged; a URL without `assets/` is replaced silently and not reported (consistent with the existing policy that free-text externals are only surfaced when they look like a misparsed local path).

**Case sensitivity — as claimed.** `wholeAsset` is now `/^assets\/[^/\\\s]+$/.test(field) || (assetField && (field.startsWith('assets/') || /^(?:https?:\/\/|data:)/i.test(field)))`. `DATA:image/svg+xml,assets/inline.png` in a module `assets[n][1]` is structural → `asset()` returns `null` at `/^data:/i` before any lookup; the embedded `assets/inline.png` is not extracted because `wholeAsset` is true. `Assets/x.png` in an `image`/`icon` key is no longer blocking (R5 hypothesis resolved): `startsWith('assets/')` fails, the literal regex is case-sensitive and finds nothing, so the value is silently ignored, as before R5.

**D-R5-2 (id-less target chats) — fixed by trace; both variants sensitive.**
`existingChats = list(target.chats).map(row).filter(c => typeof c.id === 'string' && c.id.length > 0)` feeds both the `risuTransferSource` shortcut and the legacy loop. With `candidate.id` always a nonempty string, `row(g.ids)[item.id] === candidate.id` can no longer match an absent mapping, so the spurious `Hydrate … undefined` throw and the per-generation fingerprint cost disappear. Trace of the test: `matchingCharacters` falls through sourceId (`{ids:{}}`), originalId (`sender` ≠ `local`) to name; candidate `old` has no risuTransferSource and no mapping generation → nothing fingerprinted → the incoming chat is appended; `chats.length === 3`, `chats[0]` is the untouched id-less row, `receiver` unchanged (all mutation on `copy(database)`; `matchingCharacters` reads `database` read-only). Consequence by design: an id-less chat can never be deduplicated against, so a re-receipt adds a second copy — append-only, not destructive.

**Saved-page diagnostics — fixed by trace; test sensitive.**
`capturePlaySetMemory` now wraps each page capture: `catch (error) { throw new Error(\`${saved.path}: ${error.message}\`, { cause: error }); }`, and the slot block still wraps with `Memory save ${manifest.saveId}:`. A damaged page therefore reports `Memory save slot: wiki/events/….md: Memory save page is damaged: 51/517e…` — logical path, storage path and slot label. The test's `damagedPage = entries[0].path` is deterministic because the capture iterates `parseSavedFiles` in the same order and the first entry owns the first captured page. One accuracy note: the slot-label wrapper existed pre-fix (the failing log already begins with `Memory save slot:`); only the logical path is new. Temporary-file cleanup is unchanged (`catch (error) { await cleanup(); throw error; }`).

**Inventory doc.** The new "수신 호스트의 전제" paragraph records receiver hydration before the planner, exclusion of id-less unrelated chats, and the origin-side projection of the incoming chat selection through the old origin→local mapping. R5 gate 6 is closed.

**Planner v2 guard.** Unchanged: `applyPlaySet` orders `validateRecords` → `version === 2` throw → `decideImport`; `applyCharacterChats` rejects by delegation to the staged `applyPlaySet` before `copy(database)`, so the receiver is untouched (asserted by the existing test). The response explicitly declines a second check; this remains insurance-only, not a defect. No `ImportHost` implementation exists in the supplied set; the prepare gate is unimplemented as stated.

**KEEP constraints.** Originals: every mutating path in both planners operates on a deep copy, and the snapshot never writes to `source.database` (asserted repeatedly). External references: never fetched on any traced path. Same-character append-only: `applyCharacterChats` never replaces an existing card and only appends chats. Installation: HOLD; the response correctly notes API36/APK14 runtime testing predates this patch.

## 2. Proved defects (deterministic in supplied code; not covered by tests)

**D-R6-1 — Conflicting duplicate-page size still reports without the logical path (low; diagnostics only).** In the same loop, the `seen.has(saved.hash)` branch throws `new Error('Conflicting memory save page size')` outside the per-page `try`, so the user sees only `Memory save <id>: Conflicting memory save page size` with neither `saved.path` nor the hash. Same class as the item just fixed. Fix: wrap the branch (or include `saved.path` and the hash in the message); test: a `risubard-save-files.json` with two entries sharing a hash but differing `size`.

**D-R6-2 — Non-`http(s)` URL forms in free text still trigger a guessed local lookup (low; prevalence unknown; outside the R6 claim).** The URL exclusion matches only `https?://`. A free-text `data:` URI whose payload contains `assets/<name>`, a protocol-relative `//cdn/assets/x.png`, or `file:`/`blob:` forms still reach `asset('assets/<name>', …, literal)` and produce a blocking `Missing local asset` if the guessed path is absent. The structural path already treats `data:` verbatim, so the asymmetry is the same one R5 identified for `http`. Fix: extend the exclusion to `(?:[a-z][a-z0-9+.-]*:)?\/\/\S+` and `data:[^\s"'<>]+` tokens; test: a message with `data:image/svg+xml,…assets/inline.png…` yields `missing: []` and no `source.asset` call.

**Hardening, not new:** a registry row that maps `item.id` to a live chat id but has no `manifest` (corrupt registry) still reaches `generation.manifest.items` in `chatFingerprint` → TypeError; `snapshot.ts` tolerates such rows defensively (`object(generation.manifest)`), `characterChats.ts` does not. The injected malformed rows in the `mixed legacy` test all have `ids:{}` and so never exercise this.

## 3. Unverified risks (hypotheses)

- The URL token class `[^\s<>"']` swallows trailing punctuation (`)`, `,`, Korean text), so `external` reasons may carry suffixes and a local path glued to a URL without a delimiter (`https://x/page,assets/a.png`) is classified external rather than collected. No local lookup results, so this is cosmetic unless such glued text is meant to render.
- Whether real chats contain `data:`/protocol-relative image references with `assets/` segments (decides D-R6-2's impact).
- Id-less chats on receivers: if an app ever strips IDs from previously received chats, re-receipt duplicates rather than deduplicates (by design; non-destructive).
- Carried from R3–R5 and untouched: Painter/inlay identity across devices, pre-`inlayOrigins` chats, slot-embedded anchors, `appliedHash` ignoring Bard files, msgpack byte stability, fingerprint cost per generation, cold-stub representation.
- Hash/log binding: `inputsUnchanged` is a boolean summary; the "after" digests are not listed; correspondence to the exact text reviewed rests on the ledger plus the response.

## 5. Verdict (export/archive and planner scope only)

The four R6 fixes are correct as implemented and correctly scoped. D-R5-1 is closed for `http(s)` URLs by a trace-verified exclusion that never calls the asset loader for URL tokens, reports them as external without fetching, and still collects the adjacent local reference; D-R5-2 is closed by restricting both the stored-source shortcut and the legacy fallback to nonempty-string-ID candidates, with both pre-fix mechanisms demonstrated in the repro log; the saved-page error now names the logical path, storage hash and slot; the inventory doc records hydration and the origin-side projection. Prior narrow/wider gallery behaviour, structural asset handling, case semantics and the v2 delegation are unchanged by trace and by the still-passing policy tests. Originals are untouched on every traced path. Residuals are two low-severity deterministic gaps (D-R6-1 diagnostics, D-R6-2 non-`http` URL forms) and one hardening note. Evidence is the strongest so far — named, counted, commanded, UTC-stamped runs whose counts match the supplied files exactly — but digest binding is machine-asserted and strict type checking covers only the five shared modules. Physical installation remains on HOLD; the host/prepare/journal/transport layer is neither present nor claimed. No full-product or release approval is given or sought.
