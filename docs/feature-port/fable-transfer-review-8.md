**D-R6-2 (non-`http(s)` URI forms) — fixed by trace for all five cases; adjacent local asset collected; nothing fetched.**
`localText = field.replace(/(?:[a-z][a-z0-9+.-]*:\/\/|\/\/|data:|blob:|file:)[^\s<>"']+/gi, …)`; the callback pushes `external` only when `!/^data:/i` and the token contains `assets/…`, and always returns `' '`. Per case (field `<img src="${uri}"> local assets/actual.png`, `description` key, `wholeAsset` false):
- `data:image/svg+xml,assets/inline.png` / `DATA:…`: alt 1 fails at `data:`+`i`, alt 3 (`i` flag) consumes to `"`; not external; payload replaced; only `assets/actual.png` reaches `asset()`.

- `file:///assets/inline.png`: alt 1 matches `file://`, rest consumed; external, reason `=== uri`.

## 2. Proved residuals (deterministic in supplied code; low; new in R7; impact depends on prevalence)

**R7-1 — No left boundary on the URI tokens.** The alternation is unanchored, so a scheme-like suffix inside a word fires: `profile:assets/x.png` matches `file:assets/x.png` → pushed as external, local reference not collected; `metadata:assets/x.png` matches `data:…` → neither reported nor collected. A JS comment marker glued to a path, `//assets/x.png`, is likewise classified external. Before R7 all three collected `assets/x.png`. Quoted JSON (`"profile":"assets/x.png"`) is unaffected because `[^\s<>"']+` needs one character before the quote. Fix: prefix the pattern with `(?<![A-Za-z0-9+.-])` (also addresses §3's backtracking note); the bare `//` case is inherent to protocol-relative support and can be either documented or restricted to attribute/parenthesis contexts. Test: `profile:assets/x.png` and `metadata:assets/x.png` collect the asset and add nothing to `external`.

Optional hardening (not defects): include the first entry's path alongside the hash in the conflict message; label `file:`/`blob:` reasons distinctly from network URLs if a UI later renders `external` as "will not be downloaded".
