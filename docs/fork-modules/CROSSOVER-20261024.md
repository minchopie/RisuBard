# 전체 기능 모듈 재적용 — Codex / Claude 크로스오버

작성: 2026-10-24. 개인판 0.9.88 소스의 전체 패치 관리 작업이다. 설치·배포 기록과 구분한다.

## 작업 계약

- GOAL: 인앱 NAS 직접 적용 변경을 포함한 기존 개인 패치를 기능별로 관리하고 원작 업데이트에 다시 적용한다.
- MUST: 모든 기존 변경의 소유 모듈과 적용 순서를 명시하고, 실제 Claude 검수·전체 재적용 검사를 수행한다.
- KEEP: 기존 실행 코드, 채팅·캐릭터·페르소나·Wiki·슬롯·설정·API/NAS 자격정보·화면 선택. 실제 앱 데이터와 장치는 이번 작업 입력으로 사용하지 않는다.
- VERIFY: 변경 전 소스 보존, 기준판 재구성 동일성, 고정된 최신 원작 태그에 전체 적용 후 서버·클라이언트·호환 검사·타입·빌드. 설치·실제 전송은 별도다.

`features.json`이 파일 소유권, `manifest.json`이 입력/패치/도구 해시와 대상별 호환 설정이다. 기존 전송 `integration.patch`를 먼저 적용하고 각 기능의 잔여 패치를 순서대로 적용한다. `transfer-sync` 잔여 패치는 현재 비어 있다. 이미 공통 integration에 포함된 변경을 중복 적용하지 않는다.

새 변경이 어느 모듈에도 등록되지 않거나 한 파일을 두 모듈이 소유하면 중단한다. 기존 설치 폴더·save·NAS로 복사하지 않으며, 새 임시 체크아웃만 만든다. 원작과 충돌하면 현재 포크 파일로 덮어쓰지 않고 해당 모듈에서 실패한다.

## Claude 검수 반영

실제 구독 Claude Opus 5.5 HIGH로 transfer 호환 병합 검수와 전체 스택 1·2차 검수를 진행했다. 1차에서 증거 버전 불일치, CRLF diff, 소유 범위, 누락된 Node 검사, 가변 lock 설치, rename 감지와 인계 누락을 지적했다. 실제 소스와 재현을 대조해 수정했다. 2차 판정은 차단할 코드 결함 없음이며, 전체 실행 결과는 당시 완료 전이라 별도 확인 대상으로 남겼다.

도구는 LF/실제 diff 소유 경로를 검사하고 storage-recovery의 검사 대역 변경을 해당 모듈로 옮겼다. Node 전용 검사 전체, 고정 lock 설치, 기존 probe+대상별 probe 총19개, 태그 커밋 고정, 시작/종료·Node/pnpm·매니페스트/실제 선택 패치 해시를 기록한다. 현재 원본에서 삭제·rename으로 빠진 경로는 0개다. 향후 삭제는 누락을 숨기지 않고 실패한다.

2차 검수 후 테스트 도구만 서버 파일 동시 실행 수4로 제한했다. 최종 문서는 검사 후 작성하므로 문서 해시가 바뀐다. 최종 증거에서 검사 당시와 최종 매니페스트를 비교해 문서 해시 외 변경이 없는지 확인하고 두 대상 구조 검사를 다시 수행한다. 최종 판정 원문은 별도 완료 로그 검수와 함께 보관한다.

## 재적용 절차

원본 개인 포크 작업 트리에서 실행한다. 최신 원작으로 조립된 임시 결과 폴더는 시험/빌드 후보이며 설치본이 아니다.

```powershell
node scripts/fork-modules/module-stack.mjs generate
node scripts/fork-modules/module-stack.mjs verify --target base --full --logs tmp/fork-modules-base
node scripts/fork-modules/module-stack.mjs verify --target v0.9.81 --full --logs tmp/fork-modules-upstream
```

1. 새 개인 수정은 `features.json`의 해당 모듈에 등록한다. 파일 소유권이 겹치면 공통 연결 모듈에 배치한다.
2. `generate`가 기존 공통 전송 연결 뒤의 기능별 diff와 해시를 새로 만든다. 여기서 실패하면 누락을 덮지 않고 원인을 확인한다.
3. 새 원작 태그를 `verify --target vX.Y.Z`로 별도 조립한다. 충돌이 있으면 그 대상용 호환 패치만 작성하고 sourceSha256/targetSha를 고정한다. 원작 새 기능을 통째로 되돌리지 않는다.
4. `--full`로 전체 검사를 통과한 뒤 실제 Claude에게 변경과 로그를 함께 검수받는다. `report.json`의 work가 조립 결과 위치다.
5. APK/Windows 패키지 생성·설치·실제 NAS 전송은 그 뒤 별도로 진행한다. 기존 모듈화/동기화/인앱 검수 문서는 이전 시점의 증거로 보존한다.

`verify --full`은 의존성 설치 후 모듈 도구, 전체 서버/클라이언트/호환 검사, 타입, 공개 경계 검사, 웹 빌드를 수행한다. HTTP 호환 테스트의 서버·자료는 임시 폴더의 합성 자료다. 실제 사용자 채팅·API·NAS를 읽지 않는다.

## 네이티브 재빌드와 한계

소스 모듈 목록에 개인 save·키·로그인 자료·로컬 SDK 캐시를 넣지 않았다. Android는 기존 `scripts/android/package-runtime.mjs`와 `runtime-lock.json`에 고정된 Node 24.21.0 아카이브/해시·16KiB 검사를 재사용한다. Windows 전송기는 기존 `AdbToolsPath`에 ADB 바이너리 3개와 NOTICE.txt가 있는 Android SDK platform-tools 경로를 넘긴다. 이번 첫 Windows 시도는 NOTICE.txt 없는 SDK 경로로 실패했고, 기존 완전한 SDK 경로로 다시 실행해 통과했다.

Windows 전송기 빌드와 12개 검사, Android 내부 debug APK 빌드와 17개 JVM 단위 검사를 실행했다. Android 첫 단위 검사 실행은 한글 Gradle 도구 경로에서 GradleWorkerMain을 찾지 못해 실패했고, 기존 도구를 영문 임시 경로로 연결해 동일 검사를 통과했다. APK 전체 CRC·서명·zipalign 16KiB 및 패키지에 들어간 두 ABI의 ELF LOAD 정렬까지 확인했다. debug APK는 설치/배포용 정식판으로 표시하지 않는다.

이번 범위에서 정식 APK/PC 배포 패키지, 실제 설치·태블릿/스마트폰 UI·NAS 전송·실플레이는 실행하지 않았다. 기존 설치본과 데이터는 그대로다. 미래 원작의 구조 변경은 새 호환 패치와 재검수가 필요하다.
