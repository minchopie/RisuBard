## 데이터 보존과 실패 처리

- 업로드는 이 기기에서 NAS로 게시한다. 수동 다운로드 작업은 로컬 변경을 게시하지 않는다. 기존 자동 게시 주기는 유지된다.
- 수신 자료는 기존 영속 대기열에 남는다. 생성·입력·스크롤·대화 전환 이후 적용을 미루는 기존 가드는 유지한다.
- 같은 대화 본문이라도 Wiki/슬롯/연결 자료가 다르면 기존 확인 규칙을 따른다. 시각이나 이름만으로 판본을 버리지 않는다.
- `applied-pending`은 일부 저장 확정 뒤에도 차이 확인 또는 삭제 보류가 남았다는 뜻이다. 완전한 동기화 성공으로 표시하지 않는다.
- 인앱 재시도는 **현재 실행 중인 클라이언트가 보관한 동일 트랜잭션**에 대해서만 기존 `finish`의 판정을 다시 요청한다. 새 전송·스냅샷·가져오기나 임의 `/hold`는 하지 않는다.
- 롤백 완료 기록은 이전 서버에 없던 선택 필드이며 앱 DB/전송 프로토콜 변경은 없다. 구 기록의 모호한 결과를 성공으로 추정하지 않는다.
- 서버가 `applied`를 확인하면 현재 자료를 유지하고, `rolled-back`을 증명하면 이 작업의 이전 메모리 상태만 복구한다. 부분 저장/불명확/연결 실패면 자료·저널·저장 잠금을 유지한다. 동시에 두 번 실행하지 않는다.
- 앱 재시작 이후에는 기존 시작 복구 경로가 영속 저널을 처리한다. 이번 버튼은 재시작한 앱의 메모리 상태를 추측해서 덮어쓰지 않는다. 기존 시작 복구의 사용자 확인 절차는 바꾸지 않았다.
- 정상 전송과 새 재시도에 자동 모달·전체 화면 덮개를 추가하지 않는다. 최종 저장/복구 구간의 기존 쓰기 보호는 유지하므로 모든 순간의 입력 가능성을 보장하는 변경은 아니다.

## 검수 상태

실제 구독 Claude CLI(`claude-opus-5-5`, HIGH)의 1차 검수는 조건부 승인, 2차는 코드 검수 승인이었다. 지적 6건을 재현/소스 대조해 다음과 같이 수정했다. CLI는 Read/Grep/Glob만 사용했고 개인 저장소·키·기기를 검수 입력으로 넘기지 않았다.

| 지적 | 처리 |
|---|---|
| 롤백 응답 유실 후 idle로 끝없이 대기 | 서버가 기존 서비스 manifest에 롤백 완료 기록을 남긴다. 재시작 뒤 남은 저널도 완료된 작업으로 정리한다. 예전 서버/기록에 대한 idle은 이 클라이언트가 전혀 수정하지 않았을 때만 해제하고, 이미 수정했다면 저장 원본을 추측하지 않고 앱 재시작 안내를 표시한다. |
| 마지막 적용 시각이 함수에만 있고 패널에는 없음 | 실제 패널 표시와 DOM 검사 추가. |
| 업로드 미룸이 다운로드 재시도 안내로 표시됨 | 방향과 무관한 재시도 안내로 수정. |
| 긴 재시도 도중 자동 타이머 소진 | 재시도 종료 후 기존 자동 주기 재예약. 일시 중지/꺼짐은 그대로 존중한다. |
| 다음 주기 시작 시 부분 적용 건수가 0으로 바뀜 | 완료 결과의 건수는 새 적용 결과가 올 때 갱신. 대화 열기 이벤트가 연달아 와도 직전 결과 유지. Codex 자체 검수에서도 발견해 검사 추가. |
| status 대기 중 생성 종료 시 수신 전용인데 snapshot 수행 | 해당 주기는 끝까지 수신 전용 유지. status/기존 계획 해제 대기 뒤에도 다시 확인. |

첫 원작 격리 검사에서는 새 retry export를 빠뜨린 `sendPreSync` 검사 대역 1건이 실패해 보완했다. 앱 전송 구현 실패와 구분한다. 복구 상태 줄은 좁은 화면에서도 안내·버튼이 줄바꿈되도록 했다.

2차 검수 후 Codex가 공통 상태 줄의 삭제 보류 문구도 확인했다. `keptDeletions`만 남은 경우에도 ‘일부 적용 완료’로 표시하고 기존 회귀 검사에 상태 문자열 검증을 추가했다. 이 두 파일 외 실행 코드는 2차 검수본과 동일하다.

## 적용 및 후속 인계

- 이 패치는 기존 더티 작업 트리의 **0.9.88 소스** 위에 적용했다. 버전을 새로 올리거나 공개 릴리즈하지 않았다.
- 독립 모듈은 기존 `manifest.json`의 파일 목록과 `integration.patch`로 원작에 다시 붙인다. 이번 작업만의 `scoped.diff`는 작업 전 개인 패치가 있는 사본 기준이며, 원작에 단독으로 적용하는 전체 모듈 패치와 구분한다.
- 원작 연결 절차: 기존 `check-upstream.mjs patch` → 대상 태그에 `verify --full`. 실제 충돌과 실패가 있으면 그 결과를 근거로 수정한다.
- 크로스오버와 루트 종합 인계/기준 문서/원장176에 실제 설치와 소스 검수의 경계를 기록한다. 설치본 자료를 앱 소스의 `save/`로 오인하지 않는다.
- `rolledBack` 완료 기록은 기존 `applied`와 같은 보관 방식이며 자동 정리 정책을 추가하지 않았다. 장기간 기록 증가를 실측하지 않았다.
- 예전 서버/기록에서 `idle`만 돌아오고 클라이언트가 이미 수정됐다면 안전하게 판정할 근거가 부족하므로 기존 시작 복구가 필요하다. 일부 저장 실패 자체를 버튼 하나로 무조건 해결한다고 보장하지 않는다.
- Claude가 남긴 비차단 검사 한계: 이 신규 롤백 회귀는 미디어/staging 실제 제거까지 단독 증명하지 않으며, 실제 타이머 소진 시점·계획 해제 직후 생성 전환·Android 좁은 화면의 접근성은 추가 실기기/경계 시험 대상이다.

실행하지 않은 것: 이 패치의 PC 앱 교체, Android APK 설치, 실제 개인 NAS 업로드/다운로드, 태블릿·스마트폰 실플레이. 소스 검수 및 모의 저장소 검사와 혼동하지 않는다.
