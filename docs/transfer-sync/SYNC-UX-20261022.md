## 수정 결과

### 페르소나

기존 `settings/personas` 그룹 전송 형식을 유지한다. 새 내부 도우미 `server/node/transfer-sync/nas-sync-reconcile.cjs`가 공통 이력을 기준으로 페르소나 ID별 3-way 병합을 수행한다.

- A,B와 A,B,C → A,B,C. 양쪽의 독립된 추가 항목도 함께 남는다.
- 한쪽 수정은 적용, 양쪽의 같은 수정은 하나로 처리한다.
- 삭제 대 수정, 같은 항목의 서로 다른 수정은 확인을 남긴다.
- 공통 이력이 없으면 안전한 추가의 합집합만 허용한다. 공통 기반이 모호하면 자동 병합하지 않는다.
- 명시적으로 충돌 내용을 선택해도 무관한 새 항목은 양쪽 모두 보존한다.
- 기존 ID와 채팅 바인딩을 다시 쓰지 않는다. 설명만 같고 ID가 다른 페르소나는 임의로 하나로 없애지 않는다.
- 잘못된/중복 ID, 보호된 참조, 같은 이미지 경로의 다른 해시는 자동 처리하지 않고 원본을 남기며 진단 안내를 표시한다. 실제 앱은 기존 `ensurePersonaIds`로 누락 ID를 초기화한다.
- 합쳐진 내용이 실제 참조하는 이미지·삽입 자료로 의존성 목록을 다시 계산한다.

전송 시 정렬은 결정적이지만 적용 시 기존 로컬 목록 순서를 유지하고 새 항목만 뒤에 붙인다. 각 기기의 선택은 인덱스가 아니라 기존 선택 ID로 유지한다.

### userNote와 현재 선택

`userNote`는 원래 앱의 현재 페르소나 메모 미러다. 독립적인 사용자 자료나 새 캐릭터 항목으로 취급하지 않는다.

- 선택과 `username/userIcon/personaPrompt/userNote` 미러를 독립 편집으로 게시하지 않는다.
- 전송 그룹에는 구버전 수신이 필요로 하는 결정적 호환 미러(정렬 첫 항목)를 유지한다. 신버전 수신은 그 미러를 선택 강제로 쓰지 않고 자기 선택 페르소나에서 다시 만든다.
- 과거 독립 `settings/userNote` 리비전은 이력에 남는다. 신버전은 값을 적용하지 않고 수신 확인만 마무리한다. 목록·충돌 개수에서 제외하고 해당 옛 루트의 직접 복원/택일은 거부한다.
- 전역 미러만 수정 중이거나 기존 마이그레이션으로 레코드와 어긋나 있으면 덮지 않고 보류한다. 화면에 해당 페르소나 이름과 편집·저장 후 재동기화 안내를 표시한다.

**모든 기기를 함께 업데이트해 사용해야 새 선택 보존 동작이 일관된다.** 구버전 기기는 호환 미러를 자기 선택으로 적용해 정렬 첫 항목으로 선택이 바뀔 수 있다. 새 코드의 자료 병합과 기존 앱 설치 완료를 혼동하지 않는다.

### 대화와 Wiki

- 대화 본문, Wiki/기억, 저장 슬롯, 이미지, 실행 설정·변수의 차이를 구분해 표시한다.
- 같은 본문에 다른 Wiki/연결 자료가 동시에 도착하면 불필요한 형제 대화를 만들지 않고 확인 대기로 둔다. 기억 파일을 임의로 합치지 않는다.
- 로컬에 대화가 아직 없더라도 임의의 Wiki 판본을 고르지 않는다. 이름이 표시된 선택지에서 사용자가 고른 판본 하나를 설치하고 나머지는 이력에 보존한다. 새 기기 수신→명시 선택→대화 하나 생성 경로를 검사했다.
- 실제 메시지가 갈라진 경우 기존처럼 각 갈래를 보존한다. 모든 갈래 적용이 확인되면 ‘보존된 갈래’로 구분해 미해결 충돌 수에서 제외한다.
- 대화의 정확한 실행 의존성 검사와 arm/save/finish 복구 계약은 유지한다.
- 적용할 자료 없이 보류만 있어도 ‘최신 상태’라고 표시하지 않고 받은 변경 확인 필요로 표시한다.

### 통합 화면

자동 동기화를 첫 영역으로 두고 직접 파일/USB/Wi-Fi 전송과 연결 설정은 접을 수 있게 했다. 동기화에 기기 키 전달이 필요하면 기존 직접 전송 영역을 펼친다.

캐릭터·대화·페르소나는 이름으로, 설정 그룹은 사용자용 제목으로 표시한다. 원시 루트 ID는 진단용 상세로 옮겼다. 출처가 현재 기기인지 다른 기기인지 구분하되, 근거 없이 다른 기기의 기종이나 적용 완료를 추정하지 않는다.

`GET /api/nas-sync/overview`는 마지막 동기화 기록의 대화·Wiki/기억 파일 수·슬롯·참조 페이지, NAS 업로드 또는 이 기기 적용 상태를 보여 준다. 새 메시지가 있으면 업로드 대기를 표시한다. **전체 Wiki의 현재 파일을 다시 캡처한 실시간 동일성 검사나, 다른 기기의 ACK 조회는 아니다.** 상대 기기의 적용 완료는 확인되지 않았다고 명시한다.

수정은 기존 구현 세 곳이다. 서버의 기존 스냅샷 거절에 `NAS_SYNC_PLAN_PENDING` 코드만 붙이고 HTTP400과 기존 메시지·가드는 유지한다. coordinator는 스냅샷의 이 코드만 기존 deferred 상태로 처리하고 publish/pull을 시작하지 않으며 다음 정상 주기에 계획을 다시 확인한다. 클라이언트의 일반 오류 경로에서는 이미 알고 있는 비어 있지 않은 계획을 `/arm` 요청 전(`!tookBusy`)에만 기존 finish(false) 경로로 정리한다. arm을 시도했거나 결과가 불확실한 계획은 새 정리 대상이 아니다.
