# RisuBard v0.9.78

## [안정성] 저장이 계속 실패하면 디스크가 가득 차던 문제

- **증상:** 데이터가 매우 큰 상태에서 저장이 실패하면, 저장을 다시 시도할 때마다 `save/kv/objects`에 데이터 전체 크기(1GB 이상)의 파일이 하나씩 쌓여 드라이브가 가득 찰 수 있었습니다. 미참조 파일 정리를 하거나 재시작하면 줄어들었습니다.
- **원인:** 호환용 데이터베이스 파일을 새로 쓸 때 이전 파일을 바로 지우지 않고 한 시간 뒤의 정리 작업에 맡겼습니다. 저장이 실패하면 몇 초마다 다시 써서 정리보다 쌓이는 속도가 빨랐습니다.
- **변경:** 새 파일을 쓰면 이전 파일을 바로 지웁니다. 백업 스냅샷이 같은 파일을 쓰고 있으면 지우지 않습니다.

## [성능] 출력 트리거가 있는 카드에서 채팅 파일이 계속 커지던 문제

- **증상:** 0.9.69에서 고친 "채팅 변수를 많이 쓰는 카드의 채팅 파일이 계속 커지던 문제"가 출력 시점에 실행되는 트리거를 가진 카드에서는 그대로 남아 있었습니다. 이런 카드는 대개 채팅 변수도 많이 써서, 응답마다 채팅 변수 전체 복사본이 지난 메시지에 계속 쌓였습니다.
- **원인:** 출력 트리거가 채팅을 바꾸면 앱은 바뀐 채팅의 사본으로 작업을 이어 갔습니다. 지난 메시지의 기록을 이 사본에서 지워서 실제로 저장되는 채팅에는 반영되지 않았습니다.
- **변경:** 저장되는 채팅에서 직접 지웁니다. 이미 쌓인 기록도 다음 응답을 받을 때 지워집니다.

## [성능] 리롤을 반복하면 마지막 메시지가 계속 커지던 문제

- **증상:** 채팅 변수를 많이 쓰는 카드에서 같은 응답을 여러 번 리롤하면, 리롤할 때마다 마지막 메시지가 채팅 변수 전체 크기의 두 배씩 커졌습니다. 채팅 변수가 크면 메시지 하나가 저장 한도를 넘어 저장 오류가 날 수 있었습니다.
- **원인:** 스와이프를 바꿀 때 채팅 변수를 그 스와이프의 상태로 되돌리려고, 스와이프마다 채팅 변수 전체를 응답 전과 응답 후로 두 번 복사해 두었습니다.
- **변경:** 같은 응답의 스와이프는 모두 같은 상태에서 시작하므로 채팅 변수 전체는 한 번만 저장하고, 나머지 스와이프는 그 결과와 달라진 변수만 저장합니다. 스와이프를 바꾸거나 리롤할 때 채팅 변수가 되돌아가는 동작은 그대로입니다. 이 버전 이후에 저장한 스와이프 기록은 이전 버전에서 열면 채팅 변수가 바르게 되돌아가지 않을 수 있습니다.

## 바드위키에 같은 이름이나 별칭의 문서가 생기던 문제

위키 작성 AI가 이미 있는 인물을 다른 이름으로 부르며 새 문서를 제안하면, 그 별칭이 기존 문서의 이름과 같아도 새 문서가 만들어졌습니다. 그 결과 같은 이름이나 별칭을 가진 문서가 여러 개 생겨 `[[이름]]` 링크가 어느 문서로 연결될지 정해지지 않았습니다.

- 새 문서 후보의 별칭이 기존 문서의 이름과 같으면, 새 문서를 만들지 않고 기존 문서를 갱신하며 새 이름을 별칭으로 더합니다. 대화에 실제로 나온 별칭만 이 판단에 씁니다.
- 한 번의 분석에서 같은 인물이 여러 이름으로 제안되면 하나의 문서로 모읍니다.
- `선배`처럼 여러 인물이 함께 쓰는 별명만 겹칠 때는 서로 다른 인물로 보고 합치지 않습니다. 대신 이미 다른 문서가 쓰는 별칭은 새로 붙이지 않아 링크가 엇갈리지 않습니다.
- 이름이 여러 기존 문서와 겹쳐 어느 문서인지 정할 수 없으면 새 문서를 만들지 않고 분석 결과에 `이름 충돌` 경고를 남깁니다.
