# RisuBard v0.9.80

## [안정성] 커진 채팅 때문에 저장과 설치 초기화가 계속 실패하던 문제

- **증상:** 0.9.77 이하에서 채팅 변수를 많이 쓰는 카드로 오래 대화하면, 업데이트한 뒤에도 저장할 때마다 `Invalid string length` 오류가 나고 `Server database flush failed (500)`로 저장이 멈출 수 있었습니다. 설치 초기화 창에서 롤백이나 초기화 다시 시도를 눌러도 같은 오류로 계속 실패했습니다.
- **원인:** 예전 버전은 AI 응답마다 채팅 변수 전체를 복사해 두었고, 이 복사본 때문에 메시지 하나가 저장할 수 있는 크기를 넘었습니다. 0.9.78은 새 응답을 받을 때 이 복사본을 지우는데, 저장이 먼저 실패해서 정리할 기회가 오지 않았습니다.
- **변경:** 서버가 채팅을 디스크에 쓸 때 마지막 응답이 아닌 메시지의 복사본을 지웁니다. 마지막 응답의 복사본도 너무 커서 저장할 수 없으면 그것까지 지우고 저장합니다. 이 경우 그 응답을 리롤해도 채팅 변수는 되돌아가지 않습니다. 대화 내용과 현재 채팅 변수는 그대로입니다.
- **업데이트 후:** 한 번 저장되면 디스크의 채팅은 줄어듭니다. 메모리에 남은 큰 데이터를 비우려면 앱을 한 번 재시작하세요.

## [수정] 아카라이브 복사에서 에셋메이드 삽화 뒤에 빈 그림이 붙던 문제

0.9.73부터 에셋메이드(Asset Maid) 같은 그림 플러그인이 넣은 삽화를 아카라이브용으로 복사하면, 삽화가 원본 대신 다시 구운 그림으로 들어가고 그 뒤에 빈 그림이 한 장 더 붙었습니다.

- **원인:** 에셋메이드는 삽화 위에 평소에는 보이지 않는 재생성, 이전/다음 버튼 묶음을 겹쳐 둡니다. 복사기가 이 겹친 층 때문에 삽화를 상태창처럼 그림으로 구웠고, 투명한 버튼 묶음을 숨은 창으로 잘못 알아 따로 한 장 더 구웠습니다. 버튼을 빼고 나면 그 그림은 비어 있었습니다.
- **해결:** 보이는 내용이 그림 한 장뿐인 블록은 0.9.72 이전처럼 원본 그림 파일을 그대로 넣습니다. 숨은 버튼과 히스토리 그림은 무시하고, 배경도 그림자도 없는 투명한 층은 숨은 창으로 보지 않습니다.
- 모듈 에셋, 캐릭터 에셋, 인레이 삽화 모두 원본 그림 한 장으로 들어갑니다. 배경 위에 캐릭터를 겹친 장면과 상태창은 지금처럼 그림으로 굽습니다.
- 메시지별 복사와 챗 저장기에 똑같이 적용됩니다.

## [성능] 메시지가 쌓일수록 봇 버튼이 느려지던 문제

봇 화면 안의 버튼(`risu-trigger`)을 누르면, 채팅이 길수록 반응이 늦어져 메시지 15개 정도에서 클릭마다 1초 가까이 걸렸습니다.

- **원인:** 버튼 하나를 누를 때마다 버튼과 상관없는 메시지까지 화면의 모든 메시지를 다시 그렸습니다. 트리거가 채팅 변수를 하나라도 바꾸면 전체를 다시 그렸고, 결과를 반영할 때 채팅을 통째로 바꿔 넣어 내용이 같은 메시지도 새것으로 취급됐습니다. 변수 묶음도 통째로 갈아끼워서 변수를 읽는 첫 메시지가 덩달아 다시 그려졌습니다.
- **변경:** 버튼이 있는 메시지만 다시 그립니다. 트리거가 메시지를 바꾸지 않았으면 기존 메시지는 그대로 두고 바뀐 변수만 씁니다. 아무것도 바뀌지 않은 클릭은 다시 그리지 않고, 트리거가 그 메시지를 이미 다시 그렸으면 두 번 그리지 않습니다.
- **결과:** 측정한 채팅에서 화면 전환 버튼은 약 1초에서 50ms 이하로, 상태를 바꾸는 버튼은 메시지 수와 상관없이 그 메시지 하나를 그리는 시간만 걸립니다.
- **봇 제작자 참고:** 실행된 트리거가 모두 Lua인 버튼은 이제 전체를 다시 그리지 않습니다. 버튼으로 다른 메시지의 표시까지 바꿔야 한다면 Lua에서 `reloadDisplay`를 부르세요. Lua가 아닌 트리거는 예전처럼 전체를 다시 그립니다.

## [수정] 플러그인이 콘솔을 로그로 뒤덮던 문제

V3 플러그인이 앱 기능을 부를 때마다 요청과 응답을 콘솔에 남겨서, 화면을 계속 살피는 플러그인이 있으면 개발자 도구 콘솔이 끝없이 차고 남긴 내용이 메모리에 쌓였습니다. 이 로그는 이제 기본으로 꺼져 있습니다. 필요하면 개발자 도구 콘솔에서 `localStorage.setItem('risubard.debugPlugins','1')`을 실행한 뒤 새로고침하면 켜집니다.

## [개발] 버튼 반응 시간 측정 로그

느린 버튼의 원인을 찾을 때 쓰는 측정 로그를 넣었습니다. 기본으로 꺼져 있고, 개발자 도구 콘솔에서 `localStorage.setItem('risubard.debugTiming','1')`을 실행한 뒤 새로고침하면 클릭마다 트리거 실행, 결과 반영, 메시지 렌더링, 화면 반영 시점이 `[timing]`으로 찍힙니다. 끄려면 `localStorage.removeItem('risubard.debugTiming')`을 실행합니다.
