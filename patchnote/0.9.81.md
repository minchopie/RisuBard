# RisuBard v0.9.81

## [수정] 0.9.80 이후 일부 봇의 버튼이 한 번 눌러서는 반응하지 않던 문제

0.9.80에서 봇 버튼을 빠르게 하려고 바꾼 동작 때문에, 일부 봇의 첫 메시지 페이지 넘기기 같은 버튼이 한 번 눌러서는 화면이 바뀌지 않고 다시 눌러야 반영됐습니다.

- **원인:** 0.9.80은 Lua 버튼이 채팅 변수를 바꿔도 버튼이 있는 메시지만 다시 그렸고, 채팅이 바뀌지 않은 것처럼 보이는 클릭은 아예 다시 그리지 않았습니다. 상태를 전역 변수나 Lua 안에 두는 봇, 버튼으로 다른 메시지의 표시를 바꾸는 봇은 이 때문에 화면이 늦게 따라왔습니다.
- **변경:** 기본 동작을 0.9.79처럼 되돌렸습니다. 버튼으로 채팅 변수가 바뀌면 모든 메시지를 다시 그리고, 버튼이 있는 메시지는 클릭마다 다시 그립니다. 0.9.80의 나머지 개선(내용이 같은 메시지를 새것으로 취급하지 않기, 변수를 키 단위로 쓰기, 트리거가 이미 다시 그린 메시지를 두 번 그리지 않기)은 그대로입니다.

## [봇 제작자] 빠른 버튼 모드

버튼의 상태를 채팅 변수에 두고, 그 상태를 버튼이 있는 메시지에서만 보여 주는 봇은 0.9.80의 빠른 동작을 직접 켤 수 있습니다.

- 채팅 변수 `__risubard_fast_buttons`를 `1`로 두면 켜집니다. 캐릭터의 기본 변수에 `__risubard_fast_buttons=1`을 넣거나 Lua에서 `setChatVar(id,'__risubard_fast_buttons','1')`을 부르면 됩니다.
- 켜면, 실행된 트리거가 모두 Lua인 버튼은 모든 메시지 대신 버튼이 있는 메시지만 다시 그리고, 아무것도 바꾸지 않은 클릭은 다시 그리지 않습니다. 메시지가 쌓여도 버튼 반응이 느려지지 않습니다.
- 버튼으로 다른 메시지의 표시까지 바꿔야 하면 Lua에서 `reloadDisplay`를 부르세요.

## [수정] 클릭해서 수정하기가 봇 화면의 탭과 입력 칸 클릭에도 편집을 시작하던 문제

"클릭해서 수정하기"를 켜면 메시지 안에서 봇이 그린 탭(라벨), 체크 칸, 입력 칸, 링크를 눌러도 메시지 편집이 시작돼 봇 화면이 사라졌습니다. 이제 이런 조작 요소와 `risu-trigger` 버튼을 누를 때는 편집을 시작하지 않습니다.
