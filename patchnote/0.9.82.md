# RisuBard v0.9.82

## [추가] 봇을 가져올 때 이미 설치된 봇을 새 버전으로 업데이트

리스렐름에서 받거나 charx, png, json 파일로 봇을 가져올 때, 같은 봇이 이미 설치되어 있으면 새 봇을 하나 더 만드는 대신 기존 봇을 업데이트할지 묻습니다.

- **같은 봇 찾기:** 리스렐름 항목이 같거나, 리스바드에서 내보낸 카드의 봇 ID가 같으면 같은 봇으로 봅니다. 그 밖에는 버전 표시(`v1.2`, `(2)` 등)를 뺀 이름이 같거나, 제작자가 같고 로어북과 정규식 제목이 대부분 겹치는 봇을 후보로 보여 줍니다. 후보에 없는 봇도 전체 목록에서 직접 고를 수 있고, `새 봇으로 설치`를 누르면 지금처럼 새로 설치합니다.
- **내 수정 지키기:** 처음 설치한 버전을 기록해 두고 세 버전을 비교합니다. 제작자만 고친 항목은 새 버전으로, 내가 고친 항목은 그대로 둡니다. 로어북, 정규식, 트리거, 에셋은 항목 하나씩 비교하며, 내가 추가한 항목은 원래 자리에 남깁니다.
- **둘 다 고친 항목만 묻기:** 제작자와 내가 같은 항목을 고쳤을 때만 바뀐 내용을 나란히 보여 주고 직접 고르게 합니다. 충돌이 없으면 요약만 보여 주고 바로 업데이트할 수 있으며, `전체 항목 보기`로 자동 처리된 항목도 확인하고 바꿀 수 있습니다.
- **처음 업데이트:** 이 기능이 생기기 전에 설치한 봇은 처음 버전의 기록이 없어 누가 고쳤는지 구분할 수 없습니다. 이때는 달라진 항목을 모두 보여 주고, `모두 새 버전`, `모두 내 버전`으로 한 번에 고를 수 있습니다. 이번 업데이트부터 기록이 남습니다.
- **그대로 두는 것:** 채팅, 채팅 폴더, 메모, 메모리, TTS 설정, 바드 로어 분석처럼 내 데이터는 바꾸지 않습니다. 업데이트 전 상태는 `(업데이트 전)`이 붙은 사본으로 휴지통에 3일 동안 보관합니다.
- 리스렐름에서 charx나 png로 받은 봇에도 이제 리스렐름 항목 ID를 기록하므로, 다음에 같은 봇을 받으면 바로 찾습니다. 채팅을 함께 담은 캐릭터 패키지는 지금처럼 항상 새 봇으로 설치합니다.

## [추가] 모듈을 가져올 때도 설치된 모듈을 새 버전으로 업데이트

risum, json, 모듈용 charx 파일이나 모듈 공유 링크로 모듈을 가져올 때도 같은 확인 창이 뜹니다.

- **모듈 ID 유지:** 업데이트해도 설치된 모듈의 ID를 바꾸지 않습니다. 그래서 봇과 채팅에 연결해 둔 모듈, 전체 켜짐 상태가 그대로 유지됩니다.
- **같은 모듈 찾기:** 같은 파일에서 나온 모듈(파일에 담긴 원래 모듈 ID가 같음)이나 같은 리스렐름 항목이면 같은 모듈로 봅니다. 그 밖에는 버전 표시를 뺀 이름, 같은 네임스페이스, 절반 이상 겹치는 에셋으로 후보를 찾습니다. 다른 사람이 RisuAI에서 내보낸 모듈도 파일의 원래 ID로 찾습니다.
- **병합:** 봇과 같은 방식으로 제작자만 고친 항목은 새 버전으로, 내가 고친 항목은 그대로 두고, 둘 다 고친 항목만 묻습니다. 로어북, 정규식, 트리거, 에셋은 항목 하나씩 비교합니다.
- **사본:** 업데이트 전 상태는 이름 끝에 `(업데이트 전)`이 붙은 꺼진 사본으로 모듈 목록에 남깁니다. 모듈마다 가장 최근 사본 하나만 두고, 다음 업데이트 때 바꿉니다.

## [추가] 에셋 저장 구조 전환: 에셋이 많아도 저장과 봇 설치가 느려지지 않게

지금까지는 에셋 하나를 저장할 때마다 모든 에셋의 목록 파일(`kv/manifest.json`)을 통째로 다시 썼습니다. 에셋이 수십만 개면 저장 한 번에 몇 초씩 걸려, 봇 하나 설치에 몇 시간이 걸리기도 했습니다.

- **새 에셋:** 이번 버전부터 새로 들어오는 그림과 파일은 데이터 폴더의 `asset-store/`에 파일 하나로 저장하고 목록 파일은 건드리지 않습니다. 에셋 이름에 내용의 지문(SHA-256)이 들어 있어 따로 목록이 필요 없고, 읽을 때마다 지문으로 내용을 확인합니다. 에셋이 몇 개든 저장 한 번의 비용이 같습니다.
- **기존 에셋 옮기기:** 옮길 에셋이 남아 있으면 메뉴의 홈 버튼이 주황색으로 깜빡이고, 시작 화면 맨 위에 주황색 `에셋 저장 구조를 전환해 주세요` 카드가 크게 나타납니다. 카드에서 옮길 에셋 수, 목록 파일 크기, 최근 목록 저장 시간을 바로 볼 수 있습니다. 자동으로 옮기지는 않습니다. `점검`은 옮길 개수, 목록 파일 크기, 최근 목록 저장 시간을 보여 주기만 합니다. `시험 전환`은 1,000개만 옮긴 뒤 모두 다시 읽어 확인하고, `전체 전환`은 5,000개씩 나눠 옮기며 진행률을 보여 줍니다. 도중에 멈추거나 창을 닫아도 다시 누르면 이어서 옮깁니다. 다 옮기면 홈 버튼 깜빡임이 멈추고 다음에 앱을 열 때 카드도 사라지며, 같은 패널은 `설정 > 개발자`에 남습니다.
- **원본 보존:** 같은 드라이브 안에서는 파일을 복사하지 않고 연결(하드 링크)만 만들어 디스크를 더 쓰지 않으며, 옮기는 동안 원본을 지우지 않습니다. 하드 링크를 쓸 수 없는 드라이브(exFAT 등)에서는 복사본을 확인한 뒤에만 더 쓰지 않는 원본을 지웁니다. 확장자가 대문자인 에셋(`.PNG` 등)은 대소문자를 구분하지 않는 드라이브에서 다른 에셋과 섞이지 않도록 지금처럼 목록 파일에 둡니다. 에셋 약 10만 개(8GB)인 실제 데이터 복사본에서 전체 전환이 10초 걸렸고, 목록 파일이 22.5MB에서 0.4MB로, 저장 한 번이 약 150ms에서 15ms로 줄었습니다. 전환 뒤와 되돌린 뒤 모든 에셋을 다시 읽어 원본과 한 바이트도 다르지 않음을 확인했습니다. 에셋이 많을수록 차이가 커집니다.
- **되돌리기:** 패널의 `되돌리기`로 모든 에셋을 목록 파일로 돌려놓을 수 있습니다. 이전 버전 앱으로 돌아가기 전에는 먼저 되돌려 주세요. 되돌리지 않고 이전 버전을 켜면 옮긴 에셋이 보이지 않지만, 이전 버전은 이 폴더를 지우지 않으므로 다시 이 버전으로 오면 그대로 보입니다.
- **삭제와 정리:** 지운 에셋은 바로 없애지 않고 `asset-store-trash/`에 두었다가, 기존 정리와 같이 1시간이 지난 뒤 지웁니다. 봇 삭제나 가져오기 취소처럼 지금도 공간을 바로 되찾는 정리는 그대로 바로 지웁니다.
- **백업:** 내보내기와 가져오기 형식은 그대로입니다. 백업을 복원하면 복원된 에셋은 목록 파일로 들어가므로, 에셋이 많다면 복원 뒤 다시 전환해 주세요.

## [추가] 모바일에서 메시지 버튼을 바로 펼쳐 보이는 설정

설정에 `모바일 메시지 버튼 펼쳐 표시`가 생겼습니다. 켜면 화면 너비가 640px보다 작을 때 번역, 리롤 같은 주요 메시지 버튼을 더보기 메뉴에 넣지 않고 메시지 아래에 바로 보여 줍니다. 기본값은 꺼짐이라 지금처럼 더보기 메뉴를 쓰며, 데스크톱 배치는 바뀌지 않습니다. (외부 기여, PR #44)

## [수정] 아카라이브 복사에서 접힌 캐릭터 그림과 봇 버튼이 빈 칸으로 나오던 문제

0.9.80부터 그림으로 굽는 블록 안의 버튼이 모두 빠져서, 아카라이브용 복사 결과에 빈 자리가 생겼습니다.

- **증상:** 펼치기 버튼 역할을 하는 접힌 캐릭터 그림(배경 위에 캐릭터를 겹친 장면)이 통째로 빈 그림이 되고, 봇 화면의 선택 버튼(이름 칩, 방 번호, 제출 버튼 등)이 사라져 틀만 남았습니다.
- **원인:** 그림으로 구울 때 버튼과 `role="button"` 요소를 모두 뺐습니다. 0.9.80에서 숨은 창 판별을 고치면서 이런 블록이 따로 떼어 구워지지 않고 바깥 블록과 함께 구워지게 되자, 안쪽의 버튼이 지워졌습니다.
- **변경:** 그림으로 굽는 블록 안의 버튼은 화면에 보이는 그대로 넣습니다. 화면에 떠 있는 고정 버튼(FAB)만 지금처럼 뺍니다.
- **FAB:** 봇이 `<button>`이 아닌 라벨이나 `div`로 만든 고정 버튼(예: 지도, 설정, 일정, 인물, 스쿼드)도 이제 빼서, 본문 끝에 버튼 이름이 글자로 줄줄이 붙지 않습니다. 화면에 고정된 작은 요소만 빼고, 안에 패널을 품은 큰 고정 창은 지금처럼 따로 그림으로 굽습니다.
- 메시지별 복사와 챗 저장기에 똑같이 적용됩니다.

## [수정] 아카라이브 복사에서 배경 위에 겹친 그림 조각이 따로 떨어져 나오던 문제

배경 그림 위에 액자처럼 기울여 얹은 작은 그림(예: 창밖 날씨 컷)이 장면과 함께 구워지지 않고, 장면 아래에 따로 한 장씩 큰 그림으로 붙었습니다.

- **원인:** 테두리, 그림자, 회전이 있는 이런 조각을 숨은 창으로 잘못 알아 따로 구웠습니다.
- **변경:** 그림 한 장만 담은 겹친 층은 숨은 창이 아니라 장면의 일부로 보고 장면과 함께 굽습니다.

## [수정] 그림이 많은 메시지를 아카라이브 챗 저장기로 복사하면 클립보드 오류가 나던 문제

메시지별 `아카라이브 챗 저장기` 버튼으로 그림이 많은 메시지를 복사하면 `Clipboard write was blocked due to lack of user activation.` 오류와 함께 복사가 실패할 수 있었습니다.

- **원인:** 브라우저는 클릭 직후 몇 초 안에만 클립보드 쓰기를 허락합니다. 복사기는 그림을 모두 구운 다음에 클립보드에 썼기 때문에, 굽는 데 그 시간을 넘기면 브라우저가 쓰기를 막았습니다.
- **변경:** 버튼을 누르는 즉시 클립보드 쓰기를 시작하고, 복사할 내용은 그림을 다 구운 뒤 채웁니다. 오래 걸리는 메시지도 복사됩니다.

## [수정] 첫 메시지만 있는 채팅에서 봇 버튼으로 연 패널이 닫히지 않던 문제

인사말만 있는 채팅에서 봇의 고정 버튼(FAB)으로 패널을 열면, 다시 눌러도 패널이 닫히지 않고 화면을 덮은 투명한 배경 때문에 다른 곳도 누를 수 없었습니다(예: Merry Sisters! Final의 설정, 스킬 버튼).

- **원인:** 버튼이 변수를 바꾸면 화면 전체를 다시 그리면서 메시지별 다시 그리기 횟수를 0으로 되돌립니다. 메시지를 다시 그릴지 판단하는 값이 두 횟수의 합이라, 화면 전체 쪽이 1 늘고 메시지 쪽이 1에서 0으로 줄면 합이 같아 다시 그리지 않았습니다. 그래서 두 번째 클릭부터 바뀐 변수가 화면에 반영되지 않았습니다.
- **변경:** 두 값을 더하지 않고 따로 비교하므로, 어느 쪽이 바뀌어도 메시지를 다시 그립니다. 패널을 몇 번이든 열고 닫을 수 있습니다.
