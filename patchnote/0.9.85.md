# RisuBard v0.9.85

바드위키 인물 문서가 턴마다 불어나던 문제를 줄이고, 문서를 바로 줄여 주는 `정본 압축` 버튼을 추가했습니다. 응답을 만들 때 예전 장면의 원문이 실제로 들어가도록 기억 배치를 고쳤고, OOC 메모장에서 메시지를 바로 지울 수 있습니다.

## [기능] 정본 압축 버튼으로 인물 문서를 바로 줄임
- **정본 압축 버튼:** `위키 도구`의 `정본 압축`과 문서 편집 화면의 `압축`으로, 캐릭터 문서 전체 또는 지금 보는 문서의 겹치는 줄을 AI가 합치고 사건 문서가 이미 기록한 줄을 정리합니다. 자동 정리와 달리 문서 크기나 새 응답 수를 따지지 않고 바로 실행합니다.
- **적용 전 미리보기:** 문서마다 `5,200자 → 2,900자 (44% 감소)`처럼 결과를 보여 주고, 적용할 문서를 골라 저장합니다. 적용 전 상태는 위키의 되돌리기에 남고, 미리보기 뒤에 바뀐 문서는 덮어쓰지 않고 건너뛰며, AI가 줄일 항목을 못 찾으면 그 이유를 표시합니다.

## [기능] 바드위키가 예전 장면의 원문과 인물 정보를 함께 가져옴
- **원문과 인물 문서를 따로 담기:** 기억을 두 칸으로 나눠, 인물과 장소 문서는 `기억 예산`의 목표 분량 안에 먼저 담고 사건 요약과 원문은 나머지 분량에 질문과 잘 맞는 장면부터 짝지어 담습니다. 원문은 예전에 인물 문서와 사건 요약 뒤의 마지막 차례라서 거의 들어가지 못했습니다.
- **요약 대신 제목:** 원문이 함께 들어가는 장면은 사건 요약 대신 제목과 순서 표시만 넣어, "그때 던진 꽃다발이 다음 날 어디 있었지?"처럼 두 장면을 함께 떠올려야 하는 질문에서도 두 장면의 원문이 같이 들어갑니다.
- **인물 문서 몫 제한:** 문서마다 칸의 4분의 1 정도(기본 1,000토큰)까지만 질문과 관련된 부분을 골라 넣어, 한 인물이 칸을 독점하지 않고 여러 인물이 나눠 들어갑니다.
- **시험 결과:** 45턴 시험 대화에서 같은 분량(약 7천 토큰)으로 확인한 결과, 지난 장면 질문 25개 중 정답 원문이 모두 들어간 질문이 0개에서 14개로, 인물의 상태와 관계 질문 7개 중에서는 4개에서 5개로 늘었습니다.
- **없는 과거 사실 금지:** 응답 지침에 출처가 없는 과거 사실(물건의 위치, 누가 한 말, 숫자, 이유)을 그럴듯하게 채우지 말라는 규칙을 넣었습니다. 롤플레이 중인 캐릭터에게 "모른다고 말하라"고 시키지는 않아 이야기 흐름은 깨지지 않습니다.

## [편의성] OOC 메모장에서 바로 삭제하고 위쪽 메뉴를 고정
- **메시지 삭제:** 각 카드의 `삭제`로 원본 채팅에서 바로 지웁니다. 사용자 입력을 지울 때는 이어진 AI 응답까지 함께 지울지 고를 수 있고, 연결된 바드위키 사건도 챗의 삭제와 같은 방식으로 철회하며 응답을 만드는 중에는 지울 수 없습니다.
- **위쪽 메뉴 고정:** 아래로 스크롤해도 제목, 챗 숨김, 글자 크기, 그룹 선택, 검색 줄이 불투명한 별도 층으로 위에 남아 지나가는 카드가 비쳐 보이지 않습니다.

## [편의성] 바드위키 설정을 간단과 고급으로 나눔
- **간단 보기의 작업 규모:** 위키 패널의 설정 탭과 환경설정에 `간단`과 `고급` 보기를 넣었고, 처음에는 간단 보기로 열립니다. `가볍게(24K)`, `보통(32K)`, `넉넉(48K)`, `크게(64K)` 중 작업 규모 하나만 고르면 위키 분석이 한 번에 읽는 분량과 분석에 넣는 로어북 양이 같이 맞춰지며, 보통이 이전 기본값입니다.
- **고급 값 유지:** 간단 보기에는 작업 규모, 작업 모델, 위키 작성 언어, 기억 예산만 보이고 나머지는 고급 보기에서 하나씩 고칩니다. 고급에서 직접 고친 값은 간단 보기에서도 그대로 쓰이고, 작업 규모를 새로 고를 때만 바뀝니다.

## [안정성] 바드위키 인물 문서가 턴마다 불어나던 문제
- **캐릭터 지시문 새로 작성:** 공식 기본 프리셋 2026-10-28판에서, 문제가 생길 때마다 규칙을 덧붙이다 서로 부딪히던 지시문을 처음부터 다시 썼습니다. 캐릭터 문서를 로그가 아니라 현재 카드로 다뤄 같은 주제의 줄을 고쳐 쓰고, 끝났거나 사건 문서가 이미 기록한 줄은 지우며, 보고 듣고 확인한 일은 `지식과 비밀`에 적지 않고 합친 줄의 턴 표시는 `(#4–#9)`처럼 묶습니다.
- **프리셋 자동 교체:** 공식 기본 프리셋을 쓰고 있었다면 업데이트 뒤 자동으로 새 판으로 바뀌고, 이전 판(2026-10-27)은 `과거 공식 프리셋` 폴더에 보관됩니다. 보관판은 3개까지만 유지해 가장 오래된 판은 정리되며, 직접 복사해 고친 프리셋은 그대로 둡니다.
- **리부트 뒤에도 정리:** 위키 리부트 중에는 인물 문서 정리가 꺼져 있어서 45턴 시험 대화에서 문서 하나가 4만 바이트 가까이 불어났습니다. 이제 리부트 중에도 같은 기준으로 정리하고, 이미 불어난 문서는 다음 갱신 때 크기를 보고 정리하거나 `정본 압축`으로 바로 줄일 수 있습니다.
- **막힌 정리를 더 일찍 재시도:** 줄일 항목을 못 찾아 `정본 정리 보류`가 나오면 새 응답 8개 대신 3개가 쌓였을 때 다시 시도합니다. 정리 때 `(#4)` 같은 사건 번호로 앞선 사건 문서를 찾아 근거로 쓰므로, 예전 사건이 남긴 항목도 지워집니다.
- **중복 절 제목:** AI가 `### 지식과 비밀`처럼 표시 기호까지 붙여 돌려주면 기존 절을 못 고치고 `### ### 지식과 비밀` 절을 하나 더 만들던 문제를 고쳤습니다. 이미 생긴 절은 다음 갱신 때 원래 절과 합쳐집니다.
- **끊어진 링크 자동 보정:** AI가 사건 제목을 한두 단어 다르게 적어 점선으로 끊기던 `[[링크]]`를, 문서를 저장할 때마다 가장 비슷한 실제 제목으로 고쳐 씁니다. AI 호출 없이 글자 유사도만 계산하고, 비슷한 제목이 둘 이상이거나 충분히 비슷하지 않으면 그대로 둡니다.

## [안정성] 원격 임베딩 모델에서 의미 검색이 빠지던 문제
- **조회 제한 시간까지 대기:** 의미 검색이 질문 임베딩을 2초까지만 기다리고 아무 표시 없이 단어 검색만 쓰던 탓에, OpenRouter 같은 원격 모델(시험한 qwen3-embedding-8b는 5~11초)을 쓰면 임베딩 비용만 내고 결과는 거의 쓰이지 않았습니다. 죄송합니다. 이제 `위키 조회 제한 시간`(기본 10,000ms)만큼 기다리며, 그만큼 응답 시작이 늦어질 수 있습니다.
- **빠진 이유 표시:** 시간 초과, 임베딩 준비 중, 요청 실패로 의미 검색이 빠지면 요청 기록의 `위키 조회 진단`에 이유가 나오고, 색인 생성 실패(키나 모델 이름 오류)는 "만들기 실패"로 따로 표시합니다. 응답이 빠른 임베딩 모델이 좋으며, 모델을 바꾸면 위키 전체를 다시 임베딩합니다.

## [안정성] 모델이 응답하지 않을 때 위키 정리가 끝나지 않던 문제
- **다시 시도와 추가 분석이 바로 시작:** 모델 서버가 응답하지 않으면 요청 하나가 약 5분 뒤 실패하고 설정한 횟수만큼 다시 보내는데, 그동안 `다시 시도`나 `추가 분석`은 앞의 요청 뒤에 줄만 서서 정리가 계속 도는 것처럼 보였습니다. 이제 두 버튼은 그 챗에서 진행 중이거나 기다리던 위키 정리를 끊고 바로 새로 시작하며, 다른 챗은 건드리지 않습니다.
- **계속 응답이 없을 때:** 새 시도도 다시 기다리게 되니 `fetch failed`가 보이면 리스바드 서버가 모델 주소에 연결되는지(인터넷, VPN, 프록시) 확인해 주세요.

## [성능] 밀린 위키 정리를 턴 묶음으로 처리
- **턴 묶음 분석:** 정리 중에 새 응답이 쌓이면 밀린 턴마다 분석을 따로 돌리던 것을, 들어가는 만큼(최대 4턴) 묶어 분석 한 번으로 처리합니다. 사건 문서는 턴마다 따로 남고, 아크플로터는 늘어난 사건만큼 체크포인트를 함께 반영합니다.
- **중복 분석 제거:** 고칠 문서가 한 번에 쓰는 양보다 많을 때 남은 후보를 버리고 분석부터 다시 돌리던 것을, 첫 분석 결과로 남은 문서까지 이어서 작성하게 했습니다. '한 번에 고칠 위키 문서 수' 설정은 없애고 문서 길이를 보고 정하며, 응답이 잘리거나 깨지면 묶음을 반으로 나눠 다시 시도합니다.
- **분석 최대 길이 기본값:** 8,192에서 32,768 토큰으로 올려 긴 응답의 앞부분이 잘리는 일이 줄었습니다. 직접 바꿔 저장해 둔 값은 그대로 씁니다.

## [시스템] 휴지통 자동 정리
- **14일 지난 항목 삭제:** 데이터 폴더의 `trash`에서 14일이 지난 항목을 서버가 시작하고 2분 뒤, 이후 하루에 한 번 지웁니다. 진행 중인 복구 기록(`live-files-recovery`)은 건드리지 않습니다.
- **보관 일수 설정:** 환경 변수 `RISUBARD_TRASH_RETENTION_DAYS`로 보관 일수를 바꿀 수 있고, `0`이면 자동 정리를 끕니다.

## [호환성] 내보낸 charx와 모듈 파일을 가져올 수 없던 문제
- **우연한 구분 표시 충돌:** 캐릭터 `.charx`와 모듈 `.module.charx`를 내보낼 때 그림 데이터 중간에 ZIP 구분 표시와 같은 바이트가 우연히 들어 있으면 리스바드나 리스에서 가져오지 못했습니다. 이제 각 파일의 크기를 미리 적어 두므로 내용과 상관없이 가져올 수 있습니다.
- **다시 내보내기:** 이미 내보낸 파일은 그대로이니, 가져오기가 안 되던 파일은 이 버전에서 다시 내보내 주세요.
