# RisuBard v0.9.85

NAS 동기화 적용 계획과 다음 스냅샷 요청이 겹칠 때 발생하던 `Finish the pending sync apply before taking a snapshot` 오류를 수정합니다. 기존 0.9.84의 기능을 포함하는 개인 포크 배포입니다.

## 변경

- 이전 적용 계획이 늦게 준비되어 새 스냅샷과 겹치면 일반 오류로 표시하지 않고 기존 적용을 기다린 뒤 재시도합니다. 진행 중인 저장·적용 기록을 강제로 지우지 않습니다.
- 적용을 시작하기 전 자료 준비나 저장 대기에서 일반 오류가 발생한 경우, 이미 준비한 계획을 기존 정리 경로로 해제합니다. 적용 시작을 요청한 뒤의 불확실한 기록은 이 정리 대상에서 제외합니다.
- 수동 버튼을 **업로드**(이 기기 → NAS), **다운로드**(NAS → 이 기기)로 분리합니다. 다운로드 전 로컬 변경은 보존하되 이 수동 작업에서 업로드를 실행하지 않습니다. 기존 자동 동기화 주기는 유지합니다.
- 자료 목록에 이름과 NAS 최신판의 날짜·시간을 한국시간으로 표시합니다. NAS 파일 시각이 없는 옛 로컬 판본은 업로드 확인 시각임을 명시하고, 알 수 없는 날짜는 추정하지 않습니다. 마지막 전송으로 확인한 기록이며 날짜로 충돌 판본을 덮어쓰지 않습니다.

## 기존 데이터 유지

Android는 일반판 `app.risubard.personal`을 삭제하거나 초기화하지 않고 업데이트 설치합니다. Windows는 앱을 종료한 뒤 같은 Windows 계정·같은 기존 폴더에서 `save`와 기존 설정·키를 보존해 앱 파일을 업데이트합니다. 설치 폴더 밖 `%LOCALAPPDATA%\RisuBard\nas-sync`의 기기 정보도 유지해야 합니다. 새 폴더·다른 계정으로 이전하는 작업과는 다릅니다.

기존 대화·페르소나·프리셋·모듈·API/NAS 설정을 일괄 초기화하지 않습니다. 새 보안 기능·인증 절차·프로토콜·외부 의존성은 추가하지 않았습니다.

## 검증 범위

Codex가 오류를 재현하는 회귀 검사와 수정 후 검사를 실행하고 실제 구독 Claude Opus 5.5 HIGH가 변경 코드·시험 결과를 검토합니다. 최종 전체 검사·패키지 검사 결과는 첨부 `RELEASE-CHECKS.md`에 기록합니다.

실제 NAS·기기 간 동기화와 장기 플레이는 이번 릴리즈에서 검증하지 않았습니다. 기존 `sync apply deadline` 전체 원인이나 모든 환경의 동기화 완료를 이번 수정으로 보장하지 않습니다. 이번 요청은 릴리즈이며 기존 기기 설치·자료 변경은 실행하지 않습니다.
