# 0.9.92-ver11

## [추가] NAS 배포로 플러그인(.js)도 올리고 받음

- 사용자: 「플러그인도 받을 수 있도록 수정해서 버전업하자.」
- 이전: NAS 배포는 캐릭터 카드·페르소나·프롬프트 프리셋만 받았다.
- 이제(content-updates 모듈의 자체 파일만, 호스트 파일 변경 없음):
  - 설정 > 캐릭터·페르소나 배포에서 `.js` 플러그인을 고르면 `//@name`·`//@version` 줄에서 이름과 판을 읽어 `plugin:<이름>`으로 올린다.
  - 다른 기기는 「새 플러그인이 올라왔어요. 지금 가져올까요?」를 묻고, 「네」일 때만 받아서(크기·SHA-256 확인) 원작 `importPlugin`에 스크립트를 넘긴다. 손으로 파일을 고른 것과 같은 경로라 원작 창(「기존 플러그인을 업데이트하시겠습니까?」, API 2.1 안전 검사, 헤더 오류)이 그대로 뜬다.
  - 같은 이름의 플러그인을 바꾼 뒤에는 원작 코드 편집기의 「적용」(`applyPluginCode`)과 같은 규칙으로 이 기기의 설정값(새 판에도 있는 항목)과 켜짐/꺼짐을 되돌리고 다시 불러온다.
  - 같은 이름에 스크립트가 같으면 묻지 않고 「가져옴」으로 적는다(받아서 비교, 페르소나와 같은 방식).
  - 가져오는 동안 페르소나·프리셋과 같이 `transferBusy`를 잡는다.
- 옛 판 보호: ver10 이하 클라이언트는 모르는 종류를 페르소나로 묻고 캐릭터로 가져오려 하므로, 서버는 목록 요청에 `kinds`가 없으면 기존 세 종류만 보낸다. ver11 클라이언트는 `kinds`를 보낸다.
- 서버: 플러그인은 `.js`만, 8 MiB까지.
- 검수(Opus 에이전트, 읽기 전용) 반영: 원작 `importPlugin`은 플러그인을 목록에 넣은 뒤 자체 저장이 실패해도 아무 값도 돌려주지 않는다(오류 창만 띄움). 이때 「아니오」로 적지 않고, 설정값·켜짐/꺼짐을 되돌린 뒤 다시 불러오고 여기서 저장한다(저장이 또 실패하면 오류로 끝나고 기록하지 않음).
- 시험 +10(클라이언트 7, 서버 3). 이전 코드에서 모두 실패 확인.
- 구현: Opus 에이전트(커밋 `fc04547`), Claude가 변경 대조·검사·배포.
