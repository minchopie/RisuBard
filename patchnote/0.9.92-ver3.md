# 0.9.92-ver3

## [변경] 카드 Lua `getFullChat`에 메시지 ID 추가

- 배경: 앱은 요청에 들어가는 대화 메시지마다 메시지 ID(chatId)를 붙여 보낸다(memo). 카드 Lua의 `getFullChat`에는 이 ID가 없었다. 그래서 카드는 요청 속 메시지가 저장된 대화의 어느 메시지인지 글로 짐작해야 했다.
- 변경: `getFullChat`이 돌려주는 각 메시지에 `id`(그 메시지의 chatId)를 더한다. `role`·`data`·`time`은 그대로다. ID가 없는 메시지에는 `id`를 넣지 않는다.
- 영향: `role`·`data`·`time`과 메시지 순서·개수는 그대로라, 이 필드를 읽는 카드는 동작이 같다. 메시지의 키 전체를 비교하는 카드(예: `getChat` 결과와 키 집합 비교)는 `id` 하나가 더 보인다(`getChat`·`getRecentChats`는 바뀌지 않았다). 마물소녀도감 카드 1.2.35-argon.10이 이 값으로 대화 창을 정확히 자른다.
- 모듈: `lore-lua`(`src/ts/process/luaChatEntry.ts`, 시험 `luaChatEntry.test.ts`, `scriptings.ts`의 getFullChatMain 한 곳).

## [수정] 요청 직전 카드 Lua(editRequest)가 생성 중인 채팅을 읽도록

- 배경: 앱은 생성 대상 채팅을 고정해 두고(target) 답을 그 채팅에 저장한다. 그런데 요청 직전에 카드 Lua를 부르는 두 곳(editRequest)만 이 대상을 넘기지 않았다. 그래서 생성 도중 다른 채팅 페이지로 옮기면 카드 Lua의 `getFullChat`·채팅 변수가 지금 보고 있는 채팅을 읽었다. 원작 0.9.92·0.9.94도 같다.
- 변경: 두 editRequest 호출에 이미 있는 생성 대상(target)을 넘긴다. 출력 편집(editOutput 등)은 원래부터 대상을 넘기고 있었고, 같은 방식이다.
- 영향: 채팅을 옮기지 않으면 동작이 같다. 대상 채팅을 찾지 못하면(생성 중 삭제 등) 카드 Lua 요청 편집을 건너뛰고 원래 요청을 그대로 쓴다.
- 모듈: `transfer-sync`(`src/ts/process/index.svelte.ts`를 맡은 모듈, 두 줄).
