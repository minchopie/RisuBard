# 0.9.92-ver4

## [수정] NAS에서 큰 카드를 받다가 「socket hang up」으로 실패하던 문제

- 증상: 태블릿이 집 와이파이에 있는데도 마물소녀도감 1.2.35-argon.16(115MB, 전신 에셋 64장 포함)을 NAS에서 가져오다가 「socket hang up」으로 실패했다.
- 원인(추정): 앱 서버는 기기의 와이파이 보고로 NAS 집 주소/외부 주소를 고른다. Android는 이 보고를 NAS 동기화 주기 직전에만 보내고, 서버는 2분이 지난 보고를 믿지 않아 외부 주소를 쓴다. 집 안에서 외부 주소로 나가는 연결은 느리고 자주 끊긴다(확인: PC에서 외부 주소로 같은 파일을 받아 같은 오류를 재현, 집 주소로는 4.4초에 받음). 태블릿이 그때 외부 주소를 골랐는지는 기기 기록이 없어 직접 확인하지 못했다.
- 변경 1(클라이언트): NAS 배포 목록 확인·가져오기·올리기 직전에 와이파이 보고를 다시 보낸다. 집 와이파이에서는 집 주소를 쓴다. 보고에 실패하거나 3초 안에 끝나지 않으면 기다리지 않고 전처럼 진행한다. 위치 권한이 없어 와이파이 이름을 모르면 전처럼 외부 주소다.
- 변경 2(서버): 받기 중 연결이 끊기거나 멈추면 이미 받은 부분부터 HTTP Range로 이어 받는다(최대 5번). 한 번 받는 동안 집/외부 주소는 처음 정한 대로 유지한다(NAS 동기화 한 번과 같은 방식). Range를 무시하는 서버는 처음부터 다시 받는다. 끝에서 크기·해시를 확인하는 것은 그대로다.
- 그대로인 것: 집/외부 주소를 고르는 규칙(모르는 와이파이·오래된 보고는 외부), 올리기 방식, 앱 코드 업데이트(백그라운드 확인은 서버 혼자 하므로 이번 보고 갱신이 닿지 않는다).
- 모듈: `content-updates`(`src/ts/content-updates/contentUpdates.ts`, `server/node/content-updates/content-updates.cjs`, 시험, `docs/content-updates/README.md`).
