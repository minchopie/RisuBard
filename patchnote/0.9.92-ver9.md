# 0.9.92-ver9

## [정리] 재활용 점검 2차 — 나머지 모듈 전부 (Codex R2~R5)

- 사용자: 「나머지 우리가 생성한 모든 모듈도 다 봐줘.」 기준은 1차와 같다: 이미 있는 함수와 동작이 똑같은 것만 바꾸고, 새 공용 함수는 만들지 않는다. 기능 변화 없음.
- 범위: transfer-sync 서버(19개 구현 파일 + 공유 7개), transfer-sync 클라이언트·설정 화면, storage-recovery, host-bridges, bardwiki-cache-prefix, file-export, mobile-ui, model-compat, lore-lua, legacy-local-ai, distribution. history-docs는 문서라 제외.
- 반영(transfer-sync 서버):
  - `play-set-fingerprint.cjs`, `play-set-service.cjs`: 자체 SHA-256 함수 삭제 → `play-set-relink.cjs`의 `hash`.
  - `nas-sync-service.cjs`, `nas-sync-share.cjs`, `nas-sync-projection.cjs`: 자체 `sha256` 정의 삭제 → 이미 불러오는 `file-store.cjs`의 `checksum`. `nas-sync-store.cjs`의 같은 해시 식도 `checksum`.
  - `nas-sync-service.cjs`: 항목 키 문자열을 직접 만들던 10곳 → `nas-sync-core.cjs`의 `rootKey`.
- 반영(model-compat): `translator.ts`의 모바일 구글 번역 조건 1줄 → 이미 불러온 `shouldBatchPrivateMobileGoogleTranslation`(v0.9.92 호환 패치 포함).
- 반영 안 함: 파일 SHA-256 읽기 4곳을 앱 코드 업데이트의 `hashFile`로 바꾸는 것(동작은 같다고 판정됐지만 줄 수가 줄지 않고 동기화 모듈이 앱 코드 업데이트 모듈에 새로 기대게 됨). 그 밖의 유사 코드 약 30건은 허용 입력·오류 처리·재시도 조건·불러오기 격리가 달라 그대로 둔다(판정은 REVIEW).
