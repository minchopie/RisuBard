# 0.9.96-ver10

- 대상: 원작 안정판 v0.9.96 `97ea0351120b2a6decba8985e6c8c3cef6517ddf`. 0.9.96-ver9 위의 판이다.
- 이 판은 두 부분이다: 「내 기기 자동 동기화」가 도는 간격(아래 첫 부분)과 속도 개선(아래 「바뀐 것: 속도」). 둘 다 앱 코드만 바꾸며 **런타임 지문을 바꾸지 않는다**(ver9와 같은 `33b30c76…`).

## 바뀐 것: 자동 동기화 = 답 5번 또는 1시간 중 먼저 오는 쪽
지금까지는 자동 동기화가 **동기화가 끝나고 30초마다**, **저장이 끝나고 5초 뒤마다**, 그리고 앱으로 돌아올 때·창을 다시 누를 때(30초 넘게 지났으면)·채팅을 열거나 캐릭터를 바꿀 때·인터넷이 다시 연결될 때마다 돌았습니다. 한 번 돌 때마다 「내 변경을 묶는 중」 동안은 저장이 잠깐 기다려야 해서, Asset Maid처럼 자주 저장하는 편집이 계속 끊겼습니다.

이제 자동 동기화는 **마지막 동기화 뒤 답을 5번 받았거나 1시간이 지났을 때**(먼저 오는 쪽) 한 번 돕니다.
- 답 1번 = 채팅에 답 생성이 한 번 시작된 것. 새 메시지 보내기, 다시 생성(리롤), 다시 보내기, 손으로 누른 이어 쓰기, 캐릭터 비서·명령어(`/multisend` 줄마다)·파일 여러 줄 보내기·플러그인이 채팅에 보낸 것도 각각 1번입니다.
- 세지 않는 것: 한 번의 답 안에서 앱이 스스로 다시 시작하는 것(자동 이어 쓰기, 트리거가 요청한 이어 다시 보내기 — 기다린 시간이나 채팅 모양과 상관없음), 프롬프트 미리보기(개발 도구·단축키), 이미 답을 만드는 중이라 시작되지 않은 보내기, 앱을 다시 켤 때 이어 붙는 서버 작업, 채팅 답이 아닌 모델 호출(BardWiki 보조 호출, 플러그인의 보조 요청, 기억·번역 등).
- 다섯 번째 답은 답이 다 만들어진 뒤에 동기화합니다(답을 만드는 동안 동기화하지 않는 것은 그대로).
- 저장, 앱으로 돌아오기, 창 다시 누르기, 채팅 열기, 캐릭터 바꾸기, 인터넷 재연결은 그 자체로는 동기화를 시작하지 않습니다. 때가 됐으면(5번 또는 1시간) 그때 돕니다.
- 세는 숫자와 마지막 동기화 시각은 기기마다 따로 기억합니다(동기화되지 않음). 앱을 켤 때 하는 동기화도 「마지막 동기화」라서 그때부터 다시 셉니다(그 동기화를 하지 못했으면 껐다 켜기 전의 숫자와 시각을 이어 갑니다).

그대로인 것:
- **앱을 켤 때 한 번** 동기화합니다(다른 기기에서 한 것을 먼저 받아 오기 위해).
- 「NAS에 업로드」·「이 기기에 다운로드」 버튼, 자동 동기화 켜기·재개는 누르면 바로 돕니다. 손으로 돌린 것도 「마지막 동기화」로 칩니다.
- 실패했을 때 다시 시도(5초 → 15초 → 1분 → 5분), 다른 작업 중일 때 잠깐 뒤 다시 시도, 답을 만드는 동안 미뤘다가 끝나면 이어서 하기, 적용 복구, 처음 합류·기준 채택, 화면 설정 동기화 제외, 동기화 잠금은 전과 같습니다. 실패 뒤 인터넷이 다시 연결되면 바로 다시 시도합니다.
- 앱이 가려져 있는 동안(최소화·다른 앱) 하지 못한 동기화는 다시 돌아오면 바로 합니다.
- 받아 온 변경은 전처럼 안전한 때(앱을 켤 때, 앱으로 돌아올 때, 채팅을 열 때, 버튼을 누를 때)에만 적용합니다. 받아 놓고 아직 적용하지 못한 변경이 있으면, 그 사이에도 5분에 한 번까지는 앱으로 돌아오거나 채팅을 열 때 적용을 시도합니다.
- 보내지 않은 변경은 사라지지 않습니다. 다음 동기화 때 함께 올라갑니다. 앱 업데이트·콘텐츠(카드·플러그인·모듈·프리셋) 업데이트 확인은 동기화와 따로 돌아서 늦어지지 않습니다.

## 바뀐 것: 플러그인 전체 화면(Asset Maid 작업 공간)이 열려 있는 동안
- 자동 동기화를 시작하지 않고, 받아 온 변경도 적용하지 않습니다. 창을 닫으면 30초 안에 밀린 동기화가 돕니다.
- **창을 계속 열어 두면 자동 업로드도 그동안 계속 미뤄집니다**(1시간이 지나도). 닫으면 바로 따라잡습니다. 열어 둔 채 다른 기기로 옮겨 가야 하면 창을 닫고 「NAS에 업로드」를 눌러 주세요.
- 이유: 플러그인 전체 화면 안에서 누르고 쓰는 것은 앱이 볼 수 없어서(분리된 화면), 앱은 사람이 아무것도 안 하는 줄 알고 받아 온 변경을 적용할 수 있었습니다. 그러면 Asset Maid가 편집을 시작할 때의 설정과 저장할 때의 설정이 달라져 「설정의 편집 기준이 변경되었습니다.」가 뜰 수 있습니다(Asset Maid 설정은 동기화되는 플러그인 저장소에 있음. 이 알림이 실제로 그 때문에 떴는지는 확인하지 못함).

## 바뀐 것: 속도 (이 판의 두 번째 부분)
동작·화면·저장 내용은 그대로 두고, 앱이 쓸데없이 하던 일만 줄였습니다. 모델 응답·네트워크·디스크 속도처럼 기기 밖의 시간은 그대로입니다.
- **플러그인 저장소 읽기**: 플러그인이 자기 설정 한 줄을 읽을 때마다 앱이 전체 데이터(모든 캐릭터·채팅)를 통째로 복사하던 것을, 그 한 줄만 복사하도록 바꿨습니다. Asset Maid는 열 때·보낼 때마다 이 읽기를 여러 번 합니다.
- **플러그인이 캐릭터를 저장할 때 같은 채팅을 다시 올리지 않음**: Asset Maid가 「프롬프트 저장」 등으로 캐릭터를 저장하면 내용이 똑같은 긴 채팅(시험 데이터 2.8MB)도 매번 통째로 다시 저장했습니다. 이제 채팅이 정말 같을 때(깊은 비교로 확인될 때)만 건너뛰고, 조금이라도 다르거나 확실하지 않으면 전처럼 저장합니다.
- **로어북 검색**: 메시지를 보낼 때 로어북 항목마다 최근 메시지 글을 다시 만들던 것을, 한 번의 보내기 안에서만 재사용합니다(보내기가 끝나면 버림). 프롬프트 결과는 1바이트도 바뀌지 않습니다.
- **플러그인 응답 전달**: 플러그인에 큰 데이터를 넘길 때의 내부 검사를 줄였습니다(넘기는 내용은 같음).

## 주의
- 동기화가 드물어진 만큼, **다른 기기로 옮겨 가기 전에는 설정 → 「NAS에 업로드」를 한 번 눌러 두세요.** 다른 기기에서 바로 이어집니다(누르지 않아도 다음 동기화 때 올라갑니다). 두 기기에서 같은 것을 동기화 사이에 고치면 전처럼 충돌 검토로 갑니다.
- 실제 기기(PC 앱·휴대폰·태블릿)에서의 확인은 아직 하지 않았다(단위 시험·조립본 브라우저 흐름 시험·격리 시험 데이터 실측만).
