# RisuBard 0.9.96-ver11

## 고친 것: 카드 업데이트 뒤 Asset Maid가 열리지 않던 문제
- 같은 그림의 이름만 바뀐 카드로 업데이트하면 그림 번호는 맞게 옮겼지만, Asset Maid가 그림을 찾는 지문은 옛 이름 그대로 남을 수 있었습니다.
- 이제 사용자 레퍼런스를 옮긴 뒤, 최종 그림의 이름·확장자와 같은 이름 그림의 순번에 맞춰 캐릭터 그림 기록을 바로잡습니다. 이미 맞는 기록과 모듈 그림 기록은 그대로 둡니다.
- 그 기기에서 직접 고른 레퍼런스 유지, 사라진 인물·폼의 보류 안내, crop 그림 보존은 그대로입니다.
- 이미 이 문제로 깨진 카드도 같은 배포를 「다시 받기」 → 기존 캐릭터 업데이트 화면 → 「적용」으로 복구할 수 있습니다. 저장된 비교 기준이 같은 새 판이라 Asset Maid가 「내 버전 유지」로 골라져 있어도, 적용을 마친 뒤 그림 번호를 확인해 풀리지 않는 기록만 바로잡습니다. 직접 고른 레퍼런스는 그대로 둡니다.
- 풀리는 기록들로 그림 번호가 실제 위치와 같은지 확인할 수 없거나, 해당 그림이 없으면 임의로 고치지 않고 복구한 수·그대로 둔 수와 이유를 알립니다. 정상 기록과 본문은 그대로 두며, 비교 분류와 자동 편집을 고르는 조건은 바꾸지 않았습니다.

## 바뀐 것: NAS 배포 다시 받기
- 「NAS에 올라온 배포」에서 이미 가져온 항목과 이 기기에서 올린 항목에도 「다시 받기」가 나옵니다.
- 직접 누른 항목은 같은 판이 설치돼 있어도 가져올지 다시 묻습니다. 자동 확인·「지금 새 배포 확인」·아직 안 물어본 항목의 「지금 물어보기」는 그대로입니다.
- 창을 닫으면 결정하지 않은 상태로 남고, 「아니오」를 고르면 「이 기기에서 안 받음」으로 남습니다. 이미 설치된 내용은 지우지 않습니다.
- 같은 파일의 모듈은 기존 id를 재사용하므로 중복으로 추가하지 않습니다.

## 확인 범위
- 단위 시험, 실제 Asset Maid 원작·MGE-C 0.2·0.3 코드로 병합 결과를 읽는 격리 시험, 조립본 브라우저 흐름 시험(격리 서버·버린 데이터, NAS·모델 요청은 가짜 응답)으로 확인했습니다. 흐름 시험: ver10에서 카드 업데이트로 Asset Maid가 「ASSET_MAID_CHARX_INVALID_CONTENT … asset:54」로 열리지 않던 캐릭터가, ver11의 「다시 받기」 → 업데이트 화면 → 「업데이트」 뒤 정상으로 열렸고(그림 기록 272개 복구), 직접 고른 레퍼런스 327개는 같은 그림 그대로였습니다.
- 휴대폰·태블릿 실기기에서의 확인은 아직 하지 않았습니다.
- 런타임 지문은 바뀌지 않습니다(ver10과 같은 `33b30c76…`). NAS 앱 코드 업데이트로 받습니다.
- 앱에서 지운 캐릭터가 Asset Maid 목록에 남는 문제는 이번에는 조사만 했습니다(플러그인 쪽 수정이 필요해 이번 판에 넣지 않음). 목록·저장소 정리 동작은 바꾸지 않았습니다.
