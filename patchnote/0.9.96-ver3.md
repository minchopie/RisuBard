# 0.9.96-ver3

## [BardWiki] 서브모델 지시문을 턴이 바뀌어도 캐시되는 자리로 옮김

- 대상: 원작 안정판 v0.9.96 `97ea0351120b2a6decba8985e6c8c3cef6517ddf`. 0.9.96-ver2에서 `bardwiki-cache-prefix` 모듈만 바꿨다.
- confirmedMessages를 싣는 위키 기록(`bardwiki-analysis`)과 정본 갱신(`bardwiki-canonical-update`) 요청은 이제 시스템 메시지 끝에 두 작업의 고정 지시문(`<bardwiki_task name="memory-writer">`, `<bardwiki_task name="canonical-update">`)을 함께 싣는다. 이 묶음은 같은 채팅·같은 설정이면 모든 턴, 모든 호출에서 바이트까지 같다. 사용자 메시지는 그대로 `<confirmedMessages>`로 시작하고, `<request_instructions>`에는 이번 작업 이름 한 줄과 호출마다 달라지는 조각(로어 참고 안내, 과거 턴 재분석, 이야기 아크, 재요청 안내, 마크다운 재시도, 프롬프트 스키마)만 남는다.
- 지시문 문구는 고치지 않고 자리만 옮겼다. 위키 기록 재요청은 예전처럼 마지막 문장을 교체한다는 한 줄을 붙여 같은 뜻을 유지한다.
- 고정 묶음을 넣으면 요청이 커지므로, 예전 배치에서 남기던 자료를 하나도 빼지 않고 'AI 분석 토큰 상한' 안에 들어갈 때만 새 배치를 쓴다. 들어가지 않으면 그 요청은 0.9.96-ver2와 같은 배치로 보낸다. 정본 갱신 묶음 나누기와 호출 수·순서는 바뀌지 않는다.
- 리부트·일괄 분석 요청과 confirmedMessages가 없는 요청(정리·기준 합성·v1/v2 분석 등)은 예전 그대로다.
- 측정(기본 프리셋·한국어, o200k): 고정 묶음 44,051자 / 8,256토큰(기록 5,077 + 정본 3,150). 턴 사이에 같은 앞부분 130 → 8,442토큰. 같은 턴 안에서는 시스템+원문 증거가 예전처럼 공유된다(130+증거 → 8,442+증거). 대신 요청마다 다른 작업의 지시문이 함께 실려 기록 요청은 약 +3,270, 정본 요청은 약 +5,190토큰 커진다(캐시 적중 시 할인 대상). v10 프리셋: 묶음 43,199자 / 8,074토큰.
- 실제 모델 응답 품질과 공급자 캐시 적중은 아직 확인하지 않았다(빌드·검사만).

## [BardWiki] 서브모델 증거에서 숨김 기록(HTML 주석)을 뺌

- 카드가 응답마다 붙이는 숨김 기록(MGE 카드의 `<!--MGE_STATE … MGE_STATE-->` 등 HTML 주석)은 카드의 editprocess 정규식이 본 요청에서 지우므로 본모델은 읽지 않는다. 그런데 위키 기록·정본 갱신 요청의 증거(`confirmedMessages`)와 최근 맥락(위키 검색어·이름 찾기에 쓰임)에는 저장된 원문이 그대로 들어가 이 기록이 서브 요청의 절반 이상을 차지했다.
- 이제 `memoryAnalysisClient.ts`의 분석 입구(`confirm`, `schedule`)에서 증거 메시지와 최근 맥락 메시지의 HTML 주석(`<!--`부터 `-->`까지, 닫히지 않으면 끝까지, 바로 앞 줄바꿈 1개 포함)을 지운 사본을 서브 분석에 넘긴다. 일반 턴, 과거 턴 재분석, 추가 분석, 리부트·일괄 분석이 모두 이 입구를 지나므로 한 번씩만 적용된다.
- 카드 정규식을 그대로 돌리는 방식(processScript editprocess)은 CBS·플러그인 처리기·현재 열린 채팅에 따라 결과가 달라질 수 있어 쓰지 않았다. 대신 글자만 보고 정하는 순수 함수라 한 턴의 모든 서브 요청과 재시도에서 증거가 바이트까지 같다.
- 바뀌지 않는 것: 저장된 메시지, 메시지 ID·역할·순서, 확인 표시, 카드, 본모델 요청, 로어북 활성화(원문 그대로 검사), 첫 메시지 증거(이미 editprocess를 거침), 0.9.96-ver3 앞 절의 요청 배치, 호출 수·순서. 주석이 없는 메시지는 그대로 보낸다. 사용자 직접 위키 명령의 현재 메시지 자료는 이번에 바꾸지 않았다.
- 측정(o200k): 실제 채팅 내보내기(2026-10-09, 기록 2건)의 마지막 턴 증거 블록 3,802자 / 2,497토큰 → 1,581자 / 1,083토큰. 카드 editprocess 정규식 2개를 적용한 결과와 바이트까지 같다. 최근 판 카드의 실제 요청 기록(응답 21,785자 중 기록 약 20,600자)에서는 카드 정규식 기준으로 증거 블록이 14,295 → 990토큰으로 줄어드는 것으로 측정됐다(이 판에서 다시 재지는 않음).
- 실제 모델 응답 품질과 기기 적용은 아직 확인하지 않았다(빌드·검사만).
