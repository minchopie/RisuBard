# 0.9.96-ver5

- 대상: 원작 안정판 v0.9.96 `97ea0351120b2a6decba8985e6c8c3cef6517ddf`. 0.9.96-ver4 위에 세 가지를 바꿨다(앱 코드만).

## 바뀐 것: 「화면 설정」의 값은 기기마다 따로 둡니다(동기화하지 않음)
휴대폰·태블릿·PC는 화면 크기가 달라서, 설정의 「화면」 페이지에 있는 값은 이제 NAS 동기화로 주고받지 않습니다.
- 테마 탭: 테마 프리셋(목록과 고른 것), 테마, 사용자 HTML, 사용자 CSS, 앱 스킨 선택, 색 구성표, 글자 색과 사용자 글자 색, 글꼴
- 크기와 속도 탭: 줄 간격, 입력창 글자 크기, 메모리 한도 선 두께(나머지 크기·속도 값은 원래부터 기기별)
- 기타 탭: Realm 숨기기, 아이콘 둥글게, 사용자 배경, 추가 에셋 미리보기, 메모리 한도 표시, 말풍선 배경·테두리·둥글기·글자 테두리, 따옴표(따옴표 그대로 두기, 인용 꾸밈, 사용자 따옴표와 그 글자), API 키 숨기기, 메뉴 사이드바, 베타 모바일 화면, 채팅 스티커, 태그 자동완성(설정과 단축키)
- 앱 스킨 목록(스킨 자료 자체: 추가·삭제·가져오기)은 이전처럼 동기화됩니다. 「화면」 페이지 밖의 설정도 이전처럼 동기화됩니다.
- 각 기기의 지금 화면 설정은 그대로 남습니다. 이 판으로 올린 기기는 자기 화면 설정을 NAS에 올리지 않고, 다른 기기의 화면 설정을 받아 적용하지도 않습니다.
- 이미 걸려 있던 화면 설정 충돌·확인 필요 항목은 이 판에서 사라집니다(NAS 기록은 지우지 않고 그대로 둡니다).
- 아직 이전 판인 기기끼리는 이전처럼 화면 설정을 주고받습니다. 이 판으로 올린 기기가 메모리 설정을 바꿔도 이전 판 기기의 메모리 한도 표시·선 두께는 바뀌지 않습니다. 모든 기기를 이 판 이상으로 올리면 화면 설정은 완전히 기기별이 됩니다.
- 이전 판에서 화면 설정을 바꾼 직후 NAS에 아직 올리지 못한 채 이 판으로 올리면, 그 기록 하나는 업데이트 뒤 NAS로 올라가 아직 이전 판인 기기의 화면 설정을 한 번 바꿀 수 있습니다(사용자 결정 A: 그대로 둠). 모든 기기를 이 판으로 올리면 생기지 않습니다.

## 고친 것: BardWiki 문서 정리(정본 정리) 요청이 Gemini에서 400으로 거절되던 것
- Google AI Studio(OpenRouter 경유 포함)는 문서 정리 요청의 응답 형식(JSON 스키마)에 붙은 큰 개수 제한(`maxItems`: 항목 128개, 처리 기록 512개)을 받지 않고 `INVALID_ARGUMENT`로 거절했습니다. 그래서 매번 한 번 거절된 뒤 스키마를 글로 적어 다시 보내는 길로 돌아갔습니다.
- 이 두 제한을 스키마에서 뺐습니다. 섹션 수 제한(인물 문서 4개)은 그대로입니다. 개수 상한은 응답을 받은 뒤 원래 적용 코드가 지킵니다(새 항목은 옛 항목이 가리킨 것만 쓰고, 처리 기록은 옛 항목마다 하나만 봄).
- 같은 BardWiki 계열의 다른 요청(턴마다 정본 갱신 등)은 이번에 바꾸지 않았습니다.

## 고친 것: NAS 배포 받기가 아무 말 없이 끝나던 것
- 설정의 「캐릭터·페르소나 배포」에서 버튼을 눌렀는데 확인·받기를 하지 못하면, 그 까닭을 패널에 적습니다(앞선 확인이 아직 진행 중, 동기화 중, 답변 생성 중, 다른 알림 창, 가져오기 복구 남음, 위키 리부트 작업이 남은 채팅 이름, 목록 읽기 실패 등). 앱을 켤 때의 자동 확인은 지금처럼 조용히 넘어갑니다.
- 페르소나·프리셋·플러그인은 지금 가져올 수 없는 상태이면 묻기 전에 멈추고 까닭을 알려 줍니다(전에는 「네」를 누르고 파일을 다 받은 뒤 말없이 멈췄습니다).
- 「지금 물어보기」·「다시 받기」를 누르면 누른 그 항목부터 묻습니다.
- 받는 동안 패널에 「(크기) NAS에서 받는 중… 몇 분 몇 초 지남」이 보이고, 받기 시작할 때 화면 아래 알림이 뜹니다(다른 화면에서도).
- 배포 목록 읽기가 2분 안에 끝나지 않으면 멈추고 까닭을 적습니다. 파일 받기에는 시간 제한을 두지 않았습니다(느린 정상 받기를 끊지 않음).
- NAS 연결이 끊겨도(socket hang up 등) 새 바이트가 계속 들어오는 동안은 이어받기를 계속합니다(전에는 끊김 5번이면 포기). 끊긴 채 진행이 없는 일이 5번 이어지면 포기하고, 그때 오류 창에 다시 받는 방법을 적습니다.

## 고친 것: 집 Wi-Fi인데 NAS 바깥 주소로 붙던 것
- 앱은 지금 붙은 Wi-Fi 이름이 「집 Wi-Fi」 목록(기기마다 따로 저장)에 있으면 집 주소(내부 주소), 아니면 바깥 주소를 씁니다. 집 안에서 바깥 주소로 받으면 큰 파일이 끊기거나(socket hang up) 몹시 느립니다.
- 이제 집 Wi-Fi로 확정하지 못할 때(Wi-Fi 이름을 못 읽음, 목록에 없는 이름, 기기의 연결 보고가 오래됨·없음)는 바깥 주소로 가기 전에 집 주소에 짧게(최대 4초, 계정 정보 없이) 닿는지 확인하고, 닿으면 집 주소를 씁니다. 결과는 1분 동안 기억합니다. 유선 PC가 원래 쓰던 확인 방식과 같습니다.
- 목록에 있는 집 Wi-Fi면 지금처럼 바로 집 주소, 모바일 데이터·연결 없음이면 지금처럼 확인 없이 바로 바깥 주소입니다(휴대폰 동작은 그대로).
- 설정 > 전송의 NAS 경로 표시에 무엇으로 정했는지가 보입니다(예: 「등록 안 된 Wi-Fi 이름 · 내부 주소 응답」). 「지금 Wi-Fi를 집으로 등록」은 그대로 쓰면 됩니다(등록하면 바로 집 주소).
- 앱 코드만 바뀌었습니다(앱 다시 설치 불필요).

- 실제 기기 적용은 아직 확인하지 않았다(빌드·검사만).
