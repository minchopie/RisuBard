# RisuBard v0.8.14

v0.8.4~v0.8.13에 걸쳐 추가·개선한 기능을 v0.8.13의 동작 기준으로 모아 정리했습니다. 버전별 변경을 하나씩 따라가지 않아도, 지금의 리스바드에서 무엇을 할 수 있는지 확인할 수 있는 통합 패치노트입니다.

이번 정리의 핵심은 **선택형 첫 메시지 제작, 프리셋·모듈·플러그인 정리, CBS 편집 지원**, 그리고 **장기 대화를 위한 BardWiki와 세이브/로드 개선**입니다.

## 1. RisuAI·포켓리스 사용자가 주목할 확장 신기능

기존 캐릭터·로어북·모듈·프롬프트 프리셋을 활용하면서, 제작과 관리에 드는 수고를 줄이는 기능을 확장했습니다.

### 퍼스트 메시지 스튜디오 — 선택형 도입부를 만드는 편집기

캐릭터의 첫 메시지를 여러 단계의 선택 화면으로 만들 수 있습니다. 기본 화면과 선택지는 편집기에서 구성하고, 세밀한 꾸미기가 필요할 때는 사용자 CSS와 추가 HTML을 사용할 수 있습니다.

- **화면과 선택지 제작**: 화면·선택지 추가, 삭제, 순서 변경, 다음 화면 연결, 직접 입력과 완료 조건을 설정합니다. 등록한 변수의 값 목록으로 선택지를 바로 만들 수도 있습니다.
- **선택에 따라 달라지는 시작**: 선택 결과를 채팅 변수에 저장하고, 변수 조건에 맞는 시나리오로 연결합니다. 선택지마다 화자·설명·삽화를 붙일 수 있습니다.
- **외형 편집**: 강조색·배경·글자색, 선택지 열 수와 모서리 형태를 조정합니다. 추가 HTML에서는 `{{variable_name}}`으로 변수를 표시할 수 있으며, 실행 스크립트와 위험한 이벤트 속성은 제거합니다.
- **공유와 재편집**: 프로젝트를 내보내고 다시 불러올 수 있습니다. 첫 메시지와 선택 동작을 일반 Risu의 CBS·트리거 형식으로 변환해 카드로 공유하고, RisuBard에서는 카드에 보존된 원본 프로젝트를 다시 열어 편집할 수 있습니다.
- **다국어 제작**: 다국어 문구 편집과 UI 문구 자동번역을 지원합니다. 앱 언어를 기본으로 사용하며, 기존 카드에 `cv_lang`이 지정되어 있으면 이를 우선합니다.
- **편집 흐름 개선**: 변수 이름을 바꾸면 연결된 선택지·입력 대상도 함께 갱신합니다. 미리보기에서 다른 화면을 편집해도 진행 단계와 입력값을 가능한 범위에서 유지하고, 현재 화면을 삭제하면 시작 화면으로 돌아갑니다. 내비게이션을 숨긴 스킨에서도 미리보기를 처음부터 시험할 수 있습니다.
- **문구·설정 편집 보완**: 번역 문구를 지웠을 때 다른 언어의 문구가 다시 채워지는 문제를 수정하고, 어느 탭에서든 프로젝트 설정을 바로 열 수 있게 했습니다.

퍼스트 메시지 스튜디오는 **베타 기능**입니다. 주요 제작·공유 기능을 사용할 수 있으며, 사용성과 호환성은 계속 다듬고 있습니다.

### 프리셋·모듈·플러그인 폴더 정리

항목이 많아져도 별도 관리자 창을 오갈 필요 없이, 평소 사용하는 목록 안에서 정리하고 바로 사용할 수 있습니다.

- 폴더 생성·이름 변경·삭제, 전체·미분류 보기, 검색과 폴더별 항목 수 표시를 지원합니다.
- 다중 선택과 일괄 이동, 드래그 이동, 폴더·항목의 순서 변경을 지원합니다.
- 폴더로 좁혀 본 상태에서도 프리셋 선택·편집·복제·내보내기, 모듈 활성화·페르소나 할당, 플러그인 업데이트·권한·인자 편집 등 기존 동작을 그대로 사용할 수 있습니다.
- 폴더를 지워도 안의 항목은 삭제되지 않고 미분류로 돌아갑니다. 정리 작업은 현재 활성 프리셋이나 모듈·플러그인의 실행 상태를 바꾸지 않습니다.
- 기존 데이터 형식은 유지하며, 구버전 데이터의 정리 정보와 페르소나 ID를 보정합니다.

### 페르소나별 모듈과 필요한 로어북만 사용하는 빌더

- **페르소나별 모듈 할당**: 사용할 페르소나를 검색해 모듈을 연결할 수 있습니다. 현재 활성 페르소나에 할당한 모듈이 기존 전역·채팅·캐릭터 모듈에 더해져, 페르소나마다 다른 보조 규칙을 적용할 수 있습니다.
- **페르소나 빌더의 선택적 로어북 검색**: 캐릭터 로어북 전체를 넣는 대신, 매 생성 요청의 사용자 입력과 현재 초안에 맞는 항목만 찾아 넣습니다. 수정한 내용은 다음 요청부터 반영됩니다.
- 채팅과 같은 검색 엔진으로 보조 키워드·단어 매칭·상시 활성·재귀 검색·토큰 예산을 적용합니다. 실제 채팅 기록과 채팅 전용 로어북은 검색하지 않으며, 채팅의 로어북 활성 상태도 바꾸지 않습니다. 별도로 선택한 모듈 로어북의 주입 방식은 유지합니다.
- 페르소나 전환이나 모듈 내용 교체 후 이전 모듈 캐시가 남는 문제를 보완했습니다.

### CBS 조건 보기와 변수 사이드바

복잡하게 중첩된 CBS 구문을 읽고, 관련 변수값을 확인·수정하기 쉬워졌습니다.

- **조건과 본문 분리**: 로어북·팝업 편집기에서 `if`·`or`·`equal` 등의 조건식과 본문을 나누어 표시합니다. 조건을 실행해 결과만 보여 주는 방식이 아니라, 모든 분기를 펼쳐 살펴보는 편집용 보기입니다.
- **중첩 구조 강조**: 비교식과 `OR`·`AND`·`NOT`을 구분하고, 중첩 조건을 테두리로 묶습니다. 좁은 화면에서는 줄바꿈합니다.
- **원문 보존**: 조건 보기에서 본문을 편집해도 CBS 구문은 유지됩니다. 조건식 자체는 `원문` 보기에서 수정합니다.
- **변수 자동 수집**: 원문에 고정된 이름으로 쓰인 변수와 비교·대입 값 후보를 모읍니다. 검색·전체 변수 보기·후보 외 값 직접 입력을 지원합니다.
- **저장 대상 선택**: 캐릭터·채팅 정보가 있으면 현재 채팅 값 또는 캐릭터 기본값을 골라 수정합니다. 체크 버튼이나 Enter로 적용하며, 조건식 원문은 바꾸지 않습니다.
- **독립 사이드바**: 변수 영역은 본문과 따로 스크롤하고 검색·저장 대상 선택은 상단에 고정합니다. 접었다 펼쳐도 입력 중인 값을 유지하며, 좁은 영역에서는 `변수` 버튼으로 열 수 있습니다.

### LLM 번역 캐시 관리자

LLM 번역 사용 시 언어 설정에서 번역 캐시를 직접 관리할 수 있습니다.

- 검색, 100개 단위 탐색, 번역값 편집·복사, 개별·전체 삭제, 가져오기·내보내기를 지원합니다.
- 번역 요청 도중 캐시를 수정하거나 삭제해도, 늦게 끝난 요청이 이전 값을 되살리지 않도록 했습니다.
- 여러 창이나 원격 접속에서 동시에 수정할 때 항목별 충돌을 감지합니다. 일부 삭제가 실패해도 실제 저장 상태와 메모리 캐시를 다시 맞춥니다.

## 2. 리스바드 코어 기능 개선

### BardWiki 리부트 — 기존 대화로 위키 다시 만들기

현재 대화의 첫 확정 AI 응답부터 최신 응답까지, 기록을 순서대로 분석해 위키를 다시 만드는 `위키 리부트`를 추가했습니다.

- **1턴·2턴 처리 선택**: 시작 전에 기존 위키를 다시 만들지 확인하고 처리 단위를 선택합니다. 2턴 방식은 두 응답의 의미 분석을 한 요청으로 묶어 반복 프롬프트와 분석 호출 수를 줄이되, 사건 문서와 출처는 턴별로 보존합니다. 정본 갱신에는 별도 호출이 필요할 수 있으며, 설정한 분석 예산에 맞춰 나누어 처리합니다.
- **완성 전까지 기존 위키 보호**: 별도의 임시 위키에 결과를 쌓고, 전체 작업이 끝난 뒤에만 기존 위키를 교체합니다. 도중 실패나 취소로 기존 정본이 덮어써지지 않습니다.
- **안전 정지와 이어하기**: 현재 배치를 마친 뒤 정지할 수 있고, 앱을 종료했다 다시 열어도 이어서 진행할 수 있습니다. 강제 종료된 경우 완료 기록을 확인하고 불완전한 쓰기를 되돌린 뒤 재시도합니다.
- **정지와 취소 구분**: 정지는 이어하기 위한 진행 상태를 남깁니다. 정지하거나 실패한 작업을 명시적으로 취소하면 임시 위키를 폐기하고 기존 위키를 유지합니다.
- **진행 상태 표시**: 툴바에서 정지·계속·정지 대기·마무리 상태를 확인합니다. 리부트뿐 아니라 자동 분석·추가 분석·직접 위키 명령 중에도 입력창의 BardWiki 버튼이 회전합니다.
- **작업 중 기준 시점 보호**: 리부트가 끝나거나 취소되기 전까지 새 응답 생성·재생성·이어쓰기와 위키 직접 편집을 잠급니다.

### 긴 대화를 막던 분석·설정의 고정 상한 해제

긴 대화에서 `Analysis context exceeds 128000 characters` 오류로 분석이 중단되던 문제를 수정하고, 다음 앱 내부 고정 상한을 해제했습니다.

- 요청 내용을 추리기 전에 적용하던 원문 64,000자·128,000자 제한
- 분석 대상 메시지 12개·참고 대화 100개 제한
- 분석·검색 토큰 설정의 32,768토큰 상한과 최근 메시지 설정의 100개 상한
- 추가 검색 4회·정본 갱신 대상 8개 상한
- 추가 분석·대량 메시지 삭제에 남아 있던 개수 제한

**기본값은 그대로이며, 필요한 설정값을 사용자가 직접 늘릴 수 있습니다.** 입력은 설정한 요청 예산에 맞춰 처리하고, 모델 자체의 입력·출력 한도와 데이터 무결성 검증은 유지합니다. 모든 입력을 무제한으로 전송한다는 뜻은 아닙니다.

큰 설정값이 저장·통신 과정에서 거부되거나 재실행 후 초기화되는 문제도 수정했습니다. 대상이 많아도 변경 내역과 경고를 기록하고, 저장 후 되돌릴 때 문서가 누락되지 않도록 보완했습니다. 분석 토큰 도움말도 실제 동작에 맞췄습니다.

### 주요 인물 기록과 과거 사건 검색 개선

- **주요 인물의 첫 등록 개선**: 상태 변화가 없어도 확정된 대화에서 지속적인 역할·관계·능력·목표·지식이 드러난 주요 인물은 새 문서 후보로 포함합니다. 지휘자·동료·대립자 등 참여자를 개별 점검하며, 다른 문서에 이름이 있다는 이유로 인물 문서를 생략하지 않습니다.
- **중요한 기록 우선**: 주요 대상의 최초 등록과 중요한 지속 변화를 사소한 행적 갱신보다 우선합니다. 이름만 언급된 대상, 별칭 중복, 반복 갱신과 근거 없는 원작 설정 등록은 계속 억제합니다.
- **간접 단서 탐색 개선**: 질문과 기록의 표현이 정확히 일치하지 않아도 한국어 복합어와 인물·장소·물건·행동의 관계를 활용해 관련 사건의 근거를 찾도록 개선했습니다.
- **문서 비대화 완화**: 캐릭터의 연대기에 사건 근거는 유지하면서, `관련 문서`에 모든 사건 링크가 반복 나열되는 현상을 줄였습니다.
- **정본 갱신 묶음 처리**: 여러 문서의 갱신을 가능한 경우 한 번에 처리하고, 설정한 분석 토큰 예산을 넘을 것으로 예상될 때 나눕니다. 나누어 처리해도 원래 사건 근거를 유지합니다.

### Wiki Prompt Preset과 퍼즐·단서 추적

- 새 기본 프리셋에 `퍼즐·단서 추적기`를 추가했습니다. 문양·순서·좌우 배치·짝·빈칸·장치 위치·시도 결과를 기록하고, 관찰한 사실과 추론한 규칙·정답을 구분합니다.
- `퍼즐·관계 추론` 응답 보조 블록은 관련 위키 문서가 실제로 회수된 답변에서 단서 관계를 검토하도록 돕고, 추론을 확정 사실처럼 단정하지 않도록 제한합니다.
- 편집기를 `위키 작성 블록`과 `응답 보조 블록`으로 나누어, 응답 보조 지침이 위키 분석·작성 규칙과 섞이지 않게 했습니다.
- 잠긴 핵심 계약과 동적 주입 블록의 내용을 읽고 복사할 수 있으며, 입력란 높이를 조절할 수 있습니다. 사용자 블록의 `프롬프팅 도움말`에서는 분석 항목의 의미, 근거·추론의 경계와 퍼즐 작성 예시를 확인할 수 있습니다.
- **기존 사용자 프리셋은 자동으로 덮어쓰지 않습니다.** 새 퍼즐 블록은 새로 생성되는 기본 프리셋에 포함되며, 기존 프리셋에서는 같은 목적의 사용자 블록을 직접 추가할 수 있습니다.

### 세이브/로드 — 이야기는 되돌리고 프롬프트 설정은 유지

세이브를 불러오면 새 채팅을 만드는 대신 **현재 채팅을 저장 시점으로 되돌립니다.** 저장하지 않은 대화가 사라질 때는 먼저 확인합니다.

- **슬롯을 골라 저장**: 불러오기와 같은 슬롯 목록에서 새로 저장하거나 기존 슬롯을 덮어쓸 수 있습니다. 덮어쓰기는 확인 후 실행하고 슬롯 이름은 유지한 채 대화·위키·변수·저장 시각·턴 수·미리보기를 갱신합니다.
- **저장 실패 보호**: 중복 저장을 막고 새 저장본이 완성된 뒤 기존 슬롯을 교체합니다. 작성이나 교체가 실패하면 기존 슬롯을 보존합니다.
- **저장·불러오기 전환**: 창을 닫지 않고 두 모드를 오갈 수 있으며, 선택한 슬롯과 미리보기를 유지합니다. 모드 전환만으로 작업을 실행하지 않고, 작업 중에는 전환을 잠급니다.
- **복원하는 것**: 대화 기록, Memory Wiki, 스토리 진행 변수와 프롬프트 외 로컬 변수, 페르소나·모델 바인딩입니다.
- **현재 설정을 유지하는 것**: 작가·문체·언어·서술 시점·답변 길이 같은 프롬프트 옵션, 채팅별 토글 고정, 프롬프트 프리셋 연결과 파라미터 적용 설정입니다. 예를 들어 답변 길이나 문체를 바꾼 뒤 옛 세이브를 불러와도 지금의 프롬프트 설정은 유지됩니다.
- **기존 세이브에도 적용**: 옛 세이브에 들어 있는 프롬프트 설정은 무시합니다. 현재의 빈 값·비활성화·고정 해제 상태도 유지하며, 파일 변환이나 재저장은 필요 없습니다.

세이브/로드 바로가기는 하나의 플로팅 블록으로 정리했습니다. 빈 영역을 드래그해 위치를 옮기면 채팅 입력창 기준 상대 위치가 저장되고, 보조 패널을 열거나 채팅 폭이 달라져도 화면 안쪽에 배치됩니다. 닫기 전 확인 창을 표시하며, 숨긴 버튼은 `BardWiki / 공통 옵션`에서 다시 켤 수 있습니다.

### 채팅별 설정과 BardWiki 모델 요청 안정화

- 전역 토글 값을 채팅별로 고정할 수 있습니다. 고정한 페르소나·프롬프트도 파란색으로 표시해 전역 설정과 구분하고, 이미지가 없는 페르소나의 검은 핀 타일은 제거했습니다.
- 실제 요청과 화면에 표시하는 모델 이름이 같은 모델 모드·바인딩 규칙을 따르도록 수정했습니다.
- BardWiki 자동 분석·정본 갱신·리부트는 현재 화면에 열린 채팅이 아니라 **요청이 속한 채팅의 모델 설정**을 사용합니다. 백그라운드 작업 중 다른 채팅으로 이동해도 원래 설정을 유지하며, 직접 지정한 비채팅 작업 바인딩은 우선합니다.
- 선택한 보조 모델 프리셋의 추론 강도를 그대로 사용합니다. 내부 구조화 요청이 추론 강도를 `minimal`로 강제해 설정을 덮어쓰거나 일부 Gemini 모델에서 오류를 내던 문제를 수정했습니다.
- Ollama Cloud의 GLM 등 보조 모델 요청에 JSON 모드와 전체 응답 스키마를 함께 전달해, 필수 분석 항목 누락으로 위키 갱신이 실패하는 문제를 보완했습니다.
- 서버측 요청 기능 사용 시 내부 분석 JSON이 다음 턴의 채팅 메시지로 노출될 수 있던 문제를 수정했습니다.

## 3. 그 밖의 사용성·호환성·안정성 개선

### 로어북 편집 공간과 창 조작

- 이름·기본 키·보조 키·순서를 한 줄에 배치하고, 키 입력칸은 버튼으로 전체 너비의 여러 줄 영역으로 펼칠 수 있게 했습니다. 펼친 입력칸의 높이도 조절할 수 있습니다.
- 목록·설정·변수 영역 사이의 폭과 창 가장자리·모서리의 크기를 조절할 수 있습니다. 최소 폭을 낮췄으며, 창 크기를 바꿀 때 중앙 배치를 유지합니다.
- 조절 핸들은 드래그·방향키로 조작하고, 더블클릭·Home으로 초기화합니다.
- 확인·선택·로딩 창과 BardWiki 도움말이 메모리 도크나 생성 통계 창 뒤에 가리지 않도록 표시 순서를 정리했습니다. 드롭다운·선택 목록·토스트도 확인 작업을 가리지 않도록 조정했습니다.

### 모델과 플러그인 지원

- Gemini 3.7 Flash와 NovelAI Diffusion V5 Curated를 추가하고, OpenAI 추론 설정·모델 표시·요청 추적을 개선했습니다.
- 플러그인 업데이트는 오래된 브라우저 캐시를 우회하며, 브라우저 요청이 실패하면 서버 경로로 자동 재시도합니다. 실제 설치 데이터 반영과 저장 완료를 확인한 뒤 결과를 표시합니다.
- 자체 생성 정보 창을 제공하는 플러그인은 제공자 등록 시 `overrideRequestStatus: true`로 RisuBard의 고급 요청 상태 창을 끌 수 있습니다. 명시하지 않은 플러그인은 기존 창을 사용하며, 구형 `hostRequestStatus` 옵션도 호환을 유지합니다. 제작자 문서에 적용 범위와 양방향 예제를 추가했습니다.
- V3 플러그인에 화면 절전 방지, 인레이 접근 권한과 채팅 출력 완료 이벤트를 추가했습니다.

### 가져오기·내보내기와 대용량 데이터

- 캐릭터 카드와 모듈을 내보내고 다시 가져올 때 확장 설정이 더 정확히 유지되도록 개선했습니다.
- 대용량 로컬 백업을 복원할 때 전체 파일을 서버 메모리에 올리지 않고 디스크 기반으로 스트리밍해 메모리 급증과 서버 종료 문제를 완화했습니다.
- 서버에 저장한 백업의 복원 후처리가 길어져도 연결이 끊기지 않도록 진행 응답과 연결 유지 처리를 보강했습니다.
- 일반 저장소 요청에 인증 API 요청 제한이 중복 적용되어 발생하던 `getItem` 오류와 429 응답 문제를 수정했습니다.
- 대형 세이브, Lua 스크립트 메모리, 자산 정리, CSS 렌더링, 파일 선택과 기존 데이터 보정을 개선했습니다.

### RisuRealm·홈 화면·테마

- 메인 화면에서 RisuRealm 브라우저를 바로 열 수 있게 하고 Related Links 영역을 제거했습니다. 카드·상세·검색 화면에 테마 토큰과 한국어 UI를 적용했습니다.
- 캐릭터 검색은 Enter로 실행할 수 있습니다. 태그 입력창에서는 전체 태그 목록, 공백으로 구분한 태그 자동완성, 방향키·Tab·Enter 선택과 중복 제외를 지원합니다.
- 캐릭터 설명의 URL을 링크로 표시하고, 설명을 드래그해 선택할 때 상세 창이 닫히지 않도록 수정했습니다. 다운로드 버튼과 설명 표시도 정리했습니다.
- 홈 화면 상단에 RisuBard 이름과 현재 앱 버전을 표시합니다.
- 색상 테마는 실제 팔레트를 보면서 선택할 수 있습니다.
