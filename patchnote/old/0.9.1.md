# RisuBard v0.9.1

v0.9.0 이후의 변경을 모았습니다. 이번 버전은 **여러 챗을 하나로 이어 붙이는 기능**, **챗 목록과 사이드바 크기 조절**, **BardWiki 작성 언어 선택과 사용성 개선**을 중심으로, **응답·위키 생성의 안정성과 모델 호환성**을 보완합니다.

## 챗 병합 — 나뉜 이야기를 하나의 챗으로

- 같은 캐릭터 안의 챗을 두 개 이상 골라 **새 합본 챗**으로 만들 수 있습니다. 원본 챗과 원본의 순서는 바뀌지 않습니다.
- 병합 창에서 챗을 검색하고, 각 챗의 처음·마지막 메시지와 메시지 수를 확인한 뒤 위·아래 화살표로 연결 순서를 정합니다. 합본 이름도 직접 입력할 수 있습니다.
- 메시지는 선택한 챗 순서대로 이어 붙입니다. 첫 메시지는 첫 번째 챗을 기준으로, 챗 설정·변수 등은 마지막 챗을 기준으로 이어받으며, 북마크와 북마크 이름도 보존합니다.
- 복제·분기한 챗처럼 같은 메시지 ID가 발견되면 중복 가능성을 알리고 확인을 받습니다. **중복 내용을 임의로 삭제하거나 서로 다른 분기를 자동으로 정리하지 않습니다.**
- 각 챗의 메시지 제외 설정이 앞서 이어 붙인 다른 챗까지 제외하지 않도록 처리했습니다. 합본에는 새 메시지 ID를 부여하고, 기존 위키 분석 확정·되돌리기 기록과 메모리 캐시는 이어받지 않습니다.
- 합본 저장이 완료된 뒤에만 새 챗으로 이동합니다. 저장 실패 시 원본 챗을 유지하며, 응답 생성이나 위키 작업 중에는 병합을 제한합니다.

**위키 문서 자체를 병합하는 기능은 아닙니다.** 합본을 만든 뒤 BardWiki에서 **위키 리부트**를 실행하면 이어 붙인 대화를 바탕으로 위키를 다시 만들 수 있습니다. 병합만으로 AI 분석이 자동 실행되지는 않습니다.

## 챗 목록과 캐릭터 사이드바

- 상단의 **현재 챗** 안내 문구를 제거하고 챗 이름만 남겼습니다.
- 챗 목록 툴바를 **새 챗 → 이름 편집 → 복제 → 병합 → 챗 분할(브랜치) → 삭제 → 새 폴더 → 더보기(…)** 순서의 한 줄로 정리했습니다.
- **다운로드·임포트·북마크**는 더보기 드롭다운으로 옮겼습니다. 기존 기능은 그대로 사용할 수 있습니다.
- 챗 목록에 독립적인 내부 스크롤바와 아래쪽 높이 조절 핸들을 추가했습니다. 펼쳤을 때의 높이는 앱 전역 설정으로 저장하며, 접었다 펼치거나 다른 캐릭터로 이동해도 같은 설정을 사용합니다.
- 캐릭터 사이드바 오른쪽에 너비 조절 핸들을 추가했습니다. 조절한 너비를 전역 설정으로 저장하고, 화면이 좁을 때는 사용할 수 있는 영역에 맞춥니다.
- 크기 조절 핸들은 드래그와 방향키를 지원합니다. 더블클릭 또는 `Home`으로 기본 크기로 되돌릴 수 있으며, 표시 설정에서 사이드바 크기 프리셋을 고르면 수동 너비 대신 해당 프리셋을 적용합니다.
- 사이드바를 좁혀도 상단 탭과 챗 목록의 툴바 버튼이 잘리지 않도록 배치를 보완했습니다.

## BardWiki 작성 언어 — 한국어·영어 선택

- **위키 작성 언어** 설정을 추가했습니다. 공통 기본값과 현재 챗별 설정에서 **한국어 / English**를 선택할 수 있으며, 현재 챗에서는 공통 설정을 그대로 따를 수도 있습니다. 기본값은 한국어입니다.
- 앱 UI·대화 언어와 별도로 사건 분석·이야기 요약·정본 문서의 작성 언어를 지정합니다. 선택한 언어는 사용자 지정 문체나 Wiki Guide 안의 언어 지시보다 우선하며, 기존 문서 제목·링크·고유명사·근거 인용은 보존하도록 합니다.
- 영어 작성용 분석 지침과 문체 지침을 추가하고, 이야기 요약·작중 행적·관련 문서·추가 분석 등의 자동 섹션 제목과 위키 목차도 언어에 맞게 처리합니다.
- **이야기** 보기에서 영어 사건 요약을 읽을 수 있게 했습니다. 인물의 행적 검색도 한국어·영어 섹션 제목과 두 단계의 제목 형식을 인식하도록 보완했습니다.
- 위키 리부트는 **시작할 때 선택한 언어를 저장**하고, 중단 후 이어 할 때도 같은 언어를 유지합니다. 기존 리부트 작업은 한국어 기준으로 이어집니다.
- 다른 언어로 작성된 기존 사건에 추가 분석을 섞어 덧붙이지 않도록 제한했습니다.

**언어 설정을 바꿔도 기존 문서 전체가 즉시 번역되지는 않습니다.** 위키 전체의 언어를 바꾸려면 원하는 언어를 선택한 뒤 **위키 리부트**를 실행하세요.

## BardWiki 화면과 사용 가이드

- 최근 분석 이후 생성·갱신된 문서의 **오른쪽에 `New` 배지**를 표시합니다. 한 번의 분석에서 순차 저장된 문서들을 함께 표시하고, 분석 사건이 없는 위키에서는 가장 최근 저장 시각의 문서를 표시합니다.
- `New` 표시는 문서의 저장 시각을 기준으로 하므로 위키를 다시 열어도 유지됩니다. 긴 문서명은 줄여 표시하되 배지는 보이도록 했습니다.
- **추가 분석**을 이름이 항상 보이는 텍스트 버튼으로 바꿨습니다. **위키 리부트와 같은 높이**로 맞추고, 기존 아이콘은 **24px로 줄여 버튼 내부 왼쪽**에 배치했습니다. 기존 마우스 오버·분석 중 애니메이션과 추가 분석 동작은 유지합니다.
- 좁은 화면에서는 위키 툴바가 줄바꿈되도록 하여 버튼 글자가 잘리지 않게 했습니다.
- 도움말 아이콘을 눈에 잘 띄는 **사용 가이드** 버튼으로 바꾸고, 가이드를 **빠른 시작 → BardWiki의 컨셉 → 핵심 설정** 순서로 개편했습니다.
- 답변 생성에 보내는 **응답 최근 메시지**와 위키 갱신에 쓰는 **분석 최근 메시지**의 차이, 메시지 수 계산, 공통값과 현재 챗 설정, 작성 언어·문체·토큰 예산을 구분해 설명했습니다. 응답 확정과 자동 분석 시점에 관한 안내도 보완했습니다.

## 위키 관리자 명령과 모델 호환성

- 위키 관리자 명령에서 정상적인 `## 제목` 형식의 문서가 불완전한 갱신으로 거부되던 문제를 수정했습니다. 기존 `# 제목` 형식도 계속 지원합니다.
- 모델 응답 앞의 `<think>`·`<Thoughts>` 사고 블록과 실제 JSON 결과를 구분하도록 개선했습니다. 사고 과정 안의 임시 JSON이나 끝나지 않은 사고 블록을 명령으로 실행하지 않고, 문서 본문에 인용된 같은 태그는 보존합니다.
- 위키 관리자 명령의 JSON이 잘렸거나 형식이 잘못되면 제한된 자동 복구를 시도합니다. 끝내 검증에 실패하면 변경을 실행하지 않고, 오류 종류에 맞는 안내를 표시합니다.
- Ollama Cloud의 구조화 응답 요청에서 지원되지 않는 `response_format` 지정을 제거하고, 프롬프트에 스키마를 전달하도록 호환성을 보완했습니다. 다른 OpenAI 호환 공급자의 기존 형식 지정은 유지합니다.

## 응답·위키 생성 안정성

- OpenAI 호환·Anthropic 연결에서 위키 요청의 **출력 토큰 한도와 온도 설정이 실제 요청에 반영되지 않던 문제**를 수정했습니다. 일반 대화의 프리셋 설정은 유지하고, 모델별 온도 제한과 토큰 필드 차이를 반영합니다. Anthropic 사고 모드의 예산이 위키 요청의 출력 한도와 충돌하면 사고 모드를 끄지 않고 예산을 조정합니다.
- 응답의 **출력 한도 도달·제공자 차단 등 종료 정보**를 검증 단계까지 전달합니다. JSON 모양이 완성돼 보여도 제공자가 잘렸다고 보고한 응답은 정상 위키 결과로 저장하지 않습니다. 빈 응답이나 사고 과정만 있는 응답도 구분합니다.
- 자동·추가 분석, 위키 관리자 명령, Markdown 초안 생성에서 형식 오류를 구체적인 안내와 함께 **한 번만 다시 요청**하도록 보완했습니다. 분석 클라이언트와 서버에서 재시도가 중첩되지 않게 했으며, 인증 오류·취소·명시적 제공자 차단을 형식 오류로 취급해 반복 요청하지 않습니다.
- 여러 정본 문서를 한꺼번에 생성하다 응답이 잘리거나 형식이 틀리면 **문서별 요청으로 나누어 복구**합니다. 요청한 문서가 하나라도 빠진 결과는 완전한 배치로 처리하지 않으며, 복구 중인 배치의 모든 초안을 검증한 뒤 저장합니다.
- 위키 요청이 일반 대화의 JSON 추출 경로나 문자 필터 설정을 물려받지 않게 분리했습니다. 사건은 저장됐지만 정본 문서 갱신이 실패한 경우에는 **변경 기록에 부분 실패 경고**를 남깁니다.
- 일반 응답의 금지 문자 필터가 재시도 상한을 건너뛰어 계속 생성하던 문제를 수정했습니다. 이미 도구를 실행했거나 스트리밍 내용을 생성한 요청은 자동으로 처음부터 재실행하지 않도록 보호합니다.
- 스트리밍 중 연결이 끊겨도 **이미 받은 마지막 부분까지 화면에 보존**합니다. 중단된 답변을 정상 완료로 처리하거나 그 답변으로 자동 위키 분석을 시작하지 않습니다.
- 스트리밍의 취소 처리와 타이머·읽기 자원 정리를 보강했습니다. 상태 표시·로그 처리 오류가 응답 전달을 끊거나 완료 처리를 두 번 실행하지 않도록 했습니다.

외부 모델의 장애나 형식 오류 자체를 없애는 것은 아닙니다. 복구 횟수는 제한하며, 검증되지 않은 결과를 억지로 저장하지 않습니다.

## 문서와 소개 자료
