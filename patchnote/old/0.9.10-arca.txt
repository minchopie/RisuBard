			<br><span style="font-size:36px;font-weight:900;line-height:1.2;letter-spacing:-2px;color:rgb(34,89,146);">RisuBard (리스바드)</span><span style="font-size:18px;letter-spacing:0;"> v0.9.10</span></div>

		<p style="margin:18px 0 8px;color:#173e69;font-size:21px;font-weight:850;line-height:1.6;">기억은 더 잘 찾고, 토큰은 덜 쓰는 BardWiki</p>

		<p style="margin:18px 0 8px;text-align:center;"><img src="assets/0.9.10-bardwiki-cost-comic.png" style="display:block;width:100%;max-width:840px;height:auto;margin:0 auto;border-radius:8px;" alt="BardWiki 기억 검색과 정본 갱신 비용 개선 2컷 만화"></p>

		<p style="margin:16px 0 0;color:#29415a;font-size:15px;line-height:1.85;">이번 연속 업데이트의 핵심은 BardWiki가 장기 기억을 <strong style="color:#173e69;font-weight:800;">찾는 비용</strong>과 정본을 <strong style="color:#173e69;font-weight:800;">고치는 비용</strong>을 함께 줄인 것입니다. 여러 핫픽스도 포함됐지만, 실제 사용감에 가장 큰 변화는 아래 두 가지입니다.</p>
	</div>

	<div style="margin:34px 0 0;padding:21px 20px;background:linear-gradient(100deg,#ddeaf8,#edf4fc);border-top:2px solid #456f9c;border-bottom:1px solid #bbccdf;">
		<h2 style="margin:0;color:#173e69;font-size:23px;font-weight:850;line-height:1.5;">1. 흔한 단어보다 사건 고유의 단서를 먼저 찾습니다</h2>
	</div>
	<div style="padding:27px 20px 18px;border-bottom:1px solid #d2deeb;">
		<h3 style="margin:0 0 15px;padding:0 0 11px;color:#1a426e;font-size:19px;font-weight:800;line-height:1.55;border-bottom:1px solid #c3d4e6;">오래된 핵심 기억이 최근의 평범한 기록에 묻히는 일을 줄였습니다</h3>

		<p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;">이전 검색은 어떤 문서에 검색어가 들어 있기만 하면 대체로 비슷한 점수를 줬습니다. 그래서 <strong style="color:#173e69;font-weight:800;">열쇠, 방, 기억</strong>처럼 여러 문서에 반복되는 말이 많으면, 오래전에 한 번 등장한 중요한 사건이 뒤로 밀릴 수 있었습니다.</p>

		<p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;">이제는 위키 전체에서 드문 이름·물건·표식에 더 높은 가중치를 줍니다. 예를 들어 <strong style="color:#173e69;font-weight:800;">붉은 방울이 달린 지하실 열쇠</strong>를 찾을 때 흔한 <strong>열쇠</strong>보다 사건에만 나온 <strong>붉은 방울</strong>을 더 중요한 단서로 취급합니다.</p>

		<ul>
			<li><p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;"><strong style="color:#173e69;font-weight:800;">오래된 사건 회수 개선</strong>: 사건 고유 단서가 있으면 최신의 일반적인 기록보다 앞서기 쉬워졌습니다.</p></li>
			<li><p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;"><strong style="color:#173e69;font-weight:800;">필요한 부분만 전달</strong>: 긴 문서 전체가 아니라 질문과 맞는 절이나 문장 주변을 모델에 보냅니다.</p></li>
			<li><p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;"><strong style="color:#173e69;font-weight:800;">추가 호출 없음</strong>: 현재 기본 검색은 별도 AI나 임베딩 호출 없이 작동하므로 검색 모델 비용이 늘지 않습니다.</p></li>
			<li><p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;"><strong style="color:#173e69;font-weight:800;">기존 위키에 즉시 적용</strong>: 새 챗이나 위키 리부트 없이 기존 BardWiki도 개선된 검색을 사용합니다.</p></li>
		</ul>

		<p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;padding:14px 16px;background:linear-gradient(110deg,#eaf2fb,#f5f9fe);border-left:3px solid #2d629d;"><strong>쉽게 말하면:</strong> 예전에는 서류 더미에서 같은 단어가 적힌 종이를 전부 뒤졌다면, 이제는 그 사건에만 남은 지문부터 찾습니다.</p>
	</div>

	<div style="margin:34px 0 0;padding:21px 20px;background:linear-gradient(100deg,#ddeaf8,#edf4fc);border-top:2px solid #456f9c;border-bottom:1px solid #bbccdf;">
		<h2 style="margin:0;color:#173e69;font-size:23px;font-weight:850;line-height:1.5;">2. 정본 전체가 아니라 바뀐 절만 다시 씁니다</h2>
	</div>
	<div style="padding:27px 20px 18px;border-bottom:1px solid #d2deeb;">
		<h3 style="margin:0 0 15px;padding:0 0 11px;color:#1a426e;font-size:19px;font-weight:800;line-height:1.55;border-bottom:1px solid #c3d4e6;">긴 캐릭터 문서일수록 절약 효과가 커집니다</h3>

		<p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;">이전에는 캐릭터·장소·설정 정본에 작은 변화가 생겨도 모델이 문서 전체를 다시 작성했습니다. 지금은 <strong style="color:#173e69;font-weight:800;">변경이 필요한 절만 생성</strong>하고, 프로그램이 그 부분만 기존 Markdown에 병합합니다.</p>

		<p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;">예를 들어 긴 캐릭터 정본에서 소지품 하나만 바뀌었다면, 전체 프로필을 새로 출력하지 않고 <strong style="color:#173e69;font-weight:800;">소지품 절만 교체</strong>합니다.</p>

		<ul>
			<li><p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;"><strong style="color:#173e69;font-weight:800;">출력 토큰 절감</strong>: 매번 정본 전체를 왕복하지 않아 긴 문서일수록 효과가 큽니다.</p></li>
			<li><p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;"><strong style="color:#173e69;font-weight:800;">원문과 서식 보존</strong>: 수정하지 않은 절은 다시 생성하거나 재직렬화하지 않고 그대로 둡니다.</p></li>
			<li><p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;"><strong style="color:#173e69;font-weight:800;">불필요한 저장 생략</strong>: 실제 변경점이 없으면 정본 저장 작업도 건너뜁니다.</p></li>
			<li><p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;"><strong style="color:#173e69;font-weight:800;">문서 손상 방지</strong>: 중복 절, 잘못된 제목 계층과 비정상적인 패치를 적용 전에 검증합니다.</p></li>
		</ul>

		<p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;padding:14px 16px;background:linear-gradient(110deg,#eaf2fb,#f5f9fe);border-left:3px solid #2d629d;"><strong>정리하면:</strong> 기억을 읽을 때는 필요한 기록만 가져오고, 기억을 고칠 때는 바뀐 절만 다시 씁니다. 입력과 출력 양쪽에서 낭비를 줄인 셈입니다.</p>
	</div>

		<h2 style="margin:0;color:#173e69;font-size:23px;font-weight:850;line-height:1.5;">3. 함께 정리된 안정성 개선</h2>
	</div>
	<div style="padding:27px 20px 30px;border-bottom:1px solid #d2deeb;">
		<p style="margin:12px 0;color:#29415a;font-size:15px;line-height:1.85;">그 밖의 패치는 핵심 흐름을 안정시키는 데 집중했습니다. 자동저장은 채팅 응답과 BardWiki 작업이 모두 끝난 뒤 실행되며, 플러그인 provider의 내부 분석 호환성을 보완했습니다. 채팅 입력창의 <strong style="color:#173e69;font-weight:800;">AUTO</strong>를 끄면 자동 위키 분석과 정본 갱신을 시작하지 않고, 실행 중인 BardWiki 작업은 위쪽 취소 버튼으로 중단할 수 있습니다.</p>
