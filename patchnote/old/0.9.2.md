# RisuBard v0.9.2

v0.9.1 이후의 변경을 모았습니다. 이번 버전은 **자동저장과 퀵세이브**, **저장 파일 화면 개편**, **BardWiki 이력 보호**, **캐릭터 정본 갱신 신뢰성 향상**, **확정된 사건 직접 편집**에 초점을 맞췄습니다.

## 자동저장과 퀵세이브

- 입력창 위의 저장 도구 모음을 새로 정리했습니다.
  - `저장`, `불러오기`, `퀵세이브`, `퀵로드`를 한곳에서 사용할 수 있습니다.
  - 도구 모음은 필요하지 않을 때 닫을 수 있으며, 기존 표시 설정도 유지됩니다.
- 채팅마다 전용 퀵세이브 슬롯이 생깁니다.
  - 첫 퀵세이브는 슬롯을 만들고, 이후 퀵세이브는 같은 슬롯을 덮어씁니다.
  - 퀵세이브가 없을 때 퀵로드를 누르면 안내 메시지를 표시합니다.
  - 저장하지 않은 현재 대화가 사라질 수 있으면 불러오기 전에 확인합니다.
- 지정한 턴 간격마다 자동저장합니다. 기본값 5턴에서는 첫 답변 뒤 저장하고 이후 6·11·16턴처럼 같은 간격으로 이어집니다.
  - 기본 간격은 5턴이며, 설정에서 1~100턴 사이로 조절할 수 있습니다.
  - 기본 보관 수는 5개이며, 설정에서 1~20개 사이로 조절할 수 있습니다.
  - 자동저장은 채팅별 순환 슬롯을 사용하고, 보관 수를 줄이면 범위를 벗어난 해당 채팅의 오래된 자동저장을 정리합니다.
  - AI 답변 생성과 BardWiki 갱신이 모두 끝난 뒤에만 저장하므로 진행 중인 작업을 끊지 않습니다.
  - 저장에 실패하면 해당 턴을 저장한 것으로 처리하지 않고 경고를 남겨 다음 기회에 다시 시도할 수 있게 했습니다.

## 저장 파일 화면 개편

- 입력창 위 저장 도구 모음을 입력창과 같은 둥근 표면과 색상 체계로 다듬고, 입력 영역 가운데에 정렬했습니다.
- 저장·불러오기 창을 더 넓고 보기 쉬운 작업공간 형태로 개편했습니다.
  - 데스크톱에서는 넓은 대화상자로, 모바일에서는 화면 전체 크기로 열립니다.
  - 상단에서 현재 캐릭터와 채팅을 확인하고 저장/불러오기 모드를 전환할 수 있습니다.
- 자동저장은 별도의 가로 목록으로, 수동 저장은 반응형 카드 격자로 표시합니다.
- 퀵세이브 카드는 아직 만들어지지 않았더라도 항상 첫 번째에 표시됩니다.
  - 저장 모드에서 빈 퀵세이브 카드를 누르면 바로 생성할 수 있습니다.
- 수동 저장 카드를 기존보다 작고 촘촘하게 정리하고 파일명과 저장 시점의 턴 수를 더 크게 표시합니다.
  - 이름 변경 버튼을 각 수동 저장 카드의 오른쪽 위로 옮겨 편집할 파일을 바로 확인할 수 있습니다.
  - 저장 시각은 하단의 보조 정보로 유지하며 자동저장과 퀵세이브의 구분도 보존합니다.
- 미리보기 영역은 세로 크기를 조절할 수 있습니다.
- 기존 수동 저장의 이름 변경, 삭제, 정렬, 덮어쓰기와 안전한 불러오기 동작은 그대로 유지됩니다.

## 화면 디자인과 모달 일관성

- 공통 모달 표면 계약을 추가하고 설정·프리셋·플러그인·북마크·캐릭터 관리 등 기존 대화상자를 같은 테마 규칙으로 통일했습니다.
  - 테마 토큰을 사용하는 불투명 배경, 테두리, 그림자와 반응형 여백을 공통으로 적용해 화면마다 배경이 비치거나 모서리와 간격이 달라 보이던 문제를 정리했습니다.
  - 확인, 입력, 로딩 대화상자도 같은 시각적 위계와 표면을 사용합니다.
- 캐릭터 저장소의 캐릭터 카드를 정사각형으로 변경했습니다.
  - 카드에 마우스를 올리거나 키보드로 포커스하면 이미지가 어두워지고 캐릭터 이름이 중앙에 큰 글씨로 표시됩니다.
  - 선택, 퀵 인벤토리 고정, 열기, 이름 변경과 폴더 드래그 동작은 그대로 유지됩니다.

## BardWiki 이력과 되돌리기 정책 변경

- **저장 파일과 자동저장을 대화와 위키를 함께 되돌리는 공식 경계로 통일했습니다.**
- 매 턴마다 전체 위키 복사본을 계속 쌓던 스냅샷과 문서별 되돌리기 기능을 제거했습니다.
  - `이번 턴 정본`에는 이제 사용된 메시지와 사건, 변경된 문서, 처리 시각, 경고 등 간결한 근거 기록만 남습니다.
  - 기록은 읽기 전용이며 턴 전체를 즉시 되돌리는 버튼은 제공하지 않습니다.
- BardWiki 근거로 사용된 메시지가 포함된 대화 구간은 바로 삭제할 수 없도록 보호합니다.
  - 필요한 시점의 저장 파일을 불러온 뒤, 상태가 어긋났다면 위키 리부트를 실행하도록 안내합니다.
- BardWiki 근거가 존재하는 과거 지점에서는 새 분기를 만들 수 없도록 막았습니다.
  - 현재 대화 끝에서 복사하거나 분기하는 기능은 계속 사용할 수 있습니다.
  - 서버에서도 같은 조건을 검사하여 이전 버전 화면을 통한 우회를 막습니다.
- 이전 버전이 남긴 턴별 스냅샷 폴더는 작업공간을 열거나 이전하는 과정에서 정리합니다.
  - 저장 파일을 만들거나 위키를 복사할 때도 오래된 스냅샷과 복구용 임시 폴더를 포함하지 않습니다.
- 위키 리부트는 한 번에 하나의 제한된 복구 체크포인트만 사용하도록 바꿨습니다.
  - 중간에 중단된 작업은 충돌과 손상 여부를 확인한 뒤 안전하게 복구할 수 있습니다.
  - 완료된 체크포인트는 기록 저장 후 제거하여 복구 데이터가 계속 누적되지 않습니다.

> 중요한 전개를 크게 바꾸기 전에는 수동 저장이나 퀵세이브를 만들어 두는 것을 권장합니다.

## 캐릭터 정본 갱신 신뢰성

- 캐릭터 변화 분석 결과를 정본 수정 단계에 더 구조적으로 전달합니다.
  - 상태 변화, 캐릭터가 새로 알게 된 사실, 지속 사실, 미해결 연속성을 함께 반영합니다.
  - 새로운 현재 상태는 이미 끝난 상태를 대체하고, 과거 상태는 서사적으로 필요할 때만 이력으로 남기도록 지침을 강화했습니다.
  - 정체성, 관계, 지식, 목표, 소지품, 제약처럼 이번 장면과 무관한 기존 사실은 보존합니다.
- 분석에서 명확한 캐릭터 변화가 확인됐지만 수정 대상이 빠진 경우, 상태 변화의 주체에서 기존 활성 캐릭터 이름 하나를 명확히 식별할 수 있을 때만 보수적으로 복구하여 갱신합니다.
  - 후보가 없거나 여러 개면 임의로 선택하지 않고 경고만 남깁니다.
- 이 보강 과정은 추가 AI 호출 없이 기존 분석과 정본 수정 단계 안에서 처리되므로 기본 호출 횟수와 예산을 늘리지 않습니다.
- BardWiki가 문서를 쓰는 동안에는 새 답변 생성, 재생성, 이어쓰기, 중단된 생성 재개를 잠시 막습니다.
  - 작성 중인 입력 내용은 보존되며, 위키 갱신이 끝난 뒤 다시 실행할 수 있습니다.

## 긴 위키 문서 검색과 응답 근거 개선

- 긴 캐릭터 문서를 읽을 때 문서 앞부분이나 오래된 사건 기록만 잡히지 않도록 발췌 방식을 개선했습니다.
  - 제목, 현재 상태, 정체성, 프로필, 교육, 직업, 관계, 지식, 목표, 소지품, 제약을 우선 확보합니다.
  - 긴 과거 이력은 시간 순서나 과거 사건이 필요한 질문일 때 우선 포함합니다.
  - 한국어와 영어 섹션 제목을 모두 인식합니다.
- 같은 발췌 규칙을 일반 응답용 위키 조회와 정본 분석의 기존 기록 조회에 함께 적용했습니다.
- 답변 근거를 판단할 때 캐릭터 문서의 현재 상태를 오래된 이력이나 근거 없는 추정보다 우선하도록 규칙을 명확히 했습니다.

## 확정된 사건 직접 편집

- 이제 과거의 확정된 사건 문서도 Memory Wiki에서 직접 수정할 수 있습니다.
  - 사건 제목과 Markdown 본문을 편집해 저장할 수 있습니다.
  - Wiki Admin에서도 **정확한 기존 사건 문서 ID**를 지정하면 제목과 본문을 수정할 수 있습니다.
- 사건을 수정해도 사건 ID, 사건 종류, 파일 위치, 최초 생성 시각, 출처 메시지 연결은 유지됩니다.
  - 저장 전 내용은 문서 이력에 남고, 직접 수정한 문서임을 표시합니다.
- `지금까지의 이야기`는 별도의 복사본이 아니라 현재 활성 사건의 `이야기 요약`을 보여줍니다.
  - 사건 내용을 수정하면 `지금까지의 이야기`에도 자동으로 반영됩니다.
  - 원문 메시지로 이동하는 출처 연결도 유지됩니다.
- 사건 종류는 편집할 수 없으며, 일반 문서를 사건으로 바꾸거나 새 사건을 수동으로 만드는 기능은 제공하지 않습니다.
- 사건 삭제는 휴지통 이동이 아니라 영구 철회이므로 기존처럼 별도 확인을 거칩니다.

## 문서
