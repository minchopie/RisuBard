# RisuBard v0.9.33

바드위키의 Batch 분석을 긴급 롤백해 기존 자동분석·추가분석 흐름을 복구했습니다. 프롬프트 블록 인젝터를 추가하고 프롬프트·데이터 저장, 가져오기와 백업의 내구성도 개선했습니다.

## [안정성] 바드위키 분석 복구

- **기존 분석 복구:** 실행 시 400 오류가 발생하던 `Batch 분석`을 제거하고 기존 `추가 분석` 버튼과 자동분석 처리 경로를 복구했습니다. `추가 분석`은 최신 AI 응답을 기준으로 이미 적용된 정본을 제외한 미처리 항목을 분석합니다.

## [기능] 프롬프트 블록 인젝터

- **블록 추출과 누적:** 설치된 프롬프트에서 제목에 지정한 문자열이 들어간 블록만 추출할 수 있습니다. 검색 문자열의 기본값은 `📙`이며, 새 추출 묶음을 만들거나 현재 편집 중인 묶음 뒤에 이어 붙일 수 있습니다.
- **독립된 추출 묶음:** 추출한 블록은 원본 프리셋과 분리해 보관됩니다. 묶음 이름을 바꾸거나 삭제할 수 있고, 새 블록 추가, 제목 인라인 편집, 내용·타입·특수 타입·역할 편집, 복제·삭제와 1칸 또는 5칸 단위 순서 이동을 지원합니다.
- **영구적인 주입 매핑:** 각 블록을 건너뛰거나 대상 기본 블록의 앞·교체·뒤에 배치할 수 있습니다. 추출 묶음이나 활성 프롬프트를 바꿔도 주입 방식과 대상 설정이 유지되며, 대상 블록을 찾지 못하면 해당 항목을 분명하게 표시합니다.
- **주입 프리셋:** 추출된 블록, 참조 토글 포함 여부, 삽입 방식과 대상 매핑을 별도 프리셋으로 새로 저장하거나 덮어쓰고 이름을 바꾸거나 삭제할 수 있습니다. 선택된 주입 프리셋은 현재 프롬프트로 요청을 보낼 때 자동 적용됩니다.
- **프리뷰와 직접 편집:** `블록 주입 프리뷰 + 에디터`에서 원본 블록과 주입 블록을 접어 내용을 확인하고 직접 편집할 수 있습니다. 주입 블록도 기본 블록과 같은 깊이로 표시해 존재하지 않는 계층으로 오해하지 않도록 했습니다. 합성 결과는 이름을 지정해 새 프롬프트로 저장하거나 확인 후 원본 프롬프트에 덮어쓸 수 있습니다.
- **작업 공간 개선:** 추출 도구와 주입 프리셋 영역, 매핑 목록과 프리뷰 사이의 너비를 조절할 수 있습니다. 상단 전체를 접을 수 있고, 좁은 창에서도 버튼과 입력란이 줄바꿈되며, 선택 항목 강조·한 줄 매핑·아래 화살표로 여는 블록 편집기·스크롤 가능한 최종 순서로 긴 프롬프트도 다루기 쉬워졌습니다.

## [기능] BardWiki 턴 기준 설정

- **턴 기준 범위:** `분석할 턴 수`와 `응답용 턴 수`는 메시지 개수가 아니라 AI 응답 턴을 기준으로 계산합니다. 응답 생성과 분석에서 사용자 메시지를 포함할지도 각각 따로 설정할 수 있습니다.

## [편의성] 페르소나와 백업 진단

- **새 챗 페르소나 고정:** 사이드바의 페르소나 선택 옆 핀 버튼으로 새 채팅에 현재 페르소나를 자동 연결할지 정할 수 있습니다. 기본값은 켜짐이며, 끄면 새 채팅을 페르소나 미지정 상태로 시작합니다.
- **대용량 백업 검사:** `pnpm inspect:backup -- <백업 파일>` 명령으로 여러 GB 크기의 백업도 전체 에셋을 메모리에 올리지 않고 검사할 수 있습니다. 개인정보가 담긴 이름이나 대화 내용 대신 데이터 개수와 익명화된 ID 해시만 출력합니다.

## [성능] 프롬프트 편집과 저장

- **불필요한 전체 저장 제거:** 변경이 없으면 저장 작업을 즉시 끝내고, 작은 변경은 전체 데이터 재인코딩 전에 패치 저장을 먼저 시도합니다. 프롬프트 편집과 설정 변경 중 발생하던 긴 멈춤을 줄였습니다.

## [안정성] 가져오기와 백업 저장

- **가져오기 완료 보장:** 캐릭터·모듈·플러그인을 가져올 때 브라우저와 서버 저장이 끝난 뒤에만 성공을 알립니다. 저장에 실패하면 성공으로 표시하지 않아 새로고침 후 가져온 항목이 사라지는 일을 방지합니다.
- **최신 상태 백업:** 전체·설정 전용·호환용·서버 백업을 만들기 전에 현재 상태를 먼저 저장합니다. 저장에 실패하면 오래된 상태로 백업 파일을 만들지 않고 작업을 중단합니다.

## [성능] 릴리즈 절차 단축

- **중복 검증 제거:** 릴리즈 버전과 패치노트를 먼저 확인하고 전체 검증은 GitHub CI에서 한 번만 실행합니다. 검증과 네 플랫폼 패키징이 모두 성공한 뒤에만 태그와 릴리즈 초안을 생성합니다.
