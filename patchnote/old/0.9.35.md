# RisuBard v0.9.35

Windows 앱 내부 업데이트의 파일 교체와 재시작 절차를 수정했습니다. 설치 파일 누락을 검사하고, 실패 시 이전 파일과 진단 기록을 보존합니다.

## [안정성] Windows 업데이트와 실패 복구

- **종료 후 파일 교체:** 기존 서버가 완전히 종료된 뒤 별도 업데이터가 파일을 교체합니다. 실행 중인 런처 때문에 교체가 막히는 문제와 배치 파일의 고정 대기 시간에 의존하던 재시작을 개선했습니다.
- **설치 완료 확인:** 새 서버가 정상 기동한 후 버전을 확정하고 백업을 정리합니다. 기동 실패 시 이전 앱 파일을 복원하며, 복원에 실패한 파일의 백업을 임의로 삭제하지 않습니다.
- **의존성 누락 검사:** 설치 전후에 서버 의존성과 `express` 로딩을 확인합니다. `update.bat`도 같은 버전의 파일이 불완전하면 다시 다운로드해 복구합니다.
- **업데이트 기록:** Windows 앱 내부 업데이트의 후처리와 독립 업데이터 기록을 설치 폴더의 `update.log`에 남깁니다. 기존 세이브와 사용자 HTTPS 인증서를 보존합니다.

## [안정성] 이번 버전 설치 안내

- **0.9.34 이하에서 설치:** 이번 다운로드에는 아직 구버전 업데이터가 사용됩니다. Windows 사용자는 서버를 종료한 뒤 0.9.35 ZIP을 새 폴더에 풀고 기존 `save`를 복사하는 방법을 권장합니다. 별도 저장 경로, `.env`, 사용자 인증서나 백업 폴더를 설정했다면 해당 설정과 파일도 함께 옮겨 주세요.
- **기존 폴더 보존:** 새 설치에서 데이터와 실행 상태를 확인할 때까지 이전 폴더와 `.update-tmp`를 보관해 주세요. 이 수정으로 이미 손상된 설치본이 자동 복구되는 것은 아닙니다.

## [시스템] 배포본 검증

- **실제 압축 파일 검사:** 각 플랫폼의 최종 배포 파일을 별도 폴더에 풀고, 동봉된 Node로 의존성과 서버 기동을 검사한 뒤 릴리즈를 생성합니다.

## [시스템] Docker 이미지 자동 게시

- **릴리즈 연동 복구:** 새 버전을 릴리즈하면 해당 버전과 `latest` Docker 이미지도 자동으로 빌드하고 게시합니다.
