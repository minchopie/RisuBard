# RisuBard v0.9.39

대형 세이브의 자동 저장 대기 시간을 크게 줄이고, OOC 대화를 본문과 위키 분석에서 분리해 관리할 수 있게 했습니다. 그리모어 분석과 플러그인 요청 로그도 실패 원인을 직접 확인할 수 있도록 보강했습니다.

## [성능] 자동 저장 속도 개선

- **대형 세이브의 저장 대기 감소:** 비슷한 크기의 60MB급 세이브에서 평소 저장 시간은 333ms, 느린 저장 시간은 1.43초, 파일 반영 시간은 282ms, 임시 파일 준비량은 2.54MiB였습니다. 네 항목은 직전 단계인 P1.1보다 각각 78.92%, 55.52%, 78.66%, 50.51% 줄었고, V1 저장 구조 초기 버전인 v0.9.30보다 각각 90.20%, 61.10%, 88.84%, 95.45% 줄었습니다.
- **검증된 변경만 바로 저장:** 일반 채팅, 프리셋과 설정 자동 저장은 바뀐 파일을 먼저 기록합니다. 구버전과 백업 호환용 전체 저장 파일은 실제로 읽거나 내보낼 때 만들며, 복잡한 변경이나 검증되지 않은 저장소는 기존 안전 경로를 사용합니다.
- **프리셋 편집 반응 개선:** 프롬프트 설정만 편집할 때 불필요한 전체 동기화와 반복 비교를 줄였습니다. 첫 검증, 오류 뒤 검증과 전체 동기화의 안전장치는 유지합니다.
- **불필요한 대용량 색인 기록 제거:** 작은 저장 완료 표식 때문에 25MB가 넘는 에셋 색인을 매번 다시 쓰던 비용과, 색인 JSON을 다시 파싱하던 중복 처리를 없앴습니다.
- **실사용 안전성 확인:** 원래 사용하던 60MB급 세이브에서 저장 285건, 호환용 전체 저장 파일 생성 35건과 백그라운드 일치 검사 190건이 모두 성공했습니다. 저장 실패와 데이터 불일치는 없었습니다.
- **저장 통계 보완:** 환경설정의 개발자 통계에서 호환용 전체 저장 파일의 생성 횟수와 느린 구간의 소요 시간을 따로 확인할 수 있습니다.

## [안정성] 프리셋 외부 편집

- **외부 편집 시작 멈춤 수정:** 프리셋 파일을 안전하게 수정하기 위한 외부 편집 모드가 저장 대기에서 멈추던 문제를 수정했습니다.

## [기능] OOC 메모장과 위키 분석 분리

- **메시지 점프 지연 개선:** OOC 메모장의 원문 이동과 하단 툴바 점프에서 채팅 전체 이미지 로딩을 기다리던 지연을 제거했습니다. 이미 표시된 메시지는 즉시 이동하며, 이후 이미지로 위치가 바뀌면 기존 스크롤 위치 유지 설정에 따라 보정합니다.

- **OOC 메모장:** 현재 챗의 OOC 응답과 대응 사용자 입력을 원본과 연결해 표시합니다. 연속된 AI 턴을 `4–5`, `8`, `10–12` 같은 그룹으로 묶고 드롭다운, 이전/다음 버튼과 내용 검색으로 탐색합니다. 각 항목 우측 상단의 `원문으로 이동`은 챗 숨김을 해제하고 해당 메시지로 이동합니다. 제목 행에서 숨김, 메모장 글자 크기와 MD 서식을 조절하며 자세한 안내는 제목 옆 도움말에 모았습니다. 원본 수정과 삭제를 바로 반영하고 본문 채팅의 강조색과 서식을 유지합니다.

- **OOC 집필 상담 제외:** 기본으로 켜지는 `<!-- OOC_turn --> 무시하기` 옵션으로 마커가 있는 AI 응답과 대응 사용자 입력을 위키 분석, 리부트, 과거 원문 검색과 답변용 최근 대화에서 제외합니다. 현재 작성한 새 사용자 요청과 원본 메시지는 유지합니다. 옵션을 끄면 다시 포함하며 기존 위키는 소급 수정하지 않습니다. 리부트는 시작할 때의 옵션을 유지합니다.

- **일반 응답의 Hypa 오류 수정:** 구형 장기기억 설정이 남아 있어도 일반 응답에서 내장 Hypa 요약기가 실행되지 않도록 수정했습니다. 플러그인에 제공하는 BardWiki 호환 기억은 유지합니다.

- **리부트 실패 원인 표시:** AI 응답 검증에 실패하면 검증기가 제공한 필드 누락이나 형식 불일치 등의 구체적인 이유를 오류창과 바드위키 작업 로그에 함께 표시합니다.

- **긴 위키 조회 결과 처리:** 사용자 토큰 예산 안의 긴 위키 문서나 과거 원문을 조회해도 오류로 중단되지 않도록 수정했습니다. 조회 결과와 프롬프트에 별도로 적용되던 글자 수 제한을 없애고, 문서별 발췌량은 실제 토큰 수와 사용자 설정을 기준으로 처리합니다.

- **사용자 메시지 제외 시 리부트:** 분석에서 사용자 메시지를 제외하도록 설정하면 위키 리부트가 근거 메시지 불일치 오류로 중단되던 문제를 수정했습니다. 분석할 원문과 근거 목록에 같은 설정을 적용합니다.

## [편의성] 그리모어 분석 오류 진단

- **실패 원인과 근거 확인:** 분석 실패 시 제공자가 보고한 출력 토큰 한도, 입력 컨텍스트 초과, 거부 신호와 JSON 형식 오류를 구분해 안내합니다. 실패한 요청의 항목 수, 토큰 설정, 제공자 사용량, 종료 사유, 원본 오류와 응답 발췌를 펼쳐 볼 수 있으며 분석창을 다시 열어도 보존합니다. 근거가 없는 토큰 부족이나 검열은 확정하지 않고, 재시도 오류에 이전 응답이 섞이지 않도록 했습니다.

## [편의성] 플러그인 리퀘스트 로그 본문

- **플러그인 요청과 응답 확인:** 플러그인 모델 로그에도 전달한 프롬프트와 설정, 응답 또는 오류 본문을 저장합니다. 스트리밍 응답과 중단 시점까지 받은 내용도 확인할 수 있습니다. 플러그인의 `nativeFetch`와 `risuFetch`로 수행한 HTTP 요청은 별도 기록에 헤더, 요청 본문과 응답을 남기며, 기본 분류는 `기타`와 `플러그인`입니다. 이전에 저장되지 않은 본문은 복원되지 않습니다.

## [호환성] 로컬 호스팅 플러그인 가져오기

- **HTTP 환경 플러그인 지원:** 내부 IP의 HTTP 주소로 접속할 때 API v3 플러그인을 가져오면 정상 파일도 손상된 파일로 표시되던 문제를 수정했습니다. 플러그인 실행에 필요한 보안 난수를 HTTP에서도 지원되는 방식으로 생성합니다.
