# RisuBard v0.9.40

저장할 때 기다리는 시간을 크게 줄였습니다. 0.9.30 이후 쌓아 온 개선으로 대형 세이브의 평소 저장 시간이 측정 표본에서 약 3.4초에서 0.3초로 줄었으며, 원하는 캐릭터만 새 V3 저장 구조로 미리 전환해 볼 수 있습니다. 바드위키 검색과 작성 설정, 백업 다운로드도 개선했습니다.

## [성능] 대형 세이브의 저장 대기 감소

60MB급 세이브로 측정한 **0.9.30 기준선과 0.9.40 후보의 비교**입니다. 모든 항목은 작을수록 좋습니다.

| 무엇이 달라졌나요? | 0.9.30 | 0.9.40 후보 | 감소율 |
| --- | ---: | ---: | ---: |
| 평소 저장 시간: 저장에 걸린 시간의 가운데 값 | 3.401초 | 0.300초 | **91.18%** |
| 느린 저장 시간: 저장 10번 중 약 9번이 이 시간 안에 끝남 | 3.675초 | 0.584초 | **84.11%** |
| 파일 반영 시간: 저장 내용을 실제 파일에 반영하는 단계의 가운데 값 | 2.530초 | 0.291초 | **88.49%** |
| 임시 파일 준비량: 저장 한 번에 준비하는 임시 데이터의 평균 크기 | 55.723MiB | 2.603MiB | **95.33%** |

- **V3 전환 없이 측정:** 위 수치는 기존 저장 구조를 사용하는 상태에서 나온 결과입니다. V3를 켜야만 얻을 수 있는 개선이 아닙니다.
- **비교 범위:** 0.9.30의 950건과 0.9.40 후보의 41건을 비교한 관찰값이며, 이전 업데이트부터 누적된 개선을 포함합니다. 후보 표본은 변경된 부분만 저장하는 작업으로 구성되어 있어, 모든 저장이나 컴퓨터에서 같은 감소율을 보장하지는 않습니다.
- **필요한 데이터부터 읽기:** 시작할 때 전체 세이브와 모든 대화를 다시 조립하는 작업을 줄이고 설정과 대화 목록, 필요한 대화를 먼저 읽습니다. 플러그인이 같은 대화의 바드위키를 반복 조회할 때도 짧은 시간 동안 결과를 재사용합니다.

## [성능] 백업 다운로드와 캐릭터 가져오기

- **브라우저에서 백업 받기:** 전체 백업, 설정 백업, RisuAI 호환 백업과 서버 백업을 브라우저의 기본 다운로드로 받습니다. 탭이 파일을 중계하지 않아 다른 탭이나 프로그램을 사용하는 동안 전송이 느려지는 문제를 줄였으며, 진행과 완료 여부는 브라우저 다운로드 목록에서 확인할 수 있습니다.
- **가져오기 대기 감소:** 캐릭터 파일, 리스렐름 캐릭터와 CHARX 모듈을 가져올 때 화면 갱신을 위해 반복하던 타이머 대기를 줄였습니다. 백그라운드 탭에서 불필요한 대기가 누적되는 문제를 완화합니다.

## [기능] 캐릭터 V3 저장 구조 미리 써 보기

**환경설정 > 데이터 및 시스템 > 개발자 > 캐릭터 V3 저장 구조 전환**에서 캐릭터를 선택해 시험할 수 있습니다.

- **V3의 목적:** 캐릭터별 데이터를 읽기 쉬운 폴더로 묶고, 필요한 파일만 읽고 쓰는 저장 구조로 발전시키기 위한 기능입니다. 데이터 관리와 향후 성능 개선을 위한 기반이며, 이번 시험 전환만으로 추가 속도 향상을 보장하지는 않습니다.
- **캐릭터 하나씩 전환:** 선택한 캐릭터의 본문, 채팅과 전용 에셋 복사본을 캐릭터 이름 기반 폴더에 배치합니다. 공유 에셋은 기존 저장소에 남으며, 바드위키와 공유 모듈까지 모두 옮기는 기능은 아직 아닙니다.
- **이름에 맞춘 폴더:** 캐릭터와 채팅 이름을 바꾸면 다음 저장에서 폴더 이름도 갱신합니다. 내부 식별자는 유지하고 이름 충돌은 번호로 구분합니다.
- **되돌리기와 재전환:** 기존 구조로 복귀할 때 전환 뒤의 편집 내용과 새 채팅도 함께 옮깁니다. 복귀 후 다시 전환할 때 중단되던 문제와 전환 직후 저장 충돌로 오인하던 문제를 수정했습니다.
- **명확한 대상과 결과:** 삭제한 캐릭터는 선택 목록에서 제외하며, 전환 실패나 에셋만 활성화된 미완료 상태를 구분해 표시합니다. 기존 백업 형식을 유지하고 자동 일괄 전환은 하지 않습니다. 시험 전환 전에는 전체 백업을 만들어 두세요.

## [기능] 바드위키 의미 검색과 작성 프리셋

- **표현이 달라도 기억 찾기:** 공통 설정에서 선택형 임베딩 검색을 켜면 현재 입력과 최근 대화를 바탕으로 과거 사건과 세부 근거를 찾습니다. Hypa 임베딩의 모델, URL과 API 키를 사용하며 기본값은 꺼짐입니다.
- **검색 준비와 재사용:** 문서 벡터를 백그라운드에서 준비하고 재사용하며, 문서나 모델 변경을 반영합니다. 준비 중이거나 임베딩 요청이 실패하면 기존 검색으로 진행합니다.
- **정돈된 기본 작성 지침:** 현재 상태, 관계와 신뢰, 지식과 비밀, 주요 전환을 구분해 같은 사실의 반복을 줄이도록 기본 위키 프리셋을 개선했습니다. 이전 공식 프리셋은 `공식기본-260922`로 선택할 수 있습니다.
- **장비와 분량 조절:** 장비와 소지품 블록은 기본으로 켜지고, 분량 압축 블록은 기본으로 꺼집니다. 공식 프리셋에서도 두 블록을 켜거나 끌 수 있습니다.
- **긴 위키 갱신:** 본문이나 수정안이 12,000자를 넘는다는 이유로 갱신을 거부하던 제한을 제거했습니다. 대화에 보내는 기억의 검색 범위와 토큰 예산은 유지합니다.
- **프리셋 선택과 설정 이동:** 검색 가능한 프리셋 선택 창을 제공하고, 공통 설정의 세로 목차와 임베딩 모델 설정 바로가기를 추가했습니다.

## [편의성] 캐릭터 정리와 이름 구분

- **중복 이름 구분:** 가져오기, 복제, 이름 변경과 새 대화 생성 시 같은 이름이 있으면 `(2)`, `(3)`처럼 번호를 붙입니다.
- **삭제와 용량 회수:** 캐릭터 삭제를 두 번 확인하면 3일 대기 없이 삭제하며, 저장 완료 뒤 관련 캐릭터와 채팅 폴더를 제거합니다. 해당 캐릭터의 에셋 중 다른 곳에서 쓰지 않는 파일은 자동 회수하고, 공유 파일이나 사용 여부를 확인할 수 없는 파일은 보존합니다.

## [안정성] 저장과 백업 복원

- **큰 채팅 나눠 전송:** 공통 설정의 저장 및 불러오기에서 큰 채팅을 나눠 업로드하도록 설정할 수 있습니다. 서버나 프록시의 요청 크기 제한에 대응하는 선택 기능이며 기본값은 꺼짐입니다.
- **복원 중단 대응:** 파일 정본이 포함된 백업의 복원 도중 종료되면 다음 시작에서 남은 파일 반영을 이어갑니다. 기존 자료는 복구용으로 보존하고, V3 캐릭터의 이전 보존 폴더가 백업에 중복 포함되지 않도록 정리했습니다.

## [안정성] 그리모어 대형 명단 분석

- **출력량에 맞춘 분할:** 연표와 명단 분석에서 예상 출력량을 고려해 작업을 나누고 출력 한도를 계산합니다.
- **남은 항목부터 재시도:** 잘린 응답에서 완료된 항목은 보존하고 실패한 항목만 더 작게 나눠 재시도합니다. 플러그인이 제공하는 종료 사유와 토큰 정보도 오류 진단에 활용합니다.

## [안정성] 알려진 문제

- **일시적인 시작 오류:** 후보 테스트 중 앱 시작 시 빈 JSON 해석 오류가 한 차례 보고됐으며 서버 재시작 후 정상화됐습니다. 원인은 아직 확인되지 않았으므로 재발하면 시작 화면의 단계와 오류 내용을 함께 알려 주세요.

## [UI] 시작 화면과 찾기/바꾸기

- **시작 단계 표시:** 첫 화면에 RisuBard 배너와 버전을 표시하고, 저장소 초기화부터 데이터 해석과 플러그인 로드까지 현재 단계를 안내합니다. 시작 실패 시 해당 단계와 오류를 남깁니다.
- **찾기/바꾸기 열기:** 채팅이나 위키 작업 중 입력창 위 툴바의 찾기/바꾸기 버튼을 열 수 없던 문제를 수정했습니다. 검색은 가능하며 실제 바꾸기는 진행 중인 작업이 끝난 뒤 사용할 수 있습니다.

## [호환성] 아카라이브 챗 저장 서식

- **글자색과 이미지 정리:** `아카라이브 챗 저장기`로 복사할 때 생각과 대사 색상을 유지하고, 불필요한 노란 배경과 이미지의 흰 테두리 및 여백을 제거했습니다.
