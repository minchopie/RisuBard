# RisuBard v0.9.52

장기기억 검색과 인물 연대기를 확장하고 CHARX 설치 취소와 복구를 보완했습니다. 응답 대기 중 채팅 전환과 퀵 터널 동기화의 안정성을 개선했습니다.

## [기능] 장기기억 검색과 인물 연대기

- **장기기억 동적 한도:** 전역 및 현재 챗 설정에서 사용 안 함, 절약형, 균형형, 회수 우선형을 선택할 수 있습니다. 활성 AI 응답의 누적 본문 길이에 따라 검색 목표 토큰, 사건 검색 토큰, 검색 최대 토큰과 분석 토큰 한도가 조금씩 늘다가 50만 자에서 멈춥니다. 기본값 대비 최대 증가는 절약형 25%, 균형형 50%, 회수 우선형 100%이며, 과거 원문 수와 검색 후보 수는 유지합니다. 검색 최대 토큰에는 별도의 검색 증가 상한도 적용하며 기본값은 사용 안 함입니다.
- **적용값 표시와 편집:** 동적 한도가 적용된 숫자는 파란색으로 표시하고 편집할 때는 원래 기본값을 보여줍니다. Enter로 확정하거나 Esc로 취소할 수 있으며, 기능을 끄면 기본값으로 돌아갑니다. 이름 옆 도움말 버튼에서 영향을 받는 항목과 1,000자 응답 기준 50턴 및 100턴의 증가량을 확인할 수 있습니다.
- **인물 연대기:** 위키의 `인물 연대기` 탭에서 인물과 명확하게 연결된 사건을 페이지로 탐색하고 사건 문서와 원문으로 이동할 수 있습니다. 연결이 불확실하거나 원문이 없는 기록은 별도로 표시합니다.
- **과거 근거 검색:** 같은 긴 문서에서 여러 근거 구간을 함께 읽습니다. 기존 의미 검색 임베딩을 켠 경우 과거 채팅 원문도 검색하며, 수정되거나 비활성화된 원문은 다시 검증합니다. 색인 준비 중이나 실패 시 기존 검색을 사용하며 동적 한도만으로 임베딩을 켜지 않습니다.

## [기능] CHARX 분류와 설치 복구

- **모듈 자동 분류:** 파일명이 `.module.charx`로 끝나면 모듈로 설치합니다. 대소문자는 구분하지 않습니다.
- **대용량 파일 확인:** 그 밖의 CHARX는 150 MB 이상 또는 에셋 5,000개 이상이면 저장 전에 모듈과 캐릭터 중 설치 유형을 선택할 수 있습니다. MB는 1,000,000바이트 기준입니다.
- **설치 취소 및 롤백:** 캐릭터와 모듈을 설치하는 동안 취소할 수 있습니다. 취소하거나 오류가 발생하면 진행 중인 저장이 끝난 뒤 이번 설치에서 추가한 항목과 새 에셋을 정리하며, 기존 에셋과 공유 에셋은 유지합니다.
- **복구 재시도:** 서버 연결 문제로 롤백을 마치지 못하면 복구 기록을 보관하고 새로고침 후에도 재시도할 수 있습니다. 복구가 끝날 때까지 새 설치는 시작하지 않습니다.
- **설치 작업 표시:** 현재 단계의 진행률, 처리 개수, 최신 처리 파일, 전체 경과 시간과 최근 작업 갱신 시간을 표시합니다. 처리량을 알 수 없는 단계는 임의의 퍼센티지를 표시하지 않으며, 진행 연결이 끊기거나 작업 갱신이 오래 없으면 별도로 안내합니다.
- **대량 에셋 설치 개선:** 파일명 중복 검사와 저장 대기 중 메모리 사용을 줄이고, 마지막 저장에서 불필요한 호환 캐시 생성을 생략합니다. 작은 압축 항목 수천 개를 한 번에 읽을 때 발생할 수 있는 스택 초과도 수정했습니다.

## [편의성] 긴 위키 문서 편집

- **본문 글자 제한 제거:** 자동 작성으로 길어진 위키도 직접 편집하거나 바드챗으로 수정할 수 있도록 남아 있던 12,000자 제한을 제거했습니다. 문서를 강제로 줄이지 않아도 수정할 수 있습니다.
- **긴 문서 구간 수정:** 바드챗에서 문서 제목 하나를 지정하면 큰 문서를 구간별로 처리하고 모두 검증한 뒤 한 번 저장합니다. 처리하지 않은 내용은 유지하고 응답 누락, 잘림이나 동시 수정이 있으면 저장을 중단합니다. 큰 문서의 여러 구간을 읽는 작업은 여러 번 호출될 수 있습니다.
- **실패 원인 안내:** 바드챗 결과의 본문, 항목 이름이나 문서 제목이 빠졌을 때 구체적인 원인을 표시합니다.

## [UI] 모바일 메시지 메뉴

- **편집과 더보기 분리:** 모바일 메시지에는 편집과 더보기 버튼만 표시하고 번역, 복사, 삭제와 재생성 등의 작업은 더보기 안으로 모았습니다. 편집 옆의 번역 버튼을 잘못 누르는 일을 줄이고 터치 영역을 넓혔습니다.

## [안정성] 응답 대기 중 채팅 전환

- **정규식 처리 회귀 수정:** 여러 정규식 규칙을 순서대로 실행할 때 호출 깊이가 누적되어 정상 채팅 본문이 `ERROR: Call stack limit reached`로 바뀌는 문제를 수정했습니다. 표시 처리와 응답 후처리를 실제 파서로 함께 검증했습니다.
- **원래 채팅에 응답 저장:** 같은 봇의 다른 채팅을 보고 있어도 일반 응답과 스트리밍 내용을 요청을 시작한 채팅에 기록하고 자동 저장합니다. 트리거 처리 결과가 현재 보고 있는 채팅을 덮어쓰는 문제를 수정했습니다.
- **입력과 후속 처리 보호:** 자동 이어쓰기, 스크립트 변수와 로어북 처리가 원래 채팅을 유지하도록 보완했습니다. 입력 처리 중 이동해도 다른 채팅의 입력 초안을 지우지 않습니다.

## [안정성] 퀵 터널 파일 동기화

- **원격 접속 호환:** 퀵 터널에서는 지원되지 않는 실시간 파일 알림 연결 대신 접속 직후와 이후 주기적인 조회로 외부 변경을 확인합니다. 채팅 전송 직전의 동기화 확인은 유지합니다.
- **동기화 재시도 복구:** 파일 상태 조회나 동기화 응답이 멈추면 제한시간 후 정리해 다음 시도에서 다시 확인할 수 있도록 보완했습니다. 늦게 도착한 응답은 반영하지 않으며, 서버에서 처리 중인 저장이 취소됐다고 가정하지 않습니다.
- **인증과 저장 대기 복구:** 인증 갱신, 저장 응답과 업로드 정리 요청을 무한히 기다리지 않도록 보완했습니다. 앞선 저장 때문에 전송하지 못한 경우에는 별도로 안내하며, 저장 응답 시간 초과를 서버의 저장 취소로 표시하지 않습니다.

## [안정성] 개발 실행 재시작

- **재시작 충돌 방지:** 개발 런처가 실제 서버 프로세스와 파일 변경 감시를 직접 관리하도록 수정했습니다. 재시작 때 서버가 남아 데이터 폴더 사용 중 오류가 발생하는 경로를 제거하고, 종료를 확인하지 못하면 새 서버를 시작하지 않습니다. 데이터 보호 잠금은 유지합니다.

## [호환성] 다른 앱에서 수정한 백업 복원

- **수정과 삭제 반영:** 백업에 이전 리스바드 전용 데이터가 함께 들어 있더라도, 최신 공용 데이터의 로어북 수정과 캐릭터 삭제를 반영합니다. 복원 대상에 남아 있는 캐릭터의 위키 등 전용 파일은 유지합니다.
