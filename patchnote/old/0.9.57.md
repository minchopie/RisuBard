# RisuBard v0.9.57

프리셋과 빌더 결과를 저장할 때의 대기 시간을 줄이고 바드페인터 저장 인증 오류를 수정했습니다. 긴 챗의 바드위키 분석과 편집 오류, 사이드바 스크롤 조작도 개선했습니다.

## [성능] 저장 대기 시간 단축

- **저장 확인이 빨라짐:** 바드페인터 화풍과 캐릭터 저장, 페르소나 빌더와 로어 빌더의 결과 반영처럼 저장이 끝나길 기다리던 동작이 크게 빨라졌습니다. 서버가 변경분을 반영할 때 DB 전체를 복제하고 다시 계산하던 과정을 바뀐 부분만 처리하도록 바꿨습니다.
- **바드페인터 저장:** 서버에 반영되면 바로 완료를 표시하고, 디스크 기록은 뒤에서 이어서 진행합니다.
- **외부 파일 감시 경량화:** 앱이 직접 저장한 파일을 외부 변경으로 오인해 모든 캐릭터의 에셋을 저장할 때마다 다시 검사하던 문제를 수정했습니다. 감시 이벤트가 유실되면 저장을 막지 않고, 백그라운드에서 바뀐 캐릭터만 찾아 다시 검사합니다.
- **저장 검증 일정 조정:** 정본 파일 검증을 30초 대신 5분 간격으로, 저장이 3초간 없을 때만 실행해 연속 저장 중 끊김을 줄였습니다.

## [안정성] 바드페인터 프리셋 저장 개선

- **저장 인증 오류 수정:** 화풍과 캐릭터 프리셋을 저장할 때 세션 쿠키 만료나 누락으로 `Server database flush failed (401)`이 발생하던 문제를 수정했습니다. 서버가 응답하지 않는 저장 확정 요청에는 대기 제한을 적용했습니다.
- **중복 저장 감소:** 이미 저장한 채팅이 변경 목록에 남아 프리셋 저장 때마다 다시 전송되던 문제를 수정했습니다. 저장 도중 추가된 편집과 실패한 저장은 재시도 대상으로 유지합니다.

## [안정성] 긴 챗의 바드위키 오류 수정

- **큰 위키에서도 새 문서 생성:** 위키 전체가 분석 토큰 한도를 넘으면 직접 위키 명령이 `입력 예산을 초과했습니다`로 중단되던 문제를 수정했습니다. 이제 제목을 지정한 문서만 원문으로 보내고 나머지는 제목 목록으로 전달합니다.
- **긴 문서 여러 개 편집과 결합:** 목록으로만 전달한 문서나 한도를 넘는 여러 문서를 고쳐야 하면, 각 문서를 원문 전체에서 구간별로 나누어 편집합니다. 모든 문서의 편집 계획을 마친 뒤 저장합니다. 한도를 넘는 문서들의 `COMBINE`은 원문 전체를 존속 문서에 합친 뒤 정리하고, 중복 문서의 제목을 별칭으로 남겨 기존 링크가 계속 연결됩니다.
- **동적 한도의 출력 토큰 오류 수정:** 장기기억 동적 한도 조정이 분석 토큰 한도를 키우면서 출력 토큰 요청도 함께 커져 Vertex AI 등에서 `maxOutputTokens` 400 오류가 나던 문제를 수정했습니다. 늘어난 한도는 입력에만 적용하고, 출력은 사용자가 설정한 분석 토큰 한도를 넘지 않습니다.
- **공급자 출력 상한 자동 조정:** Yumi Provider Manager 같은 공급자 플러그인을 쓸 때도, 공급자가 출력 토큰 값이 상한을 넘는다고 거절하면 오류 메시지의 상한값으로 한 번 다시 요청합니다. 설정한 분석 토큰 한도가 모델 상한보다 커도 위키 분석과 직접 위키 명령이 실패하지 않습니다.
- **위키 리부트 조회 시간 초과 수정:** 큰 위키에서 바드위키 리부트와 응답 분석이 `narrative inquiry timed out after 10000 ms`로 실패하던 문제를 수정했습니다. 백그라운드 분석은 조회를 최대 2분까지 기다리고, 그래도 끝나지 않으면 대화에 등장한 제목과 별칭으로 관련 문서를 찾아 분석을 계속합니다.

## [UI] 사이드바 스크롤 조작 개선

- **스크롤바 클릭 복구:** 스크롤바와 크기 조절 영역을 분리해 클릭과 드래그로 정상 스크롤할 수 있습니다. 너비 조절은 경계 중앙의 손잡이에서만 시작합니다.
