# RisuBard v0.9.6

이번 버전은 **BardWiki 장기기억 검색, 자동저장과 채팅 이동 안정화, 채팅 공유 편의성**을 개선합니다.

## BardWiki 기억 검색 개선

- 모든 검색어 일치에 비슷한 점수를 주던 방식을 문서 빈도 기반 sparse 검색으로 개선했습니다.
  - 여러 문서에 반복되는 흔한 말보다 특정 사건에만 등장하는 희귀한 이름·물건·표식을 우선합니다.
  - 오래된 사건에만 남아 있는 구체적인 단서가 최근의 일반적인 기록에 밀리는 현상을 줄였습니다.
- 문자열이 직접 겹치지 않는 기억도 나중에 semantic 후보로 합칠 수 있도록 하이브리드 랭킹 경계를 추가했습니다.
  - semantic 점수의 절대값 대신 후보 순위를 사용하므로 임베딩 모델마다 점수 범위가 달라도 기존 sparse 결과와 안정적으로 결합할 수 있습니다.
  - semantic 후보는 최대 32개로 제한하고 전체 후보·선택 문서·token 상한은 기존 bounded inquiry 계약을 유지합니다.
- 현재 기본 검색은 추가 모델 호출 없이 개선된 sparse 검색을 사용합니다. semantic 후보 생성기는 아직 기본 활성화하지 않았으므로 조회 비용과 모델 호출 횟수는 늘지 않습니다.
- 기존 챗과 기존 BardWiki에 바로 적용되며 위키 리부트나 새 챗 시작은 필요하지 않습니다.

| 이전 방식 | 0.9.6 |
| --- | --- |
| 검색어가 포함된 문서에 고정 가중치 부여 | 전체 위키에서 드문 단서일수록 높은 가중치 부여 |
| 흔한 표현이 많은 최신 문서가 앞설 수 있음 | 사건 고유 키워드를 가진 오래된 문서를 우선하기 쉬움 |
| 문자열/sparse 후보만 진입 가능 | sparse 결과와 사전 계산된 semantic 후보를 순위 기반으로 결합 가능 |

### 설계에 참고한 장기기억 연구

- [T-Mem: Memory That Anticipates, Not Archives (2026)](https://arxiv.org/abs/2606.15405) — 표면적으로 비슷한 문장뿐 아니라 미래 상황과 연결되는 연상 회상을 검색해야 한다는 문제 정의를 참고했습니다.
- [MRAgent: Memory is Reconstructed, Not Retrieved (2026)](https://arxiv.org/abs/2606.06036) — 단일 top-k 검색보다 단서를 연결해 기억을 재구성하는 접근을 향후 확장 방향으로 참고했습니다.
- [TiMem: Temporal-Hierarchical Memory Consolidation for Long-Horizon Conversational Agents (2026)](https://arxiv.org/abs/2601.02845) — 시간·세션 계층 검색의 장점과 정리 단계의 추가 호출 비용을 함께 고려했습니다.
- [Memora: From Recall to Forgetting (2026)](https://arxiv.org/abs/2604.20006) — 오래되거나 무효화된 기억을 다시 사용하는 문제도 장기기억 품질 평가에 포함해야 한다는 점을 참고했습니다.

## 자동저장 안정화

- 자동저장 간격을 설정해도 계속 `자동저장 대기 중`으로 남고 실제 저장 파일이 생성되지 않던 문제를 수정했습니다.
- 최신 AI 응답의 다음 턴 확정을 기다리던 잘못된 조건을 제거했습니다.
- 이제 채팅 응답 생성과 BardWiki 작업이 모두 끝난 뒤 설정한 턴 간격에 맞춰 자동저장합니다.
  - 자동저장 간격을 `1`로 설정하면 완료된 AI 응답마다 저장합니다.
  - 메시지를 지우거나 별도의 수동 동작으로 자동저장을 깨울 필요가 없습니다.

## 채팅 가져오기와 BardWiki

- 같은 RisuBard 데이터 프로필에서 내보낸 채팅 JSON을 다시 가져오면 원본 BardWiki 작업공간도 새 채팅으로 복제합니다.
  - Markdown 정본, 사건, 변경 이력, 턴 영수증과 휴지통 자료를 함께 보존합니다.
  - 채팅 저장이 성공한 뒤에만 복제한 BardWiki를 확정하며, 저장에 실패하면 가져오기와 임시 Wiki를 함께 되돌립니다.
- 오래된 채팅 파일이나 다른 설치에서 가져온 파일처럼 원본 BardWiki 작업공간을 찾을 수 없는 경우, 메시지에 남아 있던 위키 확정 표식을 초기화합니다.
  - 빈 BardWiki가 이미 완성된 위키처럼 취급되는 상태를 방지합니다.
  - 전체 BardWiki를 다시 만들려면 위키 리부트를 실행할 수 있도록 안내합니다.
- 다른 설치 환경으로 BardWiki까지 옮길 때는 채팅 JSON 대신 BardWiki를 포함하는 전체 백업을 사용해야 합니다.

## 캐릭터 첫 메시지 편집

- `추가 첫 메시지`를 고급 탭에서 캐릭터 정보 탭의 첫 메시지 바로 아래로 옮겼습니다.
- 목록은 기본적으로 접혀 있으며, 제목에서 등록된 개수를 확인하고 펼쳐서 추가·순서 변경·삭제할 수 있습니다.

## 채팅 분기와 불러오기

- 중간 메시지에서 분기할 때 Memory Wiki 409 오류로 분기가 중단되던 문제를 수정했습니다.
  - 새 분기에는 미래 시점의 BardWiki를 복사하지 않으며 기존 위키 확정 상태를 초기화합니다.
  - 분기 후 새 챗에서 위키 리부트가 필요하다는 안내를 표시합니다.
- 불러오기 창의 툴바에 `새 챗으로 불러오기` 옵션을 추가했습니다.
  - 활성화하면 현재 챗을 덮어쓰지 않고 저장본과 BardWiki를 새 챗으로 복제합니다.

## 저장 목록 로딩 최적화

- 저장 파일 목록을 열 때 캐릭터의 모든 일반 채팅 작업공간을 순차 검사하지 않도록 개선했습니다.
- 이제 저장 슬롯 디렉터리만 검증하여 채팅과 저장 파일이 많을 때 발생하던 불필요한 파일 접근을 줄였습니다.

## 아카라이브 채팅로그 복사

- 채팅 메뉴에 `아카라이브 채팅로그`를 추가했습니다.
- 전체 채팅 또는 1부터 시작하는 메시지 범위를 선택해 미리보기를 만들 수 있습니다.
- 실제 채팅 렌더러의 결과를 사용해 이미지와 서식을 포함한 HTML과 읽기 쉬운 일반 텍스트를 클립보드에 함께 복사합니다.
- 비활성 메시지, 코멘트와 빈 자리표시 메시지는 자동으로 제외합니다.
