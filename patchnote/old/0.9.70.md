# RisuBard v0.9.70

## [수정] 응답을 받으면 챗 화면이 위로 튀던 문제

- **증상:** `스크롤 위치 유지`가 켜져 있을 때(기본값), 휴대폰처럼 화면을 그리는 속도가 느린 환경에서 응답을 받으면 챗 화면이 현재 페이지 맨 위나 이전 메시지로 올라갔습니다. 이 경우 하단의 `최신` 버튼을 누르거나 직접 스크롤해서 내려가야 했습니다. 서버에서 챗을 다시 받아 올 때도 같은 위치로 올라갔습니다.
- **원인:** 새 메시지가 추가되면 마지막 몇 개 메시지를 다시 그립니다. 다시 그리는 동안에는 본문이 아직 비어 있는데, 이때 읽던 위치를 새로 기억하면서 엉뚱한 메시지를 잡았습니다. 본문이 다 그려진 뒤에는 그 메시지를 제자리에 붙잡느라 화면을 위로 끌어올렸습니다.
- **변경:** 최신 메시지를 보던 중에 새 메시지가 오면 화면 끝을 따라갑니다. 내가 보낸 메시지도 바로 보이고, 응답이 오면 지금처럼 응답 시작 부분으로 이동합니다. 챗을 다시 받아 오는 동안에는 읽던 위치와 페이지를 그대로 두었다가, 다 받으면 같은 자리로 돌아옵니다.

## [수정] 캐릭터 비서가 자료만 읽다가 응답 실패로 끝나던 문제

- **증상:** 캐릭터 비서가 자료를 여러 번 나눠 불러오고, 짧은 말을 출력한 뒤 다시 자료를 불러오기를 되풀이하다가 `비서가 자료만 요청하고 답하지 못했습니다`로 끝났습니다.
- **원인:** 긴 필드의 다른 부분을 읽으면 앞서 읽은 부분이 재료에서 빠졌습니다. 비서는 방금 읽은 내용을 잃어 같은 자료를 다시 요청했고, 요청 횟수를 다 쓰면 답 없이 실패했습니다.
- **변경:** 같은 자료의 여러 부분을 읽으면 이어 붙여 함께 보냅니다. 이미 받은 자료를 다시 요청하면 이미 있다고 알려 줍니다. 마지막 요청에서는 더 읽지 말고 지금 자료로 답하라고 지시해, 질문은 항상 답변으로 끝납니다. 필요한 자료를 처음에 한꺼번에 요청하도록 비서의 지시도 고쳤습니다.

## [수정] `캐릭터로 클론`이 다른 페르소나를 복사하던 문제

- **증상:** 채팅의 페르소나 창에서 글로벌 페르소나를 고르고 `캐릭터로 클론`을 누르면, 고른 페르소나가 아니라 환경설정의 기본 페르소나가 캐릭터 페르소나로 복사되었습니다.
- **변경:** 지금 화면에서 고른 페르소나를 복사합니다.

## [수정] 전체화면 플러그인 위에서 권한 확인 창이 가려지던 문제

- **증상:** 플러그인이 전체화면 창을 띄운 상태에서 인레이 읽기나 채팅 교체처럼 권한이 필요한 기능을 쓰면, 권한 확인 창이 플러그인 창 뒤에 떠서 `예`나 `아니오`를 누를 수 없었습니다. 인레이 권한은 3일마다 다시 묻고 플러그인을 업데이트해도 다시 묻기 때문에 같은 일이 반복되었습니다. 플러그인이 띄운 알림과 확인 창도 같은 문제가 있었습니다.
- **원인:** 전체화면 플러그인 창이 앱의 모든 대화상자보다 위층에 있었습니다.
- **변경:** 플러그인이 기다리는 확인 창이나 알림이 떠 있는 동안에는 플러그인 창을 대화상자 아래로 잠시 내립니다. 창을 닫으면 플러그인 화면이 원래대로 맨 위로 돌아옵니다. 플러그인 쪽에서 창을 숨겼다가 다시 띄우는 우회 처리는 더 필요하지 않습니다. ([#40](https://github.com/rpaddict/RisuBard/issues/40))

## [추가] 캐릭터 비서에 전체 챗 저장, 포크, 답변 복사, 메시지 삭제

- 프롬프트 비서에 있던 기능을 캐릭터 비서에서도 씁니다. 두 비서가 같은 버튼과 동작을 공유합니다.
- 프로젝트 줄의 저장 버튼으로 대화 전체를 Markdown 파일로 저장합니다. 각 답변이 읽은 자료도 함께 적힙니다.
- 메시지 아래의 `여기서 포크하기`는 그 지점까지의 대화와 프로젝트 설정, 재료를 새 프로젝트로 복사합니다. 질문에서 포크하면 질문은 입력창에 들어갑니다.

## [추가] 캐릭터 비서가 고칠 내용을 수정 카드로 제안

- 이제 캐릭터 비서가 고칠 곳을 찾으면, 답변 아래에 수정 카드로 보여 줍니다. 제안 내용을 편집기에 직접 옮겨 붙이지 않아도 됩니다.
- 카드에는 바꿀 위치와 함께, 바꾸기 전 내용과 바꾼 뒤 내용이 나옵니다. `적용`이나 `건너뛰기`를 누르고, 제안이 여러 개면 `남은 N개 모두 적용`으로 한 번에 반영합니다. 카드 제목을 누르면 편집기에서 그 항목이 열립니다.
- 적용한 수정은 `되돌리기`로 원래대로 돌립니다. 적용한 뒤 그 칸을 직접 고쳤다면, 그 변경을 버릴지 먼저 묻습니다.
- 고칠 수 있는 것은 지금 다듬는 봇의 필드, 추가 인사말, 로어북의 본문과 키와 보조 키와 이름, 정규식의 IN과 OUT과 이름입니다. 참고 봇, 모듈, 프리셋, 블록 트리거, 항목 추가와 삭제는 지금처럼 답변에 제안만 하고 직접 반영합니다.
- 바꿀 부분이 본문에 없거나 여러 곳에 있으면, 아무것도 바꾸지 않고 카드에 이유를 표시합니다. 다음 질문을 보낼 때는 각 제안을 적용했는지, 건너뛰었는지, 실패했는지를 비서에게 함께 알려 줍니다.

## [추가] 프롬프트 캐시가 덜 깨지는 `캐싱 친화적 구조` 옵션

- **배경:** 바드위키 기억은 매 턴 바뀝니다. 지금까지는 이 기억을 프롬프트 맨 위(항상 포함 문서)와 캐릭터 설명 바로 뒤(검색된 기억)에 넣었습니다. 프롬프트 캐시는 앞에서부터 글자가 같은 구간까지만 적중하므로, 그 아래에 있는 프리셋 본문, 로어북, 지난 대화의 캐시가 매 턴 깨졌습니다. 프리셋의 메모리 슬롯을 옮겨도 위키 기억의 위치는 바뀌지 않았습니다.
- **변경:** `환경설정 > 공통 설정 > 채팅 응답`에 `캐싱 친화적 구조`를 추가했습니다. 켜면 바드위키 기억을 최신 사용자 메시지 바로 앞으로 옮깁니다. 프리셋, 캐릭터 설명, 로어북, 지난 대화는 턴이 바뀌어도 똑같이 유지되어 캐시가 더 오래 적중합니다.
- 현재 서사 기준선은 자주 바뀌지 않으므로 지금처럼 캐릭터 설명 자리에 둡니다.
- 기본값은 꺼짐이며, 끄면 이전 배치 그대로 보냅니다. 기억이 대화 끝쪽에 놓이므로 모델이 기억을 더 강하게 반영할 수 있습니다.
