# RisuBard v0.9.71

## [추가] 캐릭터 비서 플레이 테스트

봇을 만든 뒤 직접 채팅하며 확인하던 일을 캐릭터 비서에게 맡길 수 있습니다. 비서가 유저 역할로 정한 턴 수만큼 채팅을 진행합니다.

- **시작:** 캐릭터 비서 입력창 아래 `플레이 테스트`를 누르고 턴 수, 진행 방식, 채팅 맥락을 고른 뒤 지시문을 씁니다. 예: `로어북 성능을 보려고 해. 주인공이 1-A 반 학생들 모두와 지하층에서 작전을 펼치는 챗을 진행해.`
- **새 채팅:** 시작할 때마다 대상 봇에 `플레이 테스트 N` 채팅을 새로 만들어 진행하므로, 기존 채팅은 그대로 남습니다.
- **모델:** 비서 설정의 `메인`/`보조` 선택을 따릅니다.
- **비서가 받는 자료:** 페르소나, 지시문, 지시문으로 찾은 로어북 항목, 그리고 채팅 맥락입니다. 채팅 맥락은 `최근 채팅`(비서 설정의 최근 챗 수, 0이면 20개)과 `바드위키`(지난 응답에 들어간 바드위키 문서와 최근 응답) 중에서 고릅니다.
- **실제 채팅과 같은 경로:** 비서가 쓴 입력은 사람이 입력할 때와 같이 입력 트리거와 정규식을 거쳐 전송되고, 프리셋과 로어북도 그대로 적용됩니다.
- **자동과 반자동:** 자동은 끝까지 진행합니다. 반자동은 턴마다 비서의 관찰과 입력을 보여 주고, 고치거나 그대로 보낼 때까지 기다립니다.
- **기록:** 턴마다 비서의 관찰, 보낸 입력, 봇 응답에 실제로 들어간 로어북 목록이 비서 대화에 카드로 남습니다. 다 끝난 뒤 비서에게 결과를 물어볼 수도 있습니다.
- **멈추는 경우:** `중지` 버튼, 채팅 화면의 생성 중지, 요청 실패나 빈 응답, 테스트 채팅에 직접 입력하거나 다른 채팅으로 옮긴 경우에 멈추고 이유를 알려 줍니다. 시간 제한은 없습니다.

## [수정] 저장 중에 바뀐 외부 파일이 확인 없이 덮어써지던 문제

- **증상:** 앱이 열린 채로 봇 제작 도구 같은 다른 프로그램이 캐릭터 파일을 고쳤는데, `외부에서 파일이 바뀌었습니다` 창 대신 `서버 저장 실패 — 변경사항이 디스크에 반영되지 않습니다` 오류가 떴습니다. 그 뒤 다음 저장에서 앱 내용이 그 파일을 덮어써 외부 변경이 사라졌습니다.
- **원인:** 앱이 저장하는 도중(채팅 저장은 1초 미만)에 다른 프로그램이 파일을 쓰면, 저장이 끝날 때 그 변경까지 앱이 저장한 내용으로 처리했습니다. 그래서 외부 변경으로 감지되지 않았습니다.
- **변경:** 저장이 시작된 뒤 다른 프로그램이 바꾼 파일은 앱 내용으로 덮어쓰지 않고, 저장이 끝나도 외부 변경으로 남겨 둡니다. `외부 파일 변경 확인`이 켜져 있으면, 그 파일 때문에 저장이 멈춘 경우에도 오류 대신 확인 창이 떠서 받아들일지 고를 수 있습니다.

## [수정] 요청 로그가 커지면 서버가 메모리 부족으로 꺼지던 문제

- **증상:** 요청 로그와 사용량 통계 파일이 각각 수백 MB까지 쌓이면, 서버가 이 파일을 읽다가 JavaScript 메모리 한도(약 1GB)를 넘겨 종료되고 다시 시작되기를 반복할 수 있었습니다.
- **원인:** 서버가 두 파일을 한 번에 통째로 메모리에 올렸고, 오래된 로그를 정리할 때도 남길 내용 전체를 메모리에서 다시 만들었습니다. 사용량 통계에도 요청과 응답 본문이 그대로 복사되어 있어서 통계 파일이 요청 로그만큼 커졌습니다.
- **변경:** 로그 파일을 한 줄씩 나눠 읽고, 목록과 통계에 필요한 정보만 메모리에 둡니다. 요청 본문은 로그를 펼치거나 본문을 요청할 때 그 항목만 파일에서 읽습니다. 오래된 로그 정리도 파일을 조각 단위로 복사합니다. 264MB짜리 요청 로그와 통계 파일로 시험했을 때 메모리 사용량이 약 950MB에서 약 40MB로 줄었습니다.
- **사용량 통계:** 이제 토큰 수, 모델, 시간 같은 집계용 정보만 저장합니다. 본문이 들어 있는 기존 통계 파일도 그대로 읽으며, 처음 읽을 때 본문을 뺀 형태로 한 번 정리해 파일 크기가 크게 줄어듭니다. 집계 결과는 바뀌지 않고, 요청 로그 화면의 본문은 지금처럼 볼 수 있습니다.
