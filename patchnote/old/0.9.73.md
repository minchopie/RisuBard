# RisuBard v0.9.73

## [수정] 저장 대기 중 외부에서 파일을 고치면 앱이 시작되지 않던 문제

앱이 켜져 있는 동안 봇 제작 도구나 다른 프로그램이 캐릭터 파일을 고치면, 저장을 기다리던 앱 편집이 있을 때 `외부 변경 받아들이기`가 실패했습니다. 이 상태에서 창을 새로고침하면 시작 화면이 `getItem Error: Canonical files changed while acknowledged saves are pending; a merge baseline is unavailable`로 멈췄고, 서버를 완전히 다시 켜는 것 말고는 방법이 없었으며 그러면 저장을 기다리던 편집이 조용히 사라졌습니다.

- **자동 해결:** 이제 시작과 `외부 변경 받아들이기`가 멈추지 않고 외부에서 고친 파일을 불러옵니다.
- **앱 편집 유지:** 외부에서 바뀐 것이 캐릭터 설정이나 로어북뿐이면, 그 캐릭터와 로어북만 외부 내용으로 바뀌고 저장을 기다리던 대화와 다른 편집은 그대로 저장됩니다.
- **복구 파일:** 바뀐 내용을 불러오기 전에 저장을 기다리던 앱 상태 전체를 서버 데이터 폴더의 `trash/live-files-recovery/` 안에 파일로 보관하고, 화면을 불러온 뒤 그 위치를 알려 줍니다. 설정 파일처럼 다른 파일이 바뀌어 외부 내용을 통째로 불러온 경우에도 앱 편집은 이 파일에 남습니다.

## [수정] 새 대화 첫 턴에 첫 메시지 속 키워드로 로어북이 켜지지 않던 문제

그리팅을 받은 직후 처음 보내는 메시지에서는 로어북 키워드 검색이 사용자가 입력한 한 줄만 훑었습니다. 그래서 첫 메시지에 장소나 설정 키워드가 잔뜩 있어도 그 로어가 켜지지 않아, AI가 첫 응답부터 설정을 놓치곤 했습니다.

- **첫 메시지 포함:** 대화 메시지 수가 검색 깊이보다 적으면 첫 메시지도 검색 대상에 들어갑니다. 대체 그리팅을 골랐다면 그 그리팅을 봅니다.
- **보이는 그대로 검색:** 첫 메시지는 요청에 실제로 들어가는 렌더링 결과로 검색하므로, CBS 조건으로 숨긴 분기의 키워드 때문에 로어가 잘못 켜지지 않습니다.
- **기존 규칙 유지:** 첫 메시지를 끈 대화나 `Cut Messages for AI`로 앞부분을 잘라 낸 대화에서는 첫 메시지를 검색하지 않습니다. 대화가 이미 검색 깊이만큼 쌓였다면 이전과 똑같이 동작합니다.
- **검색 깊이가 대화보다 길 때:** 검색 깊이가 대화 길이보다 크면 마지막 몇 개만 검색되던 문제도 함께 고쳐, 이제 모든 메시지를 검색합니다.

## [수정] 아주 큰 챗을 내보낼 때 나던 `Invalid array length` 오류

챗 목록에서 챗 하나를 JSON으로 내보내거나 모든 챗을 내보낼 때, 내보낼 내용이 100MB를 넘으면 `RangeError: Invalid array length` 오류가 나고 파일이 만들어지지 않았습니다. 휴대폰 브라우저에서 접속해 긴 챗을 옮기려 할 때 주로 겪던 문제입니다.

- **수정:** 내보낼 글을 파일로 바꾸는 방식을 브라우저 내장 기능으로 바꿔서 크기 제한이 사라졌습니다. 210MB짜리 모든 챗 내보내기까지 정상적으로 저장되는 것을 확인했습니다.
- **같은 방식을 쓰던 다른 내보내기:** 텍스트를 파일로 저장하는 다른 내보내기도 같은 경로를 쓰므로 함께 고쳐졌습니다.

## [개선] 챗 목록에서 여러 챗을 골라 한꺼번에 옮기기

챗 목록의 체크 상자는 지금까지 여러 챗을 지울 때만 쓸 수 있었습니다. 챗 여러 개를 폴더에 넣거나 순서를 바꾸려면 하나씩 끌어야 했고, 접어 둔 폴더에는 아예 넣을 수 없었습니다. 사이드바에서는 챗 하나만 따로 내보낼 방법도 없었습니다.

- **선택 막대:** 챗을 하나라도 고르면 목록 위 도구 막대가 선택 막대로 바뀝니다. 고른 개수, 전체 선택, 폴더로 이동, 위로, 아래로, 선택한 챗 내보내기, 선택한 챗 삭제가 한곳에 있습니다. 위로와 아래로는 고른 챗을 같은 폴더 안에서 한 칸씩 옮깁니다. 선택은 `Esc`나 ✕ 버튼으로 풉니다.
- **빠르게 고르기:** Shift를 누른 채 챗을 클릭하면 마지막으로 고른 챗부터 그 챗까지 한 번에 골라집니다. Ctrl(맥은 Cmd)을 누른 채 클릭하면 챗을 열지 않고 선택에만 넣거나 뺍니다. 터치 화면에서는 챗을 길게 누르면 선택이 시작되고, 그 뒤로는 가볍게 누르기만 해도 고르거나 뺄 수 있습니다. 이때는 챗이 열리지 않으므로, 챗을 열려면 ✕로 선택을 먼저 풉니다.
- **폴더로 이동:** 선택 막대의 폴더 버튼을 누르고 옮길 폴더를 고릅니다. `폴더 밖으로`와 `새 폴더 만들어 옮기기`도 있습니다. 챗을 받은 폴더는 펼쳐지므로 옮긴 결과를 바로 확인할 수 있습니다.
- **함께 끌기:** 고른 챗 가운데 하나를 끌어다 놓으면 나머지도 원래 순서대로 그 자리에 따라옵니다. 끄는 동안에는 접힌 폴더 아래에 놓을 자리가 나타나서, 폴더를 펼치지 않고도 넣을 수 있습니다. 이렇게 넣은 폴더는 접힌 채로 남고, 이름 옆 개수로 들어간 것을 확인할 수 있습니다.
- **끌기 손잡이:** 이제 챗은 오른쪽 끝의 점무늬 손잡이를 잡아야 끌립니다. 챗 이름을 누르다가 순서가 실수로 바뀌는 일이 줄고, 터치 화면의 길게 누르기는 선택에 쓰입니다. 손잡이는 마우스를 올리면 나타나고, 터치 화면에서는 늘 보입니다.
- **선택한 챗 내보내기:** 챗을 하나만 골랐다면 기존 챗 내보내기처럼 JSON, TXT, HTML 가운데 형식을 골라 저장합니다. 여러 개를 골랐다면 그 챗들과 그 챗들이 들어 있는 폴더만 JSON 파일 하나에 담습니다. 이 파일은 모든 챗 내보내기와 형식이 같아서 기존 `가져오기`로 그대로 불러올 수 있습니다.
- **폴더 표시:** 화살표로 펼침 상태를 보여 주고, 폴더 안 챗 개수를 이름 옆에 표시합니다. 폴더 색을 바꿀 때 `폴더 색상 변경하기`를 한 번 더 고르던 중간 단계를 없앴고, 영어로 나오던 색 이름(red, green 등)을 한국어로 보여 줍니다. 폴더를 지울 때는 확인 창에서 안의 챗이 지워지지 않고 폴더 밖으로 옮겨진다고 알려 주고, 빈 폴더에는 챗을 넣는 방법을 적어 둡니다.
- **메뉴 이름:** `더 보기` 메뉴의 `다운로드`와 `임포트`를 `모든 챗 내보내기`와 `가져오기`로 바꿨습니다.

## [추가] 챗 이름 위에 마우스를 올리면 마지막 대화 미리보기

챗 이름만으로는 어떤 대화였는지 알기 어려워 하나씩 열어 봐야 했습니다. 이제 사이드바 챗 목록에서 챗 이름 위에 마우스를 올리고 0.4초쯤 기다리면, 그 챗을 열지 않아도 목록 오른쪽에 대화 내용을 보여 주는 카드가 뜹니다.

- **보이는 내용:** 그 챗의 페르소나 이름, 마지막 메시지를 보낸 쪽의 이름과 `5분 전`처럼 지난 시간(일주일이 넘으면 날짜), 마지막 메시지의 앞부분 다섯 줄입니다. 페르소나를 고정하지 않은 챗에는 지금 선택된 페르소나 이름 옆에 `(챗에 고정 안 됨)`이 붙습니다. HTML 태그는 걸러 내고 그림은 `[이미지]`로 바꿔 글 위주로 보여 줍니다.
- **가벼운 동작:** 아직 열지 않은 챗은 마지막 메시지 하나만 서버에서 받아 옵니다. 챗 전체를 불러오지 않으므로 긴 챗도 바로 뜨고, 미리보기 때문에 챗 파일이나 내보내기 결과가 달라지지 않습니다.
- **키보드:** Tab으로 챗에 초점을 옮겨도 같은 카드가 뜹니다.
- **뜨지 않는 경우:** 터치 화면에서는 뜨지 않고, 창이 좁아 목록 옆에 자리가 없을 때도 뜨지 않습니다. 클릭하거나 목록을 스크롤하거나 챗을 끌면 카드가 사라집니다. 메시지가 없는 챗은 `아직 주고받은 메시지가 없습니다`라고 알려 줍니다.

## [추가] 인풋 도우미(실험 기능): 지시를 섞어 쓰면 AI가 내 메시지를 완성

실험 기능이라 처음에는 꺼져 있습니다. 설정 > 리스바드 > `인풋 도우미` 맨 위의 `인풋 도우미 사용`을 켜면 버튼이 나타납니다.

입력창에 평소처럼 메시지를 쓰다가 괄호 안에 지시를 섞어 넣고 전송 버튼 옆의 파란 요술봉 버튼을 누르면, AI가 지시대로 다음 턴에 보낼 메시지를 완성해 입력창 내용을 바꿉니다. 예를 들어 `나는 주문을 외우기 시작한다. (주문 내용은 맡길게. 메시지 끝에는 (ooc: ...) 를 추가해.)`라고 쓰면, 주문 대사를 직접 지어 넣고 끝에 적어 둔 `(ooc: ...)` 문장을 그대로 붙인 메시지가 들어옵니다. 바로 전송되지 않으므로 확인하고 고친 뒤 보내면 됩니다.

- **되돌리기:** 결과가 마음에 들지 않으면 요술봉 왼쪽에 생기는 되돌리기 버튼을 누르거나, 결과를 고치기 전에 `Ctrl+Z`를 눌러 원래 입력으로 돌아갑니다. 결과를 그대로 두고 요술봉을 다시 눌러 새로 받아도 되돌리기는 처음 입력으로 돌아갑니다. 버튼은 메시지를 보내거나 입력창을 비우거나 다른 챗으로 옮기면 사라집니다.
- **생성 중:** 버튼 아이콘이 빙글빙글 도는 동안에는 입력창이 잠기고, 전송 버튼과 Enter, 재생성 단축키(`Ctrl+M`)로 메시지를 보낼 수 없습니다. 보내려고 하면 인풋 도우미가 작업 중이라고 알려 줍니다. 채팅 응답을 만드는 동안에는 반대로 요술봉 버튼이 잠깁니다.
- **요청 상태 창:** 요청 상태 표시를 켜 두었다면 채팅 응답처럼 화면 구석에 `인풋 도우미` 요청 상태 창이 떠서 진행 시간과 모델을 보여 줍니다.
- **취소:** 도는 버튼을 다시 누르거나 입력창에서 `Esc`를 누르면 요청을 취소하고 원래 입력을 그대로 둡니다. 설정에서 인풋 도우미를 끄거나 다른 챗으로 옮겨도 진행 중인 요청은 취소됩니다.
- **실패:** 요청이 실패하면 입력은 그대로 두고 오류 내용을 알림으로 보여 줍니다.
- **설정 페이지:** 설정 > 리스바드 > `인풋 도우미`에서 메인 모델과 보조 모델 가운데 쓸 모델, 함께 보낼 지난 메시지 수(기본 10개), 참고 자료로 넣을 항목을 고릅니다. 시스템 프롬프트, 캐릭터 설명, 페르소나, 캐릭터 로어북, 모듈 로어북을 체크할 수 있고, 로어북은 입력과 최근 대화로 켜지는 항목만 넣습니다. 기본으로는 모듈 로어북만 꺼져 있습니다.
- **지시 프롬프트:** 같은 페이지에서 AI에게 주는 지시문을 볼 수 있습니다. 기본 지시문은 보호되어 고칠 수 없고, `복제하기`로 사본을 만들면 이름과 내용을 고쳐 쓸 수 있습니다. 그리모어 프롬프트와 같은 방식이며 `{{user}}`, `{{char}}` 같은 CBS 문법을 쓸 수 있습니다.
- **요청 기록:** 인풋 도우미 요청은 요청 기록에 `인풋 도우미`로 표시됩니다.

## [수정] 챗 목록의 순서 바꾸기와 폴더 편집에서 생기던 문제

챗 목록에서 순서를 바꾸거나 폴더 이름을 고칠 때 열린 챗의 설정이 바뀌거나 다른 조작이 막히는 문제가 있었습니다. 입력창 메뉴의 `채팅 리스트` 창은 챗을 지울 때 사이드바가 거치는 확인을 건너뛰었습니다.

- **다른 챗의 설정이 적용되던 문제:** 챗이나 폴더를 끌어 순서를 바꾸다 지금 열린 챗의 자리가 달라지면, 그 자리에 원래 있던 다른 챗에 고정된 프롬프트 프리셋과 토글 값이 적용될 수 있었습니다. 그 챗을 아직 불러오지 않았다면 엉뚱한 챗을 불러오느라 로딩 화면이 뜨기도 했습니다. 이제 순서를 바꿔도 열린 챗과 그 설정이 그대로 유지됩니다.
- **`채팅 리스트` 창의 삭제:** 입력창 메뉴에서 여는 `채팅 리스트` 창(설정에서 켠 경우에만 보임)에서 챗을 지우면, 사이드바와 달리 바드페인터 작업 확인과 그림 생성 기록 보존을 거치지 않고 바로 지워졌습니다. 어떤 챗을 지우든 맨 위 챗으로 넘어가기도 했습니다. 이제 사이드바와 같은 절차로 지우며, 보던 챗을 지운 경우가 아니면 그 챗이 그대로 열려 있습니다.
- **폴더 이름 바꾸기:** 폴더의 연필 버튼을 누르면 모든 폴더 이름이 한꺼번에 입력 칸으로 바뀌었고, 그동안에는 챗을 눌러도 열리지 않았습니다. 편집을 끌 때 그 폴더가 접히기도 했습니다. 이제 누른 폴더의 이름만 그 자리에서 고치며, Enter로 확정하고 Esc로 취소합니다. 새 폴더를 만들면 이름 입력 칸이 바로 열립니다.
- **키보드와 화면 낭독기:** Tab으로 체크 상자 사이를 옮겨 가며 Space로 고를 수 있고, 체크 상자와 폴더 버튼마다 이름이 붙었습니다. 같은 체크 상자를 쓰는 설정 화면 등 다른 곳의 체크 상자도 이제 키보드로 다룰 수 있습니다. `채팅 리스트` 창의 내보내기와 삭제 버튼도 Enter나 Space로 누를 수 있습니다.

## [개선] 토글 값이 챗마다 따로 저장됨

지금까지 토글 값을 따로 가진 것은 `채팅별 프리셋 고정`으로 고정해 둔 챗뿐이었습니다. 고정하지 않은 챗은 모두 한 벌의 값을 나눠 썼기 때문에, 한 챗에서 토글을 바꾸면 다른 챗의 토글까지 함께 바뀌었습니다. 새 챗과 새 봇도 직전 값을 그대로 물려받아서, 매번 토글을 다시 맞추거나 고정 버튼을 눌러 두어야 했습니다.

- **챗마다 따로:** 이제 모든 챗이 자기 토글 값을 가집니다. 한 챗에서 바꾼 토글은 다른 챗에 영향을 주지 않으며, 고정 버튼을 누르지 않아도 됩니다.
- **기존 챗:** 고정하지 않았던 챗은 처음 열 때 모든 챗이 함께 쓰던 값을 그대로 가져와 자기 값으로 삼습니다. 화면에 보이던 토글 값은 달라지지 않습니다.
- **새 챗과 새 봇:** 새 챗은 보고 있던 챗의 토글 값과 되돌리기 기준을 복사해서 시작합니다. 새 봇은 직접 만들든 카드로 가져오든 지금 열려 있는 챗의 토글 값으로 시작하고, 열린 챗이 없으면 모든 챗이 함께 쓰던 값으로 시작합니다.
- **새 챗에 자동 적용:** 토글 프리셋 목록에서 프리셋 옆 별 버튼(`새 채팅에 자동 적용`)을 누르면, 보던 챗의 값 대신 그 프리셋 값으로 새 챗과 새 봇이 시작합니다. 별은 프리셋 하나에만 켤 수 있고, 다시 누르면 꺼집니다.
- **고정 버튼:** `채팅별 프리셋 고정` 버튼은 이제 되돌리기 버튼을 눌렀을 때 돌아갈 값(되돌리기 기준)만 정합니다. 버튼을 누르고 `현재 설정으로 덮어쓰기`를 고르면 지금 설정이 기준이 되고, 바로 옆 되돌리기 버튼을 누르면 그 값으로 돌아갑니다. `고정 해제하고 전역 값 사용`은 없앴습니다. 프롬프트 프리셋 파일 형식은 그대로라 기존 프리셋 파일도 그대로 쓸 수 있습니다.
- **RisuAI 방식:** RisuAI처럼 모든 챗이 한 벌의 토글 값을 함께 쓰려면 설정 > 접근성에서 `모든 채팅이 토글 공유 (RisuAI 방식)`을 켭니다. 예전 이름은 `채팅 토글 바인딩 비활성화`였습니다.
- **스크립트:** 스크립트가 `toggle_`로 시작하는 전역 변수를 바꾸면 지금 챗의 토글에만 반영됩니다. 그 밖의 전역 변수는 이전처럼 모든 챗이 함께 씁니다.

## [수정] 고정한 챗의 위키 프롬프트 가이드가 공유 토글 값을 쓰던 문제

`채팅별 프리셋 고정`으로 토글 값을 따로 둔 챗에서도, 위키 프롬프트 가이드 안의 토글 조건은 모든 챗이 함께 쓰던 값으로 판단했습니다. 그래서 다른 챗에서 바꾼 토글이 이 챗의 위키 작성과 응답 가이드에 섞여 들어갈 수 있었습니다. 이제 가이드는 그 챗의 토글 값을 따릅니다.

## [수정] 메시지별 아카라이브 복사에서 상태창과 그림 겹치기가 깨지던 문제

메시지마다 붙은 아카라이브 복사 버튼은 상태창이나 그림을 겹친 장면도 HTML로 바꿔 넣었습니다. 아카라이브는 `flex`, `grid`, `position` 같은 배치 코드를 지우기 때문에, 붙여 넣으면 칸이 한 줄로 뭉치거나 캐릭터 그림이 배경 아래로 떨어졌습니다.

- **그림으로 굽기:** 이제 메시지별 복사도 챗 저장기처럼 이런 블록을 리스바드 화면 그대로 그림으로 바꿔 넣습니다. 앞뒤 문단은 계속 글자로 남습니다.
- **배경 없는 상태창:** 배경 그림이 없어도 칸을 가로로 나란히 놓은 상태창과 표는 그림으로 굽습니다. 세로로만 쌓은 블록과 접힌 `details`는 이전처럼 HTML로 둡니다.
- **본문 전체를 감싼 블록:** 메시지 전체를 하나의 상자로 감싼 경우에는 상자와 문단은 글자로 두고, 그 안의 상태창이나 겹친 그림만 그림으로 바꿉니다.
- **크기와 위치:** 가운데 정렬한 블록이 그림 안에서 한쪽으로 밀리던 문제를 고쳤고, 폭이 좁은 블록은 본문 폭에 맞춰 늘리지 않고 원래 비율 그대로 넣습니다. 챗 저장기에도 똑같이 적용됩니다.

## [수정] 바드위키가 기억을 놓치던 네 가지 경우

바드위키는 최근 대화 몇 턴만 원문으로 넣고, 그보다 오래된 기억은 매번 검색해서 가져옵니다. 그래서 검색에서 놓치거나 분석 기록이 빠지면 대신 받쳐 줄 것이 없습니다. 이번에 그런 구멍 네 곳을 메웠습니다.

- **짧은 입력에서도 검색:** `계속`이나 `*고개를 끄덕인다*`처럼 인물이나 장소 이름이 없는 짧은 입력이 바로 맞는 문서를 찾지 못하면 직전 대화의 단어로 다시 검색하게 되어 있었습니다. 그런데 반드시 넣는 문서가 하나라도 있으면 이 검색을 건너뛰었고, 기본으로 고정되는 현재 장면 문서도 여기에 들어가서 첫 분석 이후 거의 모든 챗에서 일어나지 않았습니다. 이제 그런 문서가 있어도 검색합니다.
- **과거 원문 회수:** 입력에 `왜`, `기억`, `예전` 같은 말이 없으면, 단어 검색으로 찾아 놓은 과거 메시지를 버렸습니다. 이제 그중 가장 잘 맞는 두 개까지는 흔하지 않은 단어가 하나 이상 겹칠 때 그대로 넣습니다.
- **실패한 턴 다시 분석:** 분석이 실패하거나 정본 저장이 거부된 턴은 `다음 턴에 자동으로 다시 시도합니다`라는 안내와 달리 다시 분석되지 않아 그 턴의 기억이 빠졌습니다. 이제 새 턴을 분석할 때 바로 앞 AI 응답 두 개 가운데 아직 기록되지 않은 턴이 있으면 오래된 것부터 먼저 분석합니다.
- **같은 챗의 분석 겹침 방지:** 분석 모델이 느리거나 다음 메시지를 금방 보내면 앞 턴의 분석이 끝나기 전에 다음 턴의 분석이 시작되어, 나중 분석의 저장이 `정본 문서 저장 실패`로 끝나곤 했습니다. 이제 한 챗의 분석은 한 번에 하나씩 순서대로 실행하고, 기다리는 동안 `바드위키 작업 취소`를 누르면 기다리던 분석도 함께 취소됩니다. 다른 챗의 분석은 이전처럼 동시에 진행됩니다.

## [개선] 원문 창 바로 앞의 사건이 검색에서 밀리지 않음

바드위키는 최근 몇 턴은 대화를 그대로 넣고(원문 창) 그 앞은 사건 문서로 기억합니다. 그런데 사건 문서는 입력과 겹치는 정도로만 순위를 매겨서, 겹치는 정도가 같으면 방금 지나간 일이 수십 턴 전 일에 밀려 빠지기도 했습니다. `지금 어디야?`처럼 현재 상태를 묻는 입력에서는 사건을 하나도 넣지 않는 규칙까지 있어서, 직전에 자리를 옮긴 사건조차 들어가지 않았습니다.

- **최근 사건 우선:** 원문 창 앞 AI 응답 여섯 개 안에서 벌어진 사건은 원문 창에 가까울수록 검색 점수에 더 큰 가산점을 받습니다. 한 턴 전 사건이 가장 크고 여섯 턴 전이면 거의 없습니다. 이 범위 안에서는 입력과 겹치는 정도가 같을 때 더 최근 사건이 먼저 들어갑니다.
- **현재 상태 질문:** 입력에 `지금`, `어디`, `상태`, `관계` 같은 말이 있고 `왜`, `예전` 같은 과거를 묻는 말이 없으면, 입력과 겹치는 단어가 없어도 원문 창 앞 AI 응답 여섯 개 안의 사건 가운데 가장 최근 두 개를 넣습니다. 사건 문서에 배정된 분량 안에서만 넣으므로 인물이나 장소 같은 정본 문서는 줄어들지 않습니다.
- **평소 입력:** 입력과 겹치는 말이 전혀 없는 사건은 이전처럼 들어가지 않습니다. 가산점은 검색에 이미 걸린 사건의 순서만 바꿉니다. 최근 대화 정보가 없는 챗에서는 이전과 같습니다.

## [정리] 작동하지 않던 바드쨩(Bard-chan) 설정 제거

0.9.30에서 추가한 바드쨩은 검색 후보의 점수가 비슷할 때 AI 모델에게 후보 순서를 한 번 더 정하게 하는 선택 기능(기본값 꺼짐)이었습니다. 그런데 검색 과정에서 바드쨩에게 넘길 후보 목록이 전달되지 않아서, 설정을 켜도 바드쨩은 한 번도 실행되지 않았고 0.9.30 이후 모든 버전이 그랬습니다. 켜 두었던 분도 실제 검색 결과와 비용은 꺼 둔 것과 똑같았습니다.

- **설정 제거:** 바드위키의 `현재 챗 설정`과 공통 설정에서 `바드쨩 (Bard-chan)`과 `바드쨩 모델`을 없앴습니다. 제거한 뒤에도 검색 결과와 비용은 그대로입니다.
- **저장된 값:** 예전에 저장한 바드쨩 설정값은 남아 있어도 읽지 않습니다. 따로 지울 필요는 없습니다.
- **요청 로그:** 예전 요청 로그에 남은 바드쨩 항목은 계속 `바드쨩 검색 재정렬`이라는 이름으로 표시됩니다.

## [수정] 바드위키 창에서 편집 내용과 설정이 어긋나던 문제

바드위키 창에는 편집 중인 글이 경고 없이 사라지거나, 설정이 생각과 다른 곳에 저장되는 일이 있었습니다.

- **저장 전 확인:** 저장하지 않은 문서가 있을 때 다른 문서를 열거나, 미리보기의 위키 링크를 누르거나, 새 문서를 만들거나, 다른 보기로 넘어가면 편집 내용이 그대로 사라졌습니다. 이제 저장할지 먼저 묻습니다.
- **저장 직후 멈춤:** 문서를 저장한 직후 편집기가 `본문 불러오는 중`에 멈춰 다시 고칠 수 없던 문제를 고쳤습니다.
- **설정 저장 위치:** 설정 창 제목이 늘 `현재 챗 설정`이어서, 봇에 고정한 상태에서는 그 봇의 모든 챗이 함께 바뀌는 줄 모르고 고치게 되었습니다. 이제 제목과 그 아래 한 줄이 바꾼 값이 이 챗에만 적용되는지, 봇에 고정되어 그 봇의 모든 챗에 적용되는지 늘 알려 줍니다.
- **고정 상태의 `전역값 사용`:** 봇에 고정한 상태에서 누르면 고정은 그대로 둔 채 전역값을 고정값으로 복사할 뿐이라, 나중에 바꾼 전역값을 따르지 않았습니다. 이 버튼은 이제 `고정 풀고 전역값 따르기`로 이름을 바꾸고 실제로 고정을 풉니다. 모든 봇의 기본값을 바꾸는 `전역값으로 적용`은 한 번 더 확인합니다.
- **반대로 읽히던 체크 칸:** 바드위키 설정의 사용자 메시지 칸은 체크하면 빼는 칸이라, 체크하지 않은 상태가 넣는 것인지 헷갈렸습니다. 이제 `답변에 사용자 메시지 넣기`와 `분석에 사용자 메시지 넣기`로 바꿔 체크가 곧 넣기입니다. 공통 설정의 같은 항목은 `답변에서 사용자 메시지 빼기`처럼 체크가 곧 빼기라고 이름에 밝혔습니다. 저장된 값은 그대로입니다.
- **숫자 칸:** 칸을 비우면 0이 저장되고, 허용 범위 밖의 값도 그대로 저장되어 화면의 값과 실제로 쓰는 값이 달랐습니다. 이제 실제로 쓸 값으로 칸을 바로 고치고 허용 범위를 잠깐 알려 줍니다.
- **사건 영구 삭제:** 위키 리부트 중에도 사건을 영구 삭제할 수 있던 문제를 막았습니다.

## [개선] 바드위키 창 이름과 화면 정리

- **삭제 구분:** 일반 문서의 삭제는 `휴지통으로 이동`, 사건 문서의 삭제는 되돌릴 수 없는 `영구 삭제`로 이름과 색을 나눴습니다.
- **AI가 참고할 문서 고르기:** 문서를 AI가 답할 때 `항상` 참고할지, `자동`으로 고를지, `제외`할지 편집기 위쪽 버튼으로 바로 바꿉니다. 예전에는 문서 목록에서 우클릭해야만 바꿀 수 있어 휴대폰과 키보드로는 바꿀 수 없었습니다. 목록에는 `항상`과 `제외`만 표시합니다.
- **분석과 부딪힐 때:** 편집하는 동안 위키 분석이 같은 문서를 고치면 바로 알려 주고, `최신본 보기`와 `내 편집 유지` 가운데 고를 수 있습니다. 예전에는 저장에 실패한 뒤에야 알 수 있었습니다.
- **문서 정보:** 편집기 위쪽에 출처 메시지 수와 마지막으로 고친 때를 보여 주고, 사건 문서는 몇 번째 응답에서 나왔는지도 보여 줍니다.
- **검색과 정렬:** 검색어를 지워도 목록이 걸러진 채 남던 문제를 고쳤습니다. 인물, 장소 같은 종류별로 골라 보거나 최근 수정순으로 정렬할 수 있고, 폴더 이름도 `characters` 같은 영어 대신 인물, 사건, 장소처럼 한국어로 보여 줍니다.
- **빈 위키 안내:** 아직 문서가 없으면 빈 폴더와 편집 칸 대신, 대화가 진행되면 위키 문서가 쌓인다는 안내와 `새 문서` 버튼만 보여 줍니다.
- **설정 이름:** 무슨 뜻인지 바로 알 수 있도록 이름을 바꿨습니다.
  - `응답용 턴 수` → `답변에 그대로 넣을 최근 응답 수`
  - `분석할 턴 수` → `위키 분석이 읽을 최근 응답 수`
  - `정본 대상 한도` → `한 번에 고칠 위키 문서 수`
  - `추가 검색 횟수` → `근거 부족 시 다시 찾기 횟수`
  - `분석 토큰 한도` → `위키 분석 최대 길이(토큰)`
- **사용 가이드:** 바드위키 창의 `사용 가이드`에 최근 원문 수가 "메시지 수"라고 잘못 적혀 있었습니다. 실제로는 AI 응답 수를 세므로 설명을 고쳤습니다.
- **보기 이름:** 창이 넓으면 바드페인터, OOC 메모장, 작업 공간, 이야기, 아크 플롯, 요청 기록, 설정의 이름을 아이콘 아래에 보여 줍니다. `로그`는 하는 일에 맞게 `요청 기록`으로 바꿨습니다.
- **오류가 난 부분만 표시:** 문서 하나나 이야기 요약을 불러오지 못해도 창 전체가 오류 화면으로 바뀌지 않고, 그 자리에만 오류와 `다시 시도`를 보여 줍니다. 위키 목록 자체를 불러오지 못했을 때도 `다시 시도` 버튼이 생겼습니다.
- **더 가벼운 창:** 보기를 바꿀 때마다 위키 목록을 다시 받아 오지 않습니다. 내보내기 창은 본문을 전부 받을 때까지 기다리지 않고 바로 열리며, 고른 문서의 본문만 받아 저장합니다. 내보내기 창과 요청 기록은 항목이 많으면 앞부분부터 나눠 보여 줍니다.
- **이야기와 아크:** 이야기 카드는 카드 전체가 편집 버튼이라 요약을 읽거나 복사하기 어려웠습니다. 이제 요약은 그대로 두고 편집은 연필 버튼으로 엽니다. 아크 플롯 자동 갱신이 꺼져 있으면 켜는 위치를 알려 줍니다.
- **그 밖에:** 설정 창은 `Esc`나 창 바깥을 눌러 닫을 수 있고, 추가 분석과 들여오기 알림은 닫을 수 있으며 챗을 바꾸면 사라집니다.
